# SFTP 文件面板目录树

> Status: Approved
> Owner: OpsKat maintainers
> Last updated: 2026-11-24

**Objective:** 让 SSH/SFTP 用户在文件面板里随时看到从 `/` 起的完整目录层级，并在其中一键跳转，不必逐级「上一级」或手敲路径（issue #381）。

**Hard invariant:** 文件面板既有的可观察行为不得回退——终端 cwd 双向联动、列表的就地展开（#310）、多选、拖拽移动、内联重命名、剪贴板、同名冲突对话框、权限与属性对话框、本机文件拖入上传、外部/内置编辑器入口；目录树不得引入第二个「当前目录」。

## Problem

1. **当前目录一深，上层结构就从视图里消失了。** 列表的树根恒为当前目录（`frontend/src/components/terminal/file-manager/useFileManagerDirectory.ts:140` 以 `currentPath` 为根展平），进入 `/etc/nginx/conf.d` 后，`/etc` 的兄弟目录、`/var` 等都不可见。去往上层另一分支只能连点「上一级」（`PathToolbar.tsx:88`）或在路径栏手敲。（已验证）
2. **用户要的是 FinalShell 那种「目录树 + 文件列表」。** issue #381（2026-11-17，晚于 #310 合并的 2026-09-11）原文：「finalshell 的目录树很好用，望支持」。FinalShell 的形态是：只含目录、根固定为 `/` 的树，当前目录在树里自动展开并高亮，旁边的列表显示当前目录内容。（用户陈述 + 已知产品形态）
3. **#310 曾以「面板太窄」否决双栏。** 其 spec 决策 1（`docs/specs/2026-09-09-sftp-tree-and-builtin-editor.md:30`）的两条理由：树若自带独立根会出现两个「当前目录」；默认宽度 280px 容不下两列。本方案让树只反映、不持有当前目录，并在窄宽度下改为上下排列，两条理由都不再成立。（已验证）

## Actors and user stories

1. 作为 SSH 用户，我想在文件面板里始终看到从 `/` 起的目录层级，并看出当前目录在其中的位置，以便在深层目录里不迷路。
2. 作为 SSH 用户，我想点一下树上任意目录就切换过去，以便跨分支跳转不必逐级返回或输入路径。
3. 作为 SSH 用户，我想把列表里的文件直接拖到树上的任意目录，以便跨分支移动文件时不必先剪切、换目录、再粘贴。
4. 作为面板很窄或不需要树的用户，我想把树收起，以便列表拿回全部空间。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 文件面板内新增一棵**只含目录、根固定为 `/`** 的目录树，与文件列表共存于同一个面板。（用户决定：方案 A） | 直接对应 FinalShell 形态，且改动只在面板内部，终端与 VNC 布局不变。Rejected: 面板改为可停靠到终端下方（方案 B）——要改 `MainPanel` / `VNCPanel` 两处布局并让终端高度随之变化，工作量约为 A 的两倍；A 把树与列表做成独立部件后，B 可在此基础上另行立项。Rejected: 单栏、仅把现有树的根固定为 `/`（方案 C）——每一级祖先目录里的文件也会被全部列出，当前目录被淹没。 |
| 2 | 树**不持有**当前目录：它高亮并展开到面板的当前目录；点树上的目录等价于在列表里双击进入。 | 面板与终端联动都以当前目录为唯一轴心（#310 决策 1 的第一条理由）；树只做「显示 + 发起换目录」，就不会出现第二个当前目录。Rejected: 树有自己的选中目录、列表跟随它——联动语义要重新定义。 |
| 3 | 面板宽度 ≥ 440px 时树与列表左右排列，窄于此时上下排列（树在上）；两种排列都有可拖动的分隔条。 | 面板宽度可在 200–600px 间拖动（`frontend/src/stores/sftpStore.ts:35`–`:37`），默认 280px 放不下两列（#310 决策 1 的第二条理由）；上下排列在任何宽度下都能放下。Rejected: 只做左右排列——默认宽度下两栏都不可读。Rejected: 窄宽度下自动隐藏树——用户看不出树去了哪里。 |
| 4 | 列表保留 #310 的就地展开；树与列表**共用**目录条目缓存，但**各自**维护展开状态。（用户接受推荐） | 就地展开解决的是在列表里对照多个目录、跨目录拖动，与树的导航用途不重叠，删掉它会违反 Hard invariant。共用缓存避免对同一目录重复请求；展开状态分开，是因为在列表里展开某个子目录不意味着用户想在树上展开它。Rejected: 有树时把列表退回平铺——界面更干净，但 #310 那部分能力就没了。Rejected: 共用展开状态——两边会互相牵动。 |
| 5 | 树默认显示；可以收起，收起状态和分隔条位置全局记住，跨重启保留。（用户接受推荐） | issue 要的就是树，默认收起等于藏起这个功能；窄宽度下上下排列让默认显示可行。Rejected: 按标签页分别记住——同一个人在不同主机上对「要不要树」的偏好不会不同。 |
| 6 | 树行可以作为拖放目标，但不能作为拖动的起点；本机文件拖进面板仍然上传到当前目录，不分行。 | 列表拖到树正是用户故事 3；本机文件拖入目前只有整个面板这一个目标、只认当前目录（`frontend/src/components/terminal/file-manager/useNativeFileDrop.ts:27`–`:28`），按行区分需要另改协调器，与树本身无关。Rejected: 允许从树上拖起目录——要和列表的多选拖动合并，范围扩大。 |
| 7 | 软链接目录在树上与普通目录一样显示，不单独标记。 | 列目录返回的条目只有 `isDir`，没有软链接标记（`internal/service/sftp_svc/sftp.go:158`–`:163`），软链接目录已在后端解析成目录（`:253`–`:275`）。mockup 里的软链接图标需要后端加字段，不在本轮。 |
| 8 | 从树上删除、重命名或移动当前目录（或其祖先）时，面板随即换到仍然存在的目录：删除或移走时换到最近的仍存在的祖先，重命名时换到新路径。 | 只有树能让用户对当前目录本身或其祖先动手（列表只列当前目录的子项），不处理的话列表会停在一个已不存在的路径上报错。Rejected: 在树上对这些目录禁用破坏性菜单项——与列表上同一目录的菜单不一致，用户会以为功能缺失。 |

## 布局与开合

文件面板顶部的路径栏最左侧新增「目录树」开关按钮（图标按钮，名称由 tooltip 与无障碍标签提供，按下态表示树已显示）。点击即显示或收起树；收起后列表占满原来树与列表的全部空间，路径栏、状态栏与传输区不变。

面板宽度 ≥ 440px 时树在左、列表在右；窄于 440px 时树在上、列表在下。拖动面板宽度跨过 440px 时，排列方式即时切换，不丢失树的展开状态与滚动位置。两种排列各有自己的分隔条：左右排列时拖动调节树的宽度，上下排列时拖动调节树的高度；默认值分别约为 180px 宽、面板可用高度的 40%。分隔条有上下限，保证树与列表都不会被压到不可用（各自至少能显示一个完整的行）。收起状态与两种排列下的分隔条位置全局记住，跨标签页、跨重启保留。

上下排列时，列表上方有一行小标题，显示当前目录名及其中的文件、文件夹数量，让用户看清树与列表的分界和列表所指的目录。

这套布局对挂载了文件面板的终端 tab 与 VNC tab 同样生效。

## 目录树

### 内容与加载

树的顶层恒为 `/`，只列目录，不列文件；排序与列表里的目录一致。子目录按需加载：展开某个目录时才请求它的内容，加载期间该行箭头位置显示进行中指示，子层位置显示「加载中…」占位；加载失败（典型如权限不足）时在该目录下方就地给出失败原因与重试入口，其它分支照常可用；加载成功但没有子目录的目录，箭头随即消失，不额外给「空目录」占位（目录里有没有文件，看列表即可）。

树与列表共用同一份目录条目缓存：列表已加载过的目录，树展开它时直接显示，同时在后台刷新；反之亦然。面板的「刷新」使所有缓存失效，树上所有已展开的层随之重新请求。面板内任何会改变目录结构的操作（新建文件夹、重命名、删除、移动、粘贴、上传文件夹）完成后，树与列表一起反映结果，不需要用户手动刷新。

### 定位当前目录

面板的当前目录无论因何改变——树上点击、列表双击、上一级、主目录、路径栏输入、终端 cd 后跟随——树都自动展开它的每一级祖先，高亮当前目录所在行，并滚动到该行可见（已经可见时不滚动）。自动展开只增加展开项，不收起用户手动展开的其它分支。

为定位而需要加载的每一级祖先，照上面的规则加载、显示进行中与失败。如果某一级祖先不可读（目录有执行权限但没有读权限这类情形），定位停在这一级，在它下方给出失败说明；列表仍然正常显示当前目录，二者互不阻塞。

### 交互

单击树上的目录行即切换当前目录，与在列表里双击该目录完全一致，包括按既有规则与终端 cwd 联动。单击行首箭头只展开或收起，不切换目录。

树支持键盘操作：上下方向键在可见行之间移动焦点，右方向键展开（已展开时移到第一个子项），左方向键收起（已收起时移到父项），回车切换到焦点所在目录。树对辅助技术表现为一棵树：每行报告展开状态，当前目录所在行报告为已选中。

右键树上的目录行，弹出与列表中目录行相同的菜单，操作对象是这一行代表的目录，与列表当前的选中项无关。删除、重命名或移动的对象恰好是当前目录或其祖先时，操作成功后面板按决策 8 换到仍然存在的目录；失败时面板停在原处并照常报错。

### 拖放

把列表里的条目（单个或多选）拖到树上任意可见的目录行，即移动到该目录：拖动经过时目标行整行高亮，状态栏显示「移动 N 项到 〈目标目录完整路径〉」；松开后走与列表内拖动相同的移动流程，包括同名冲突对话框。拖到被拖条目自身、自身的子孙目录，或条目当前所在的目录上，都不是合法目标，不高亮也不执行。拖动途中停在一个收起的树目录上，不会自动展开它。

## Out of scope

- 文件面板停靠到终端下方、带多列表格的形态（方案 B）——树与列表做成独立部件后另行立项。
- 软链接目录的单独标记（需要后端给条目加字段）。
- 树行作为拖动起点；把本机文件拖到树上某一行上传到该目录。
- 树的搜索/过滤、收藏/书签目录、多个根（如固定显示主目录）。
- 树行的虚拟化：#310 实测单目录 5000 条目展开后强制重排 0.2–0.9ms，本轮不承诺；如果 `/proc` 这类超大目录展开后实测卡顿，再单独引入。
- OSS 对象浏览器的同类改动。
