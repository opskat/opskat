# 性能优化第二批：输出流攒批、连接池锁、OSS / cp 并发、AI 事件与保存、资产树、主包、RDP 帧

> Status: Approved
> Owner: OpsKat 维护者
> Last updated: 2026-11-05

**Objective:** 处理 2026-11-05 性能扫描剩余的第二、三档问题，与第一批（`docs/specs/2026-11-05-perf-batch1.md`）合在同一个 PR 里交付；顺带补上第一批留下的缺口：托管凭据改口令后，缓存连接不失效。

**Hard invariant:** 除下面「行为变化」列出的三项外，用户看到的内容与数据保持不变：终端、日志和远程桌面的字节与像素一致且顺序不变，传输结果一致，会话历史一致，界面状态一致。变化的只有事件数、拷贝量、往返数、锁的持有方式和渲染次数。每一项都要先测出修改前的数字，修改后用同一方法复测。

**行为变化（用户已确认）：**
1. AI exec 工具返回给模型的输出有上限，超出时保留头尾并注明省略了多少；opsctl 的输出不受影响。
2. SQL 编辑器只在执行或重新执行时计数，翻页和改页大小时复用已有总数。
3. 托管凭据改口令或改私钥口令后，引用它的资产的缓存连接立即失效，下次使用时按新凭据重连。

## Problem

标注：**[已核实]** 表示对照分支源码（`0b81ff5e`）确认过。

1. **本地终端、VNC、K8s 日志每读一次就发一次事件。** [已核实] `localterm_svc/localterm.go:263-286`、`vnc_svc/manager.go:355-374`、`internal/app/k8s/k8s_ops.go:156-178`（4 KB 缓冲）都没有攒批。SSH（`ssh_svc/ssh.go:1058-1141`）和串口（`serial_svc/serial.go:506-571`）各自实现了 10 ms / 32 KB 攒批，但两边的 10 ms ticker 在会话整个生命周期内都在跑，空闲时每个会话每秒也要醒 100 次。
2. **K8s 日志跟随时，每个分块都触发整页 setState，并复制整个分块数组。** [已核实] `K8sLogsPanel.tsx:99-117` → `K8sClusterPage.tsx:987-999`，页面状态缓存的 effect 也会跟着每块跑一次。
3. **OSS 大文件上传只能逐片串行，文件夹下载逐个对象串行。** [已核实] `internal/app/oss/oss_transfer.go:152` 的 `TrackedReader` 把 `*os.File` 的 `ReadAt` 藏起来了，minio-go v7.3.0 因此走串行的 `putObjectMultipartStreamOptionalChecksum`，而不是 4 路并发的 `putObjectMultipartStreamFromReadAt`。`oss_svc/download.go:49-81` 逐个对象下载。
4. **SSH 连接池在锁内做网络往返，且没有超时。** [已核实] `internal/sshpool/pool.go:58-65` 的 `isAlive` 持有 `entry.mu` 发送 keepalive 并等回复，没有超时；`cleanupIdle` 持有 `p.mu` 写锁去等 `entry.mu`，还在锁内关闭连接；多个首次 `Get` 并发时会各自拨号。`sshkeepalive.Start` 发 keepalive 也没有超时。连接悄悄断开（睡眠、换网）时，整个池可能被卡住数分钟。
5. **锁内做网络 I/O。** [已核实] `ssh_svc/ssh.go:127-139` 的 `Session.Write` 写 stdin 时一直持有 `s.mu`，远端不读时 `Close` / `IsClosed` / `Resize` 都会跟着阻塞，`Resize` 自己也在锁内发 `WindowChange`。`internal/app/ssh/forward_manager.go:80-124` 的 `StartConfig` 在 `m.mu` 内拨号（可能要等 MFA）并 `Listen`。
6. **每次命令审核都要哈希整个扩展包。** [已核实] `reviewerreg/registry.go:190-297` → `eligibility.go:87-105` → `extension_svc/provenance.go:33-124`，每次都把扩展目录完整读一遍算 SHA-256（已安装的扩展有 11–26 MB），而且发生在查审核缓存之前。
7. **SQL 编辑器每翻一页都先跑一次 `COUNT(*)`。** [已核实] `pkg/dbdriver/sqldb/session.go:101-118`；前端 `SqlEditorTab.tsx:223-260` 翻页和改页大小都会重新调用 `ExecuteSQLPaged`。
8. **AI exec 输出没有上限。** [已核实] `tool_handlers_unified.go:50-121` 原样返回执行器结果（ssh / k8s 用无界缓冲，SQL 结果把所有行转成 JSON），这些内容进入模型上下文、`tool_result` 事件和会话存储。只有 oss 执行器自己设了上限。
9. **AI 每个 token 一个 Wails 事件。** [已核实] `internal/ai/runner/stream_event.go:47-54` 每个 delta 发一次事件，而前端本来就按 50 ms 合并（`aiStore.ts:477`）。
10. **每个工具事件都重写整个会话。** [已核实] `aiStore.ts:463-473` 的 `persistNow` 在 agent、工具、审批、thinking、队列事件时调用，会把整段历史序列化后经 IPC 传给后端；后端（`conversation_svc/conversation.go:132-153`）删掉全部消息再重新插入。
11. **资产树每次渲染做 O(G²) 计算，订阅整个 store，行的 memo 失效，搜索时拼音没有缓存。** [已核实] `AssetTree.tsx:239-324`、`:622-677`、`:870-975`；`lib/assetSearch.ts`；`lib/pinyin.ts` 与 `packages/ui/src/lib/pinyin.ts` 两份内容逐字节相同。
12. **主包体积大。** [已核实] `i18n/index.ts:4-5` 两套语言包一起静态导入（共 338 KB）；`lib/assetTypes/*` 静态导入每种类型的 `ConfigSection` / `DetailInfoCard`，`vnc.ts` 经 `VNCConfigSection` 把 `@novnc/novnc` 带进主包。
13. **隐藏的终端标签仍在扫描 URL。** [已核实] 终端标签用 `visibility:hidden` 隐藏（`MainPanel.tsx:232-273`），`active` 只用于 fit / 聚焦；`terminalUrlHighlighter.ts` 在隐藏标签收到输出时仍会做 rAF 扫描并注册装饰。WebGL 是否仍在重绘还需要实测。
14. **托管凭据改口令后缓存连接不失效。** [已核实] `credential_mgr_svc/credential_mgr.go:401-490` 只写库；SSH 池、查询面板、Redis 等缓存要等闲置淘汰才会用上新口令。
15. **AI / opsctl `cp` 的目录传输逐个文件串行，每个文件都要 MkdirAll 加逐级 Lstat。** [已核实] `tool_handlers_cp.go:248-260`、`helper/transfer_ssh.go:188-268`。
16. **RDP 每次刷新都拷贝整屏，所有脏区合并成一个外接框。** [已核实] `rdp_svc/frame_stream.go:39-130` 每次 flush 先 `FramebufferWriteTopDown` 拷贝整屏（1080p 约 8 MB），再从中截出脏区；`markDirty` 把所有变化并成一个外接框。fork 里已加 `FramebufferWriteRectTopDown`（`opskat/gopher-rdp` 分支 `perf/framebuffer-rect-read`，本分支已钉到该提交）。

## Requirements

| # | Requirement | Observable acceptance |
|---|---|---|
| R8 | 字节输出流统一攒批，空闲时不定时唤醒 | `internal/pkg` 下新建一个共享攒批器（按时间窗口 + 字节上限 flush；有数据时才启动计时器，flush 后停止；关闭或 EOF 时 flush 剩余数据）。localterm、K8s 日志、SSH、串口都改用它；VNC 用更短的窗口（≤4 ms）。测试：N 次小写入只产生少数几次 flush，字节内容与顺序一致；空闲时没有计时器在跑；关闭时尾部不丢 |
| R9 | K8s 日志跟随不再每块触发整页渲染 | 分块直接写入 xterm，并追加到 ref 持有的缓冲里；镜像到 React 状态的频率不超过每帧一次（以及结束 / 停止 / 卸载时）。切换标签后回放的内容与修改前一致；渲染计数测试：连续 N 个分块在同一帧内只产生 ≤1 次页面提交 |
| R10 | OSS 大文件上传走并行分片，文件夹下载并发 | 上传把可 `ReadAt` 的文件交给 minio（进度改走 minio 的 `Progress` 钩子，或者让包装器保留 `ReadAt`），从而走 `putObjectMultipartStreamFromReadAt`；进度总数与完成状态和以前一样准确。文件夹下载用有界并发（与 SFTP 一样 8 路），`Tracker` 计数准确，取消会停掉所有 worker，失败时返回首个错误。测试：`httptest` S3 桩上能观察到并发的 UploadPart，带延迟时下载 N 个对象的耗时下降 |
| R11 | SSH 连接池不在锁内等网络，探活有超时，首次拨号合并 | `Get` 的健康检查在不持锁的前提下带超时；`cleanupIdle` 不持 `p.mu` 去等 `entry.mu`，也不在锁内关闭连接；同一资产并发首次 `Get` 只拨号一次（singleflight）；`sshkeepalive` 收不到回复超时后关闭客户端。测试：一个 keepalive 永不回复的假客户端不会阻塞其它资产的 `Get` / `List`，单个 `Get` 在超时后返回或重拨；8 个并发首次 `Get` 只拨号 1 次 |
| R12 | SSH 会话写入与端口转发启动不在锁内做网络 I/O | `Session.Write` 阻塞时 `Close` / `IsClosed` / `Resize` 能立即返回，`Resize` 的 `WindowChange` 移到锁外；`ForwardManager.StartConfig` 拨号和 `Listen` 期间，其它配置的 Start / Stop / Status 不被阻塞，同一资产并发启动仍只拨一次。各有一个能挂住旧代码的测试 |
| R13 | 命令审核不再每次哈希扩展包 | 桌面进程内按扩展缓存包摘要，Install / InstallStorePackage / InstallDev / Reload / Uninstall 时失效（Enable / Disable 不改文件，不必失效），缓存键带上包内文件的大小与修改时间，文件被改过就重新计算。测试：连续多次 `Current()` 只读一次包文件；改动包内文件后摘要变化，资格判断结果与以前一致 |
| R14 | SQL 编辑器翻页复用总数 | `dbdriver.Page` 增加一个零值保持现有行为的字段（如 `SkipTotal`），设置后 `ExecutePaged` 不跑 COUNT，`Total` 为空；扩展驱动的 wire / SDK 原样透传，旧扩展忽略该字段时照常计数。前端只在执行 / 重新执行时计数，翻页和改页大小时传 `SkipTotal` 并复用总数。测试：sqldb 翻页时不发 COUNT 语句；前端翻页时 `ExecuteSQLPaged` 收到 `SkipTotal`，状态栏总数不变 |
| R15 | AI exec 工具结果有上限 | 在 `handleExec`（AI 工具边界）对所有执行器的结果统一截断：上限 50 KiB / 2000 行，保留头尾，中间注明省略的行数和字节数；SQL 结果额外限制行数并注明总行数。opsctl 的 exec 输出不变。测试：超限输出被截成头 + 说明 + 尾，未超限时原样返回；opsctl 路径不截断 |
| R16 | AI 流式 delta 在后端合并 | `content` / `thinking` delta 在翻译器里按 30–50 ms 窗口合并；任何其它类型事件发出前、以及结束时，先 flush 剩余内容；合并后的文本与逐个 delta 拼接的结果一致，事件顺序不变。测试：快速连续 100 个 delta 只发出少数几个事件，内容一致；工具事件之前的文本不会被挪到它后面 |
| R17 | 会话保存只写变化的尾部 | 保存契约改成「从第一个变化的位置起替换」：前端记住每个会话上次成功持久化的序列化结果，只发送第一个不同位置之后的消息；后端在同一事务里删除 `sort_order >= from` 的消息再插入尾部。消息全部相同时不发起 IPC。保存失败时不更新「上次持久化」记录（下次重发），并且把失败记进日志，不再静默吞掉。测试：长会话追加一条工具事件，只写入尾部；从中间编辑重发时从该位置起替换；重新加载后的历史与全量保存一致 |
| R18 | 资产树渲染与搜索按资产 / 分组数线性增长 | 只订阅需要的字段和动作；每组的资产数与子分组在一次 `useMemo` 里算出（O(G+A)）；行回调稳定，`AssetRowContent` 的 memo 能命中；拼音结果按字符串缓存，两份 `pinyin.ts` 合成一份（应用侧从 `@opskat/ui` 重新导出）。在 1000 个资产 / 100 个分组的数据上测量搜索输入和展开折叠一个分组的提交耗时：如果优化后仍超过 50 ms，就用已有的 `rows` 加 `@tanstack/react-virtual` 做虚拟化，拖拽、右键菜单、键盘聚焦的现有测试保持通过 |
| R19 | 主包不再带上非当前语言包、noVNC 和各类型的配置 / 详情组件 | 启动时只加载当前语言，切换语言时再按需加载（首屏前完成，不加全屏 loading）；资产类型注册表的元数据仍然同步加载，`ConfigSection` / `DetailInfoCard` 改成 `lazy`；`@novnc/novnc` 只在真正连接 VNC 时动态导入。记录修改前后主 chunk 的体积，并扩展 `bundleBoundaries.test.ts` 防止回退 |
| R20 | 隐藏的终端标签不做 URL 扫描 | 先实测隐藏标签收到输出时 URL 扫描与 WebGL 重绘的开销。标签不活动时暂停 URL 高亮扫描，重新激活时对当前视口补扫一次；数据照常写入缓冲。如果实测发现 WebGL 仍在重绘，也在不活动时暂停渲染、激活时刷新。测试：不活动时写入不触发扫描；激活后视口内的 URL 已高亮 |
| R21 | 托管凭据改口令时失效相关缓存连接 | `UpdatePassword` / `UpdatePassphrase`（以及会改变认证结果的 `Update`）完成后，对直接引用该凭据的每个资产调用 `assetconn.InvalidateAsset`，查找走服务层（参照 `ssh_agent_svc/source.go:79-109`），不跨层直接用别的领域的 repo。测试：改口令后 SSH 池、Redis 等已注册的失效器收到对应资产 ID；未引用该凭据的资产不受影响 |
| R22 | AI / opsctl `cp` 目录传输并发，并且每个目录只建一次 | 多文件条目用有界并发传输（8 路）；目标目录按遍历顺序先建好，不再每个文件都 MkdirAll 加逐级 Lstat（路径安全校验的语义不变）；首个错误照常返回并取消其余传输；进度上报可以并发调用。测试：带延迟的 SFTP 桩上 N 个小文件耗时下降、每个目录只建一次，越界路径照常被拒绝 |
| R23 | RDP 只拷贝脏区，多个分散的脏区不合并成整屏 | `buildFrameEvent` 用 `FramebufferWriteRectTopDown` 只拷贝脏区；脏区跟踪保留少量矩形（例如 ≤8 个），只在合并能节省面积或超出数量时才合并；每个矩形发一个帧事件，前端不改。尺寸变化（返回值和预期尺寸不一致）时与现在一样放弃本帧。测试：假帧缓冲上左上角和右下角各有一个小变化时发出两个小事件，不再是一个整屏事件；像素与整屏拷贝后截取的结果逐字节一致；拷贝的字节数等于脏区面积 × 4 |

## Out of scope

SQLite WAL / journal 模式；`formatSQLResult` 重名列被合并的正确性问题；ZMODEM 的分块 IPC；RDP 帧的压缩编码；AI 文本块分段 memo；审计日志保留策略；资产树以外的 DatabaseTree / Redis / Mongo 组件的 store 订阅。

每项都在测试桩或沙箱上测出修改前后的数字，并记录命令和结果。运行期验证沿用第一批的做法：使用沙箱（`make dev-sandbox --mocks`），SFTP / cp 用 192.168.8.141，只在 `/tmp/opskat-verify-*` 下创建和删除文件。不在用户真实数据目录上做任何验证，也不读写真实 keychain。
