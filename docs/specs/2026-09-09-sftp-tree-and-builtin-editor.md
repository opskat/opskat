# SFTP 目录树与内置文件编辑器

> Status: Draft
> Owner: OpsKat maintainers
> Last updated: 2026-09-09（修订：恢复时重读的等待与失败分流；补记文档条按钮与状态栏）

**Objective:** 让 SSH/SFTP 用户在文件面板里就地展开目录层级，并在应用内编辑远程文本文件，不再必须依赖本机安装的外部编辑器。

**Hard invariant:** 文件面板既有的终端 cwd 双向联动、多选、拖拽移动、内联重命名、剪贴板、权限与属性对话框，以及 external-edit 既有的编码识别、读取上限、远端改动冲突检测、Compare/Merge 工作台、崩溃恢复与审计，其可观察行为均不得回退；任何写回远端的路径都必须经过既有的冲突检测，不得新增绕过它的写入通道。

## Problem

1. **文件面板只能逐层进出，看不到层级。** `FileList` 只渲染 `currentPath` 这一层的条目（`frontend/src/components/terminal/file-manager/FileList.tsx:424`），层级移动只有 `onNavigate` 换根和 `onGoUp` 两种手段。要把 `conf.d/` 里的一个文件挪到 `snippets/`，必须先进 A 目录选中、剪切、再换根到 B 目录粘贴——中途看不到目标目录，也无法在两个目录间对照。拖拽移动（`onMoveEntriesToDirectory`）只能落在当前这一层里可见的文件夹上。
2. **编辑远程文件必须依赖本机外部编辑器。** 双击非目录条目直接进外部编辑链路（`FileList.tsx:557`–`:565`，`canExternalEdit` 在 `frontend/src/components/terminal/FileManagerPanel.tsx:388` 定义为 `!entry.isDir`，处理函数在 `:390`）。`external_edit_svc` 的每条打开路径最终都要 `Launch` 一个本机可执行文件（`internal/service/external_edit_svc/session.go:105`、`:199`，`compare_merge.go:404`，`rebind.go:452`）。在没装或没配编辑器的机器上，改一行 nginx 配置这种最常见的操作没有出路。
3. **应用内编辑所需的后端能力其实已经具备，只差最后一步。** `RemoteFileService` 已有 `Stat` / `ReadFile` / `WriteFile`（`internal/service/external_edit_svc/types.go:91`–`:95`），`Open` / `Save` 会话生命周期在 `session.go:16`、`:211`，`Compare` / `PrepareMerge` / `ApplyMerge` 在 `compare_merge.go:78`、`:183`、`:264` 已经把三方文本送到前端，并且前端本来就用 Monaco 渲染它们（`frontend/src/components/terminal/external-edit/MergeWorkbench.tsx:218`）。缺的只是「不拉起外部进程、直接在应用内编辑同一个会话」这一步。
4. **懒加载树 + 虚拟化的范式在仓库里已经成熟，唯独文件面板没用上。** `flattenTree` 的 depth-walk + expandedSet 纯模型在 `frontend/src/lib/redisKeyTree.ts:58`，`RedisKeyBrowser` 把它接上 `useVirtualizer` 并按 `depth` 计算缩进（`frontend/src/components/query/RedisKeyBrowser.tsx:271`–`:284`、`:578`）；OSS 的懒前缀树同形（`frontend/src/lib/ossPrefixTree.ts:30`）。`FileList` 既没有树也没有虚拟化。

## Actors and user stories

1. 作为 SSH 用户，我想在文件面板里同时展开若干目录并看到它们的内容，以便在不丢失当前位置的前提下跨目录对照与搬运文件。
2. 作为 SSH 用户，我想双击一个远程配置文件就在应用内打开编辑并显式保存，以便在没有本机编辑器的环境下也能改配置。
3. 作为 SSH 用户，我想在远端文件于我编辑期间被改动时被拦下并拿到合并入口，以便不会静默覆盖别人的改动。
4. 作为 SSH 用户，我想在应用重启后回到未关闭的编辑器 tab，以便中断不会让我以为改动丢了。
5. 作为已经在用外部编辑器的用户，我想继续用 VS Code 打开远程文件，以便这次改动不夺走我既有的工作方式。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 文件面板的扁平列表原地升级为缩进树，树根始终是路径栏里的当前目录。 | `useTerminalDirectorySync` 与路径栏都以 `currentPath` 为唯一轴心；树若自带独立根，面板里会同时存在两个「当前目录」，联动语义随即失效。Rejected: 面板内再加一列独立目录树（OSS 浏览器那种 tree + list 双列）——面板是终端旁的窄侧栏、默认宽度容不下两列。Rejected: 另开全屏「文件管理器」tab——会出现侧栏与全屏两套文件管理器实现，按 reuse-first 必须收敛成一套，工作量翻倍。 |
| 2 | 双击目录仍然是「进入」（换根），行首箭头才是就地展开。 | 保住现有肌肉记忆与 cwd 联动；换根同时把缩进深度重置为 0，这是应对深层目录的首要手段，树只承担「看邻居」。Rejected: 双击改为就地展开——既打断联动语义，也让用户失去把深度归零的动作。 |
| 3 | 内置编辑器注册为 `external_edit_svc` 编辑器列表里的一个内建条目（恒为 `Available`，可设为默认），命中它时跳过 `Launch`、由前端打开编辑器 tab。 | `OpenRequest.EditorID` 字段已存在（`types.go:138`–`:143`），`detectEditors` / `resolveEditor`（`editor.go:13`、`:59`）已提供列表与默认项语义，编码识别、读取上限、冲突检测、审计、崩溃恢复因此全部复用。Rejected: 新开一条 SFTP 读写直通路径——绕过冲突检测，会在远端已变更时静默覆盖，是真实的丢数据风险。 |
| 4 | 内置编辑器只在用户显式按 ⌘S / Ctrl+S 时保存并写回远端。 | 编辑对象是生产机上的配置文件，输入过程中的中间态不应到达远端。Rejected: 与外部编辑器一致的自动写回（`saveModeAutoLive`）——外部编辑器的自动写回以「用户主动落盘」为触发点，而编辑器内的击键没有这个语义边界。两者行为不同这一点必须在设置界面里写明。 |
| 5 | 编辑器 tab 独立于终端 tab 存活；保存时若原 SSH 会话已失效，走既有 rebind 重绑同资产的其它可用会话，绑不上才要求用户重连。 | `rebind.go:242`、`:312` 已实现按 documentKey 重绑与从远端重建会话。Rejected: 关闭终端 tab 时连带关闭编辑器 tab——会在用户毫无预期时丢掉未保存改动。 |
| 6 | 编辑器 tab 参与 `tabStore` 的持久化与恢复。 | 终端 / 查询 / 页面 tab 已经全部持久化（`frontend/src/stores/tabStore.ts:283`–`:289`），external-edit 的 manifest 本来就保住了本地副本；只恢复副本不恢复 tab 会让用户以为改动没了。Rejected: 重启后只在会话列表里留记录——「关了就没了」的观感与实际状态不符。 |
| 7 | 树的渲染数据是一个扁平行数组（depth + 路径 + 展开态），与 `flattenTree` / `flattenPrefixTree` 同形；本轮不接虚拟化。 | 同形模型让「要不要虚拟化」退化为 `FileList` 内部的局部决定，不影响模型与调用方。虚拟化是否必要要按实测决定，不靠估算。Rejected: 一开始就接 `useVirtualizer`——在没有实测数据前属于凭经验优化。 |
| 8 | 只有单个子目录、且没有文件的目录链，在树里折叠成一行显示。 | 深度的主要来源是这类独子链，折叠直接压掉缩进消耗，且不引入任何新交互。Rejected: 不折叠、改为允许横向滚动——窄面板里横向滚动会让文件名与右侧大小列同时不可读。 |
| 9 | 缩进总量按面板当前宽度封顶，超出后每级只增加极小量，并以竖直参考线表达层级。 | 面板宽度可拖拽（`useResizeHandle`），封顶保证任何宽度下文件名优先可读，拖宽后缩进自然还原。Rejected: 固定 `depth × 常量`——深层目录下文件名会被压成省略号。 |
| 10 | 展开态按绝对路径记忆并跨换根保留，但总条数设上限，超出后淘汰最久未使用的条目。 | 绝对路径做 key 才能在换根往返时保持展开；长会话下无上限会只增不减。Rejected: 换根即清空展开态——用户在两个目录间来回时每次都要重新展开。 |
| 11 | 编辑器 tab 里不渲染文件面板；要看目录树需切回终端 tab。 | 文件面板当前只挂在终端与 VNC tab 上（`frontend/src/components/layout/MainPanel.tsx:261`，`frontend/src/components/vnc/VNCPanel.tsx:482`），其宽度、开合与当前目录都按终端 tab 存放。Rejected: 把挂载条件放宽到「持有 SFTP 会话的 tab」——需要为面板状态引入一层跨 tab 共享语义，范围明显超出本轮。 |
| 14 | 「查看差异」与「用外部编辑器打开」常驻文档条，不只在冲突时出现。 | 差异是编辑远程配置时的常规动作（「我改了什么」），把它锁在冲突态里等于要求用户先撞上冲突才能对照；外部编辑器入口常驻则保住了 spec 用户故事 5「不夺走既有工作方式」，用户在内置编辑器里改到一半仍可换回 VS Code。Rejected: 只在冲突横幅里给——即本轮实现的初始形态，设计稿里两个按钮常驻，是 spec 漏记了它们。 |
| 15 | 状态栏的缩进只显示、不可切换。 | 编辑对象是生产机上的配置文件，点一下就重新缩排整个文件的风险远大于收益。Rejected: 像 VS Code 那样可点击切换并重排——会真的改文件内容。 |
| 12 | 恢复时的重读不新建 SSH 连接，而是标记「未确认」并等待该资产出现可用会话后自动重读。 | 决策 5 已确立「只重绑同资产的现有会话，绑不上要求用户重连」；重启即自动连生产机与该语义相抵触，且可能在开机时弹主机密钥/凭据。可用会话的现成信号是 `frontend/src/stores/terminalStore.ts:285`（至少有一个已连接窗格的资产集合），按 reuse-first 直接复用。Rejected: 恢复时自行拉起会话——见上；Rejected: 只给手动重试按钮——用户需要自己想到「先去连终端再回来点一下」，恢复的意义就没了。 |
| 13 | 会话不可达与「不是同一份文件」必须是两种失败，不能合并。 | 二者的出路不同：前者要重连，后者要重新打开文件。当前实现把 SSH 会话不存在也算进「可达但不是同一份文件」（`internal/service/external_edit_svc/rebind.go:221`–`:222` 返回 `sameDocument=false`，调用方 `:126`–`:128` 据此置 `reachableDifferentDocument`），于是每次重启恢复都误报成路径已变化。Rejected: 统一成一句「无法确认远程文件」——把可以自动恢复的情形和需要用户介入的情形混为一谈。 |

## 目录树

### 展开与加载

行首箭头只对目录显示。点击箭头展开该目录：面板请求这一层的条目，加载期间箭头位置显示进行中指示且该行仍可选中；加载成功后子条目以更深一级缩进插入到该行下方，该目录的展开态被记住。再次点击箭头收起，其子层从视图中移除但展开态记忆保留到父层再次展开时。

展开失败（典型如权限不足）时不静默吞掉：在该目录下方就地给出一行失败说明与重试入口，父层与其它分支保持可用。展开后为空的目录在子层给出一行明确的「空目录」占位，使「空」与「没加载出来」可区分。

已展开目录的条目不随父层收起而丢弃缓存；再次展开时先渲染既有条目，同时后台刷新该层。面板的刷新动作重新拉取当前根这一层，并使所有已展开层的缓存失效，下次展开时重新请求。

### 换根与终端联动

双击目录、点击「上一级」「主目录」、在路径栏输入路径，都是换根：新的根成为树的顶层，缩进从它算起。换根仍然按既有规则与终端 cwd 双向联动，本次改动不修改联动的触发条件与方向。

换根不清空展开态记忆：换回原处时先前展开的层级仍是展开的。展开态以绝对路径为键，总条数设上限，超出后淘汰最久未访问的条目。

### 缩进与深度

只有单个子目录、且不含文件的目录链在树里折叠为一行，行内显示合并后的相对路径；点击其中任一段等价于对该段所在目录执行展开或换根。

缩进总量按面板当前宽度封顶：未达上限时每级缩进固定，达到上限后每级只增加极小量，并以竖直参考线表达层级归属。任何深度下文件名都优先于缩进获得宽度，过长的名字中段省略；树不引入横向滚动。

### 选择、拖拽与右键

多选、Shift 区间选择、Ctrl/Cmd 增删选择在树的可见行序上生效，与当前列表行为一致。区间选择的范围是当前展平后的可见行，不包含未展开的层。

拖拽的落点从「当前层可见的文件夹」放宽到「树上任意可见的目录行」，包括已展开的深层目录与折叠链上的目录。落点整行高亮并给出将要执行的动作描述；把条目拖到它自己的祖先或自身上不构成合法落点。

右键菜单的项与作用对象规则不变。目录行的菜单继续提供既有的「在终端中打开」。文件行的菜单提供「编辑」（内置编辑器）与「用外部编辑器打开」两条，其余项不变。

## 内置编辑器

### 打开

双击文件按「默认编辑器」设置决定去向：默认编辑器是内置编辑器时打开编辑器 tab，是某个外部编辑器时行为与今天一致。右键的「用外部编辑器打开」始终显式走外部编辑器。

打开内置编辑器会新建一个 external-edit 会话并在主 tab 区打开一个编辑器 tab。tab 标题是文件名，并能看出它属于哪个资产与哪条完整远程路径。同一资产的同一路径重复打开时聚焦到已有 tab，不重复建立会话。

编辑器 tab 是一个占满主区的编辑器，右侧不带文件面板；用户要回到目录树时切回对应的终端 tab，文件面板在那里保持着它原来的宽度、开合与当前目录。

文件超过既有的读取上限、或内容无法按既有编码探测解码为文本时，不进入编辑器：在入口给出原因与出路（前往设置调整上限 / 下载到本地 / 用外部编辑器打开），既不打开一个空编辑器，也不先拉一份巨大的本地副本。上限与编码判定沿用既有设置和既有逻辑，不新增阈值。

### 文档条与状态栏

编辑器顶部的文档条从左到右是：文件类型图标、文件名、未保存圆点、以及「资产名 · 完整远程路径」；右侧是保存按钮、「查看差异」与「用外部编辑器打开」两个按钮。后两个按钮常驻，不只在冲突时才出现——「查看差异」任何时候都能把当前草稿与远端当前内容送进既有 Compare 工作台；「用外部编辑器打开」等同于文件面板右键的同名操作，若编辑器内有未保存改动，先要求用户处理（保存或放弃）再交出去，避免两个编辑器各持一份不同草稿。

编辑器底部是一条状态栏，显示光标行列、当前文件探测到的缩进（tab / 2 空格 / 4 空格等）、会话记录的编码、换行符、以及按扩展名判定的语言；右侧显示保存状态与上次写回时刻。缩进只显示不可切换，Monaco 跟随同一个探测值，以免编辑生产机上的配置文件时把既有缩进风格弄乱。

### 保存与冲突

编辑器内的修改只体现在编辑器里：tab 标题与文档条给出未保存标记，改动行在编辑区左侧有标记，远端不受影响。⌘S / Ctrl+S 触发保存，走既有的 external-edit 保存路径——先按会话记录的编码写本地副本，再写回远端。保存过程可见（按钮进入进行中态、状态条说明正在写回），成功后未保存标记消失并给出写回时刻。

远端文件在本次编辑期间发生变化时，保存被拦下、不写回：编辑器顶部出现冲突横幅，提供合并、查看差异、重新读取、仍然覆盖四条出路。合并与查看差异进入既有的 Compare / Merge 工作台，不另建一套差异界面；「仍然覆盖」等价于既有的 overwrite 解决方式，需要用户再次确认。

远端文件已不存在、写入被拒绝等失败同样surface到编辑器上并保留本地改动，不把失败折叠成「保存失败」一句话。

### 会话、关闭与恢复

编辑器 tab 不随终端 tab 关闭而关闭。保存时若原 SSH 会话已失效，先尝试重绑同资产的其它可用会话；重绑成功则照常保存，失败则提示需要重连该资产，且本地改动保留。

关闭有未保存改动的编辑器 tab 前必须确认，提供保存并关闭 / 不保存 / 取消。选择「不保存」时本地副本仍按既有的工作区保留策略留存，可从既有的会话列表恢复。

应用重启后，未关闭的编辑器 tab 随其它 tab 一起恢复。恢复出来的 tab 在重新读取远端拿到结论之前，明确标为「远端状态未确认」——既不是干净态，也不假装已同步。

重读需要一个可用的 SSH 会话。恢复那一刻通常没有：会话在重启时已经断开，终端 tab 要等被激活才重连。因此重读不新建连接，而是等待——该资产一旦出现可用会话就自动重读，随后按结论落到干净态或冲突态；远端在此期间已变化的，以冲突态呈现（合并 / 差异 / 重新读取 / 仍然覆盖四条出路与保存时一致），而不是静默用旧内容覆盖。用户也可以在「未确认」态上手动触发重读。

重读失败时按失败原因分流，不折叠成一句话：远端文件已不存在、当前远程路径已不是同一份文件、以及会话不可达（没有任何可用会话）各自给出自己的说明，三者都保留本地改动。

## 打开方式设置

内置编辑器出现在既有的编辑器列表中，标注为始终可用，可被选为默认编辑器；默认编辑器的语义仍然是「双击文件时使用」。读取上限等既有设置对内置与外部编辑器同时生效。设置界面需说明内置编辑器只在显式保存时写回，与外部编辑器的落盘即写回不同。

## Out of scope

- OSS 对象的内置编辑：OSS 已有自己的前缀树，缺的只是编辑器承载，留到下一轮复用同一个编辑器 tab。
- 树内的搜索 / 过滤框与「仅显示目录」筛选。
- 深层滚动时的定位增强（sticky 祖先行、底部完整路径条）：展开与换根两条路已经让用户自行决定深度。
- 树行的虚拟化：本轮不承诺；扁平行模型使其可在实测超阈值后单独引入。
- 把文件面板的挂载条件放宽到编辑器 tab（面板状态的跨 tab 共享）。
- 自动保存 / 自动写回远端。
- 编辑器 tab 内的分屏、多文件标签、语言服务与格式化。
