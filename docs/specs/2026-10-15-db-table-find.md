# 数据表查找（#328）与数据库面板交互优化

> Status: Draft
> Owner: OpsKat 维护者
> Last updated: 2026-10-15

**目标：** 关系型数据库面板里，用户能用 ⌘F 在表格数据中定位到具体行列；刷新、翻页、出错、未提交修改、长文本编辑、多语句执行、标签关闭这些高频操作都有明确、不丢数据的反馈。

**硬约束：** 不改变现有的 UPDATE / DELETE 预览确认流程（编辑提交仍经 SQL 预览对话框）；不在共享代码里按驱动名分支（驱动改造分支的防回退检查）；其余沿用项目现有门禁。

**基线：** 本轮叠在 `feat/database-driver-seam`（数据库驱动接口第一轮）之上开发。[用户决定] 下文的文件位置均以该分支为准。

## 问题

1. **⌘F 搜的是标签页，不是表数据。** [已核实] `panel.filter` 绑定 ⌘F（`stores/shortcutStore.ts:90`），窗口级捕获监听在 `hooks/useKeyboardShortcuts.ts:60-66` 直接触发标签过滤并阻止传播，表格的 `onKeyDown` 收不到；表格本身没有任何查找功能。用户反馈见 issue #328。
2. **SQL 结果回到第 1 页不重新取数。** [已核实] `SqlEditorTab.tsx:232` 只在 `page > 0` 时取数，从第 2 页点「首页 / 上一页」或输入 1，屏幕上仍是第 2 页的数据，行号却按第 1 页显示。
3. **左侧树「表」分组第一次点击无效。** [已核实] 渲染时默认展开（`DatabaseTree.tsx:562` `?? true`），切换时按默认收起取反（`:632` `?? false`），第一次点击把 `undefined` 变成 `true`，状态不变。
4. **刷新、翻页会重置列宽、冻结、隐藏列和表头排序。** [已核实] 每次取数都 `setColumns` 一个新数组（`TableDataTab.tsx:325`），表格只要列数组引用变化就清空这些状态（`QueryResultTable.tsx:474` 起）。
5. **「显示注释」是空壳。** [已核实] 打开后每列都显示「无注释」（`QueryResultTable.tsx:1563`）；驱动返回的列元数据 `ColumnMeta` 只有名称、类型、可空、主键（`internal/dbdriver/browse.go:43-48`），没有注释与默认值。
6. **危险 SQL 只看第一个关键字。** [已核实] `SqlEditorTab.tsx:166-168` 只对整段文本开头匹配 `DELETE|DROP|TRUNCATE|ALTER`；`SELECT 1; DROP TABLE x`、开头带注释的 DELETE、不带 WHERE 的 UPDATE 都不会弹确认。
7. **任何重新加载都把整个表格换成转圈。** [已核实] `QueryResultTable.tsx` 在 `loading` 时整块返回 spinner，表头、滚动位置、选中全部消失，与 DESIGN.md「保持窗格形状稳定」不符。
8. **未提交的修改会被静默丢弃。** [已核实] 翻页、改每页行数、表头排序、应用筛选、按单元格值筛选（`TableDataTab.tsx` 渲染期清空 `edits` 与各 handler 中的 `setEdits(new Map())`）以及关闭内层标签（`DatabasePanel.tsx` 关闭按钮）都不提示。
9. **加载错误只有一行红字。** [已核实] 失败时清空列与行，只显示等宽错误文本，没有重试入口（`TableDataTab.tsx:331`，`QueryResultTable.tsx` 的 error 分支）。
10. **两种标签的分页不一致。** [已核实] 表数据分页在底部状态条（`TableEditorToolbar.tsx` 的 `TableDataStatusBar`），SQL 结果分页在结果区顶部、用 50–500 的下拉（`SqlEditorTab.tsx` 分页区）。
11. **长文本 / JSON 只能在单行输入框里改，且没有办法把值设为 NULL。** [已核实] 单元格编辑器是单行 `<input>`（`QueryResultTable.tsx` 编辑单元格分支）。
12. **只能执行选区或整个编辑器。** [已核实] `SqlEditorTab.tsx` 的 `getExecutableSQL` 取选区，否则取全文；编辑器里放多条语句时，执行其中一条必须先手动选中。
13. **表格键盘操作不全。** [已核实] 表格 `onKeyDown` 只处理方向键、Enter/F2、Esc、⌘C/⌘V（`QueryResultTable.tsx` keydown 分支）。
14. **内层标签可用性差，⌘W 关掉整个数据库标签。** [已核实] 标签名超过 120px 截断且无提示、没有中键关闭和右键菜单（`DatabasePanel.tsx`）；`tab.close` 对非终端标签直接关闭外层标签（`hooks/useKeyboardShortcuts.ts` `tab.close` 分支）。
15. **零散细节。** [已核实] 筛选器里按回车不应用（`TableFilterBuilder.tsx`）；执行按钮没有快捷键提示；表数据状态栏没有耗时；若干文案硬编码未走 i18n（`TableDataTab.tsx` 的 "(Default)"，`QueryResultTable.tsx` 的 "Date" / "Time" / "(empty)" / "NULL"，`TableFilterBuilder.tsx` 的 "not"，`TableStructureDialog.tsx` 的 " (UNIQUE)"）；新建 SQL 标签名 `SQL ${count}` 在关闭标签后会重号（`queryStore.ts`）。

## 角色与用户故事

1. 作为查看表数据的运维 / 开发，我想按 ⌘F 输入关键词直接跳到匹配的单元格，以便在上千行里快速找到目标记录。
2. 作为编辑表数据的用户，我想在翻页、排序、刷新、关标签前被提醒还有未提交修改，以便不会无声丢掉改动。
3. 作为看业务库的用户，我想在表头看到列注释、类型、默认值，以便不查文档也能读懂字段。
4. 作为写 SQL 的用户，我想按 ⌘↵ 只执行光标所在的那条语句，以便在一个编辑器里攒多条语句逐条执行。
5. 作为编辑 JSON / 长文本字段的用户，我想在多行编辑器里修改并能显式设为 NULL，以便不必在单行框里改大段内容。

## 设计决策

| # | 决策 | 依据与被否决的方案 |
|---|---|---|
| 1 | 查找只在已加载的当前页内进行（客户端） | [用户决定] 与 issue 诉求「直接定位到对应行列」一致。否决：整表 LIKE 搜索并写入筛选器——需要判定文本列、改变结果集，用户可用现有筛选器完成 |
| 2 | ⌘F 按焦点分派：数据库表格 / 结果区 → 查找条；SQL 编辑器 → Monaco 自带查找；其余 → 标签过滤 | 沿用 `terminal.find` 与 `panel.filter` 共用 ⌘F、按焦点让路的先例（`shortcutStore.ts:94,170`）。否决：给查找另配快捷键——用户预期就是 ⌘F |
| 3 | 查找条结构照搬 `TerminalSearchBar`，并加命中计数 | 复用优先，两处查找交互一致。否决：VS Code 式浮层——会遮住单元格 |
| 4 | 当前命中即表格的选中单元格 | 行详情、⌘C 天然跟随，不新增第二套「焦点」状态 |
| 5 | 本轮叠在 `feat/database-driver-seam` 上 | [用户决定] 该分支改动同一批文件，列注释需走驱动的表元数据；PostgreSQL 查看建表语句写死 `public` 的问题已在该分支修复，不再列入本轮 |
| 6 | 列注释与默认值由驱动的表元数据提供 | 驱动分支禁止共享代码按驱动名拼 SQL。否决：前端按驱动各写一套查询 |
| 7 | ⌘↵ = 选区或光标所在语句，⇧⌘↵ = 执行全部 | [用户决定] 与 DBeaver / TablePlus / DataGrip 一致。否决：⌘↵ 保持执行全部——与主流工具相反 |
| 8 | 语句切分放在前端、方言无关 | 只需识别引号、注释、`$$` 块与分号，对四个内置驱动均成立，不需要按驱动分支。否决：交给驱动——为一个编辑器交互扩展驱动契约，代价不成比例 |
| 9 | ⌘W 在关系型数据库标签内先关内层标签 | [用户决定] 内层标签全部关完后，⌘W 才关外层标签。Mongo / Redis 等其他面板不变 |
| 10 | 一个 PR 交付全部内容 | [用户决定] 否决：拆成 bug 修复 / 查找与状态 / 新功能三个 PR |
| 11 | 列状态只在列名集合变化时重置 | 同一张表刷新、翻页列名不变，用户调过的宽度、冻结、隐藏应当保留；换表或 SQL 结果列变化时重置才合理 |
| 12 | 新增「不带 WHERE 的 UPDATE」进入危险确认 | 与「DELETE 一律确认」同级风险。否决：所有 UPDATE 都确认——带 WHERE 的 UPDATE 是日常操作，确认过多会被无视 |

## 表格内查找（#328）

适用于关系型数据库的表数据标签与 SQL 结果，仅在表格视图下可用。

- **打开：** 前提：焦点在数据库标签的表格或结果区（不在 SQL 编辑器内）。动作：按 ⌘F。结果：表格上方出现查找条，输入框获得焦点；若当前有选中单元格且查找条已有关键词，保留关键词并全选。焦点在 SQL 编辑器内时 ⌘F 打开 Monaco 查找；焦点在数据库标签之外时 ⌘F 仍打开标签过滤。
- **查找条内容：** 输入框（占位「在当前页查找」）、命中计数 `当前 / 总数`（无命中显示「无结果」并把输入框描红）、区分大小写、整格匹配、正则三个开关、上一个 / 下一个、范围说明「仅查找已加载的 N 行（第 P 页），含未提交修改」、关闭按钮。所有图标按钮带 `aria-label`。
- **匹配规则：** 在当前页的可见列中，按表格当前显示的排列顺序逐行、逐列匹配显示文本；未提交的单元格修改与未保存的新增行按修改后的值参与匹配；NULL 不参与匹配（它的「NULL」只是占位）。隐藏列不参与。正则无效时输入框描红并提示「正则无效」，不报 toast。
- **定位：** 输入变化后立即跳到第一个命中；↵ / ⇧↵ 或按钮切换下一个 / 上一个，到末尾循环。当前命中成为表格的选中单元格并滚动进可视区（行列都会滚动，被冻结列遮挡时同样可见）；行详情面板跟随该行。
- **高亮：** 每个命中格内的匹配片段用 `warning` 色标记，当前命中片段使用实色标记且所在格显示选中框；与「未提交修改」的整格浅色底区分开。
- **数据变化：** 翻页、刷新、改筛选或排序后保留关键词并重新计算，当前命中回到第一个。单元格编辑后计数随之更新。
- **关闭：** Esc 或关闭按钮关闭查找条并清除高亮，焦点回到表格的当前选中单元格。切换到 JSON 视图时查找条关闭。
- **性能：** 当前页最多 1000 行（表数据默认页大小），匹配在输入防抖后同步计算，不得引起输入卡顿；表格保持现有行虚拟化。

## 加载、错误与分页

- **刷新保留表格：** 前提：表格已有数据。动作：刷新、翻页、排序、应用筛选、SQL 重新执行。结果：保留表头、列宽、滚动位置与旧数据；旧数据变淡且不可编辑，表头下方出现不确定进度条；状态栏中部显示「正在加载第 N 页…」，停止按钮可用。首次加载（尚无数据）仍显示居中转圈。加载被停止时恢复旧数据的正常显示。
- **错误面板：** 前提：表数据或 SQL 结果加载失败。结果：结果区显示错误卡片——标题（表数据为「加载 <库>.<表> 失败」，SQL 为「执行失败」）、可选中的错误原文、「重试」「复制错误」按钮；当前存在筛选条件时额外显示「编辑筛选」，点击打开筛选器。状态栏中部显示「加载失败」。重试再次失败时卡片内容更新为新的错误。
- **SQL 结果分页移到底部：** SQL 结果使用与表数据相同的底部状态条：左侧刷新 / 停止，中部「N 行 · 耗时」，右侧首页 / 上一页 / 页码 / 下一页（SQL 结果没有总页数时不显示末页）/ 每页行数设置。原顶部分页区移除。
- **SQL 结果回到第 1 页：** 前提：SQL 结果在第 2 页及以后。动作：首页、上一页或页码输入 1。结果：重新取第 1 页数据并显示。
- **表数据状态栏耗时：** 表数据状态栏中部在行数与页码之后显示本次取数耗时（毫秒）。

## 未提交修改的拦截

- **单一目标操作：** 前提：当前表数据标签有未提交的单元格修改、新增行或待删除行。动作：翻页、改每页行数、表头排序、应用筛选、按单元格值筛选、刷新、关闭该内层标签、关闭外层数据库标签、⌘W。结果：弹出对话框，标题「当前页有 N 处未提交的修改」，正文说明继续会丢弃修改，并列出修改摘要（行号 · 列：旧值 → 新值；新增 / 删除行各占一条，超过 10 条时折叠为「另有 M 处」）。按钮：
  - 「留在本页」：取消原操作，修改保留；
  - 「放弃并继续」：丢弃修改后执行原操作；
  - 「提交修改…」：打开现有 SQL 预览确认对话框；提交成功后执行原操作；提交失败或取消预览时留在原地、修改保留。
- **批量关闭：** 前提：关闭其他 / 关闭右侧 / 关闭外层数据库标签涉及多个有未提交修改的内层标签。结果：一个对话框列出这些标签名，按钮仅「取消」与「放弃并关闭」。
- 没有未提交修改时，上述操作直接执行，不弹窗。

## 列注释与表头信息（D1）

- **驱动契约：** 表元数据中的每一列增加「注释」与「默认值」两个字段；四个内置驱动（MySQL、PostgreSQL、SQL Server、SQLite）均返回。没有注释的列返回空字符串；SQLite 不支持列注释，恒为空；没有默认值的列返回空，且与「默认值为空字符串」可区分。驱动一致性测试覆盖这两个字段的存在与类型。
- **显示注释：** 前提：表数据标签，打开「显示注释」。结果：每个列名下方显示该列注释，过长截断；无注释的列显示「—」。SQL 结果不提供该开关与注释行。
- **表头信息卡：** 前提：表数据标签。动作：鼠标在列名上悬停约 0.5 秒。结果：浮出卡片，显示列名、类型、NOT NULL / 可空、主键标记、默认值（无则不显示该行）、完整注释（无则不显示）、包含该列的索引名。鼠标移开即消失；卡片不抢焦点。元数据加载失败时不显示卡片，列名正常可用。

## 长文本 / JSON 展开编辑（D2）

- **打开：** 前提：表格中选中一个单元格。动作：⇧↵，或右键菜单「展开编辑」。结果：在该格附近打开编辑浮层，标题显示列名、类型与行号；编辑区为多行等宽文本，内容为单元格当前值（含未提交修改）的原文，不自动格式化。
- **模式：** 「文本 / JSON」切换；值能解析为 JSON 对象或数组时默认 JSON 模式。JSON 模式提供「格式化」「压缩」按钮与有效 / 无效提示；无效 JSON 只提示，不阻止确定（列可能就是文本）。
- **设值：** 「设为 NULL」（列已知为 NOT NULL 时禁用并在提示里说明）、「设为空字符串」。
- **确认 / 取消：** ⌘↵ 或「确定」把结果记为该格的未提交修改（与单行编辑同一套修改记录，仍需提交并经 SQL 预览）；内容未改动时确定不产生修改；Esc 或「取消」关闭且不改动。
- **只读场景：** SQL 结果或不可编辑的表中打开时为只读查看，仅提供复制，不显示设值与确定。

## 执行当前语句（D3）

- **语句识别：** 以分号划分语句，正确跳过单引号 / 双引号 / 反引号 / 方括号标识符、`--` 与 `/* */` 注释、PostgreSQL `$tag$ … $tag$` 块中的分号。光标位于最后一个分号之后的空白或注释区时，视为上一条语句。只含空白与注释的片段不算语句。SQL Server 的 `GO` 批分隔符不识别。
- **执行：** ⌘↵：有选区执行选区，否则执行光标所在语句；⇧⌘↵：执行编辑器全部内容（原 ⌘↵ 行为）。执行按钮主操作 = ⌘↵ 的行为，旁边下拉提供「执行当前语句 ⌘↵」「执行全部 ⇧⌘↵」及选区说明；按钮上显示 `⌘↵`（Windows 显示 `Ctrl+↵`）。
- **高亮：** 编辑器有焦点且没有选区时，光标所在语句的行带淡色底与左侧色条。
- **历史：** 记入 SQL 历史的是实际执行的文本。
- **无语句：** 光标处没有可执行语句时（空编辑器或全是注释），执行按钮禁用，⌘↵ 无动作。

## 危险 SQL 确认

- 前提：在 SQL 编辑器执行任意文本。结果：对将要执行的文本逐条语句判断（复用 D3 的切分，跳过开头注释），任一语句以 DELETE、DROP、TRUNCATE、ALTER 开头，或是不含 WHERE 的 UPDATE，就弹出现有的危险确认对话框；否则直接执行。

## 表格键盘（D4）

- Tab / ⇧Tab：向右 / 向左移动选中格；在行末 Tab 移到下一行首列，在行首 ⇧Tab 移到上一行末列。
- Home / End：本行首列 / 末列；⌘Home / ⌘End（Windows 为 Ctrl）：第一行首列 / 最后一行末列。
- PageUp / PageDown：按可视行数上下移动。
- ⌘A：选中本页全部行（与点击行号列表头全选一致）。
- Delete / Backspace：在可编辑表中，把选中格设为 NULL 并记为未提交修改；列已知为 NOT NULL 时不改动，并以 `toast.warning` 说明。
- 以上在单元格编辑中、查找条或其他输入框获得焦点时不生效。右键菜单中的对应项显示快捷键提示。

## 内层标签与 ⌘W（D5）

- **完整名称：** 悬停内层标签显示完整名称（表标签为 `库.表`）。
- **中键关闭：** 中键点击关闭该标签（受未提交修改拦截）。
- **右键菜单：** 关闭（⌘W）、关闭其他标签、关闭右侧标签、复制名称、在左侧树中定位（仅表标签：展开对应库并滚动选中该表）。
- **⌘W：** 前提：当前外层标签是关系型数据库标签。动作：⌘W。结果：有内层标签时关闭当前内层标签；没有内层标签时关闭外层标签。其他类型的外层标签行为不变。关闭仍受未提交修改拦截。

## 零散细节（D6）

- 筛选器里在任一输入框按回车即应用筛选（与点「应用」相同）。
- 硬编码文案改为 i18n（zh-CN 与 en 各用地道表达）：问题 15 列出的各处。
- 新建 SQL 标签的序号在同一数据库标签内单调递增，关闭后不复用。

## 其他修复

- **树的表分组：** 「表」分组默认展开，第一次点击即收起，再次点击展开。
- **列状态保留：** 同一结果的列名集合（按顺序）不变时，刷新、翻页、排序、筛选都保留列宽、冻结列、隐藏列、类型 / 注释显示开关；列名集合变化时才重置。

## 不做

- 整表搜索（服务端 LIKE），由现有筛选器承担。
- SQL 编辑器内错误位置标记、多结果集、SQL 历史的搜索与时间戳、左侧树键盘导航与未加载库内的表搜索。
- 表格矩形区域选择、直接键入即开始编辑（与中文输入法冲突）。
- Mongo / Redis / Kafka 等其他面板的 ⌘F、⌘W 行为。
- SQL Server `GO` 批分隔符。
