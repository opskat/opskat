# 扩展商店：官方索引、OCI 分发、签名校验与在线安装 / 更新

> Status: Approved
> Owner: OpsKat 维护者
> Last updated: 2026-10-04

**Objective:** 用户在设置 → 扩展的「商店」里浏览官方扩展，一键安装或更新到与当前应用兼容的最新版本；opsctl 也能搜索、安装、更新。扩展仓在 main 上改版本号即自动发布，发布物与索引经签名与 sha256 校验后才会被安装。

**Hard invariant:** 已有安装路径的结果不回退——从 ZIP / 目录安装、`opsctl ext dev` 装出的扩展与现在一致（仅新增安装前确认与兼容 / 解包限制）；未经索引签名与 sha256 校验的商店包绝不落盘为已安装扩展；任何失败都不改动已安装的扩展。

## Problem

标注：**[已核实]** = 对照 opskat main（06493ac1）或 `opskat/extensions` 仓源码确认；**[用户决定]** = 本轮对话中用户选定。

1. **没有在线获取扩展的途径。** [已核实] 安装只能从 ZIP / 目录（设置 → 扩展，`internal/app/extension/extension_ops.go:253-314`）或 `opsctl ext dev`；扩展仓不产出任何打包物、不发布，README 写明发布与索引"由商店负责"。用户需要自己克隆、构建扩展仓才能装官方扩展。
2. **设置页安装不经确认。** [已核实] 从 ZIP / 目录安装直接落盘并启用（`ExtensionSection.tsx:116-129` → `service.go:168-220`），用户事先看不到扩展申请的能力；只有 `opsctl ext dev` 有审批（`internal/app/opsctl/ext_dev.go`）。
3. **兼容性只校验格式。** [已核实] `minAppVersion` 只做格式校验，从未与应用版本比较（`pkg/extension/manifest.go:491`）；`hostABI` 按支持列表精确匹配（`:497`）。版本也从不比较，覆盖安装会静默降级（`service.go:168-220`）。
4. **解包没有上限。** [已核实] zip 解压只防路径穿越，不限总大小与条目数（`pkg/extension/fileutil.go:15-75`）。从网络取包后这会成为可被利用的面。

## Actors and user stories

1. 作为**运维用户**，我想在设置里看到官方扩展列表（名称、说明、所需能力、大小），点一下就能安装，并在安装前看清它要什么能力。
2. 作为**运维用户**，我想在已装扩展有新版本时得到提示，确认后更新；当前应用装不了的扩展要告诉我原因。
3. 作为**国内用户**，我想在 ghcr.io 不通时换镜像下载，且不必担心镜像篡改内容。
4. 作为**opsctl / AI 用户**，我想用命令搜索、安装、更新扩展，安装仍需我在桌面端确认。
5. 作为**扩展维护者**，我想在扩展仓里改版本号并合入 main 就自动发布，不用手工打包、上传、改索引。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | **[用户决定]** 扩展包作为 OCI 制品放 GitHub 容器镜像仓库（`ghcr.io/opskat/extensions/<name>:<version>`），不发 GitHub Release；索引条目用 `type` 标记来源类型，缺省为 `oci` | GitHub Packages 中只有容器镜像仓库允许匿名拉取公开包；不往仓库提交二进制。Rejected: GitHub Release 资产——用户不发 Release；GitHub Pages——用户选 registry；制品分支——二进制进 git 历史；Actions artifact——需登录且会过期 |
| 2 | **[用户决定]** 索引 `index.json` 提交在扩展仓 main，应用经 raw 链接取，沿用应用现有的"下载镜像"设置 | 索引有 git 历史、国内经现有镜像可取到。Rejected: 索引也作为 OCI 制品——与包同受 ghcr 可达性影响；手工维护索引——要求构建可复现 |
| 3 | **[用户决定]** 推到 main 时，manifest 版本不在索引里的扩展自动构建、推送并把新条目提交进索引；已发布版本不重建、不覆盖 | 发版即在 PR 里改版本号。Rejected: 打 tag 发布——多一步操作；手动触发——易遗忘 |
| 4 | **[用户决定]** 索引为每个版本记录包的 sha256；CI 用 ed25519 私钥对 `index.json` 签名（`index.json.sig`），应用内置公钥验签 | 索引与包都可安全地经任意镜像传输。Rejected: 只记 sha256、索引只从 GitHub 直取——国内 raw 直连不通时无法浏览；索引也走镜像但不签名——镜像可同时篡改索引与包，校验形同虚设 |
| 5 | **[用户决定]** 新增 OCI 镜像设置：直连 ghcr.io / 预置镜像 / 自定义主机 | ghcr.io 在国内常不可达，而签名 + sha256 使任何镜像都可安全使用。Rejected: 只直连、让用户配系统代理；索引列多个备用来源——发布端要传多份 |
| 6 | **[用户决定]** 只读官方索引 | 信任模型单一（一把官方公钥）。Rejected: 用户自定义索引源——需要第三方公钥管理与同名冲突处理，留后续 |
| 7 | **[用户决定]** 兼容判定以 hostABI 为准；仅当应用是正式版时再要求 `minAppVersion ≤ 应用版本`，nightly / 开发版只看 hostABI；本地 ZIP / 目录安装用同一规则 | nightly 版本号以上一个正式 tag 为基（如 `1.14.0-nightly.20261003`），按 semver 低于 `1.14.0`，严格比较会误拦已含新能力的 nightly。Rejected: 只看 hostABI——同一 hostABI 内依赖宿主新修复的扩展拦不住旧正式版；严格 semver——误拦 nightly |
| 8 | **[用户决定]** 商店安装 / 更新与本地 ZIP / 目录安装都先弹同一个确认 | 用户在落盘前看清能力。Rejected: 只有商店确认；不确认 |
| 9 | **[用户决定]** 更新为"提示 + 手动更新"：每 24 小时随应用更新检查刷新索引，打开商店也刷新；不自动安装 | 能力可能随版本变化，需用户确认。Rejected: 只在打开商店时检查——用户发现不了更新；自动更新 |
| 10 | **[用户决定]** opsctl 新增 `ext search` / `ext install` / `ext update`，安装与更新在桌面端确认 | 命令行与 AI 也能装扩展，且仍由用户把关。Rejected: 本轮只做桌面端 |
| 11 | **[用户决定]** 商店放在设置 → 扩展的「商店」子标签（mockup `01`），与「已安装」并列；只安装各扩展最新的兼容版本，不做分类与版本选择 | 改动小、与已安装列表就近。Rejected: 独立的商店页面（mockup `03`，带分类、详情面板与版本列表）——体验更全但索引与界面工作量更大；设置内 + 详情面板 |
| 12 | 打包、签名工具放在扩展仓，借 opskat 的扩展加载能力读取 manifest 与 `describe()` 产出索引元数据 | 索引里的显示名、图标、能力与宿主加载时看到的一致。Rejected: 在扩展仓另写解析——与宿主解析漂移 |
| 13 | 商店不提供比已安装版本更旧的版本；本地安装仍可降级，但确认里明确标出"降级" | 商店只做向前更新；本地安装用于开发与回退。Rejected: 本地安装也禁止降级——开发者无法回退 |

## 发布（扩展仓）

- **触发与范围。** 前置：有提交推到扩展仓 main。动作：CI 对每个扩展读取 manifest 版本。结果：版本不在 `index.json` 中的扩展被发布；已在索引中的版本跳过（不重建、不覆盖）。CI 自己提交索引的那次推送不再触发发布。
- **发布一个版本。** 构建该扩展的可安装目录并打成 zip（manifest 位于 zip 根），计算 sha256，以 `<name>:<version>` 推到 `ghcr.io/opskat/extensions/<name>`，向索引追加该版本条目，重新签名，并把 `index.json` 与 `index.json.sig` 提交回 main。任一步失败则整个发布失败，不提交索引——索引里出现的版本一定已在 registry 中。
- **PR 检查。** PR 中某扩展的 manifest 版本低于索引里该扩展已发布的最高版本时检查失败。
- **签名密钥。** 私钥只存在于扩展仓的 CI Secret 中；缺失时发布失败并说明原因。

## 索引

- 顶层含格式版本号与扩展列表。每个扩展记录：名称、各语言（en / zh-CN）的显示名与说明、图标，以及全部已发布版本。
- 每个版本记录：版本号、hostABI、minAppVersion（可空）、申请的能力、包大小、发布时间、来源。来源为 `{type, ...}`；本轮只有 `type: "oci"`（缺省值），含镜像引用与包的 sha256。
- 应用遇到未知的格式版本时提示需要更新 OpsKat，不展示商店；遇到未知的来源 `type` 时把该版本视为不可安装（原因：需要更新 OpsKat）。
- 签名覆盖 `index.json` 的原始字节。应用内置一组受信公钥（便于轮换），任一公钥验签通过即可。

## 获取与校验（应用）

- **索引。** 从扩展仓 main 的 raw 地址取 `index.json` 与 `index.json.sig`，经应用现有的"下载镜像"设置（直连 / ghfast / gh-proxy / 自定义）。验签失败则不展示商店，显示"索引签名无效"并给出重试与更换镜像。
- **刷新时机。** 应用每 24 小时检查一次（与应用更新检查同节奏）；打开商店子标签时刷新；用户可手动刷新。商店显示索引更新时间与"已验证签名"。
- **拉包。** 按 OCI 分发协议匿名拉取：先请求，按 registry 返回的认证质询取匿名令牌，再取清单与包内容。拉取主机由"扩展下载"设置决定：直连 `ghcr.io`（默认）、预置镜像 `ghcr.nju.edu.cn`（2026-10-04 核实可匿名拉取公开包）、或自定义地址（主机名，可带端口；镜像站把 `ghcr.io` 放在路径下时再跟上那段路径，如 `mirror.example.com/ghcr.io`，拉取时拼在仓库名前面，与 `docker pull` 的写法一致）。
- **校验与限制。** 下载超过索引记录的大小时中止；下载完成后 sha256 与索引不一致则删除文件、不安装，错误写明期望值与实际值。所有 zip（商店与本地）解包时限制总大小与条目数，超限则安装失败。
- **进度。** 下载时显示已下载 / 总大小，随后显示"校验中"。
- **失败与恢复。** 网络 / 镜像不可达、认证质询失败、签名无效、sha256 不符、超出大小、兼容性不满足，均以可区分的错误呈现；网络与镜像类错误提供"重试"与"更换镜像"。任何失败都不改动已安装的扩展。

## 兼容判定

- 某版本兼容，当且仅当：其 hostABI 在应用支持的列表中；且当应用为正式版（非 nightly、非开发版）时，其 minAppVersion 为空或不高于应用版本。
- 商店为每个扩展选出最新的兼容版本作为可安装版本；没有兼容版本时卡片置灰并说明原因（需要更新 OpsKat，并给出所需 hostABI 或最低版本）。
- 已安装版本不低于最新兼容版本时显示"已安装"；低于时显示"更新到 x.y.z"。商店从不提供低于已安装版本的版本。
- 本地 ZIP / 目录安装与 `opsctl ext dev` 使用同一兼容规则，不兼容时拒绝并说明原因。

## 安装确认

- 商店安装、商店更新、从 ZIP / 目录安装都先弹同一个确认；`opsctl ext install` / `ext update` 触发桌面端的同一确认（与 `opsctl ext dev` 一样经桌面审批）。
- 确认显示：扩展名称与图标、版本（升级显示 `旧版本 → 新版本`，降级明确标"降级"）、来源（官方商店，签名已验证 / 本地文件或目录）、大小、申请的能力。升级时比旧版本多出的能力标"新增"；申请 `credentials:read` 时醒目提示可读取资产凭据。
- 用户取消则不下载（商店）或不落盘（本地），已安装扩展不变。确认后执行与现有安装一致的流程；更新保留扩展数据与设置，已打开的扩展页面随重载刷新。
- 商店的确认在下载前显示索引中的信息；本地安装在读取包内 manifest 后显示。

## 商店界面

- 设置 → 扩展顶部新增「已安装 / 商店」切换。「已安装」保持现有列表，有可用更新的扩展显示"更新到 x.y.z"。设置的「扩展」标签在有可用更新时显示角标。
- 「商店」：搜索（名称与说明）、刷新、索引状态行；扩展以卡片网格展示图标、显示名、可安装版本、说明、能力标签（"读取凭据"以警示色）、大小与状态按钮（安装 / 已安装 / 更新到 x.y.z / 无法安装 + 原因）。显示名与说明跟随应用语言，缺失时回退 en。
- 状态：首次加载骨架、搜索无结果、索引获取失败（重试 / 更换镜像）、签名无效、安装中（进度 → 校验中）、安装失败。窄窗口时卡片单列。布局参照 mockup `.dev-kit/artifacts/2026-10-04-ext-store/mockups/`（本地参考，非约束）。
- 「扩展下载」设置：镜像源选择（直连 ghcr.io / ghcr.nju.edu.cn / 自定义），自定义时填写主机（可带路径前缀）；说明索引走应用的"下载镜像"设置，且无论哪个镜像都会校验签名与 sha256。主机格式非法时不保存并在字段上提示。

## opsctl

- `opsctl ext search [关键词]`：列出名称、显示名、最新兼容版本、已装版本与状态（未安装 / 已安装 / 可更新 / 不兼容 + 原因）。不需要确认。
- `opsctl ext install <name>`：安装最新兼容版本；已安装同版本或更高版本时直接说明，不重复安装。
- `opsctl ext update [<name> | --all]`：更新到最新兼容版本；无可用更新时说明。`--all` 对每个可更新扩展分别确认。
- 安装与更新由桌面端执行并弹确认；用户拒绝、校验失败、不兼容时非零退出并输出原因。桌面端未运行时报错退出。

## Out of scope

- 第三方 / 自定义索引源与其信任管理。
- 分类、版本选择、回退到旧版本、发布说明展示（独立商店页面方案）。
- 自动更新；后台静默安装。
- `oci` 以外的来源类型。
- 镜像"测试连接"按钮（mockup `10` 中出现，不做）。
- 扩展页面与宿主 JS 上下文隔离（#326 已知遗留）。

## Testing decisions
