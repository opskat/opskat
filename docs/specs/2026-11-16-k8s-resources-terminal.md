# K8s 集群页：全资源类型、Pod 终端与常用操作（第一期）

> Status: Approved（2026-11-18 修订：第二轮运行时验证后的修正）
> Owner: OpsKat 维护者
> Last updated: 2026-11-18

**Objective:** 落实 issue #370：在 K8s 集群页提供 Pod 终端，展示 DaemonSet 等全部内置资源类型与集群中的自定义资源（CRD），并补齐表格列表、统一详情页、事件与常用写操作。

**Hard invariant:** K8s 资产的配置格式与含义不变；所有新增的集群访问都走资产已配置的 SSH 跳板 / 代理链，与现有读取一致；AI 与 opsctl 经统一 `exec` 执行 kubectl 的行为、权限策略与审批不变；现有日志面板的能力不退化；顶部刷新会更新已加载内容（#212）的行为保持；`make lint`、`go test ./...`、`pnpm test` 保持通过；明、暗两套主题下都成立。

对比稿（本地证据，不入库）：`.dev-kit/artifacts/2026-11-16-k8s-resources-terminal/mockups/`。其中的端口转发页、CPU / 内存列与概览中的用量卡属于第二期，本期不做。

## Problem

标注：**[已核实]** 对照 `86f40e5f` 源码确认；**[用户反馈]** 来自 issue。

1. **没有 Pod 终端。** [用户反馈] issue #370「POD CMD 没有」。[已核实] 后端只有集群信息、各类列表、Pod 详情与日志流（`internal/app/k8s/k8s_ops.go:90-205`），没有 exec。
2. **只支持 5 种资源。** [用户反馈]「没法看 daemonset 等类型的服务」。[已核实] 资源类型固定为 Pod / Deployment / Service / ConfigMap / Secret（`frontend/src/components/k8s/cluster/resourceTypes.ts`）；StatefulSet、DaemonSet、Job、CronJob、Ingress、PVC 等无法查看；PVC 与 ServiceAccount 只出现在命名空间的计数里。
3. **每加一种资源都要复制一整套代码。** [已核实] `K8sClusterPage.tsx` 共 2424 行，每种资源各有一份列表、加载中、错误、展开、搜索、刷新状态（`:105-165`）与一段侧栏渲染分支（`:909-922`、`:1077-1092`）；后端每种资源各有一个列表函数和一个 IPC 方法。照此扩展到二十多种资源与 CRD 不可行。
4. **只能看，不能操作。** [已核实] 页面没有任何写操作；重启、扩缩容、改配置只能切到 kubectl。
5. **事件只在 Pod 详情里出现。** [已核实] 事件只随 Pod 详情读取（`internal/pkg/k8s/client.go:647`），工作负载、PVC 等的失败原因看不到，也没有集群 / 命名空间级的事件视图。
6. **任何一项读取被拒，整个页面就打不开。** [已核实] 集群信息一次读取版本、节点与命名空间，任一失败整体返回错误（`client.go:74-123`）；没有列节点或命名空间权限的受限账号无法使用该页。

## Actors and user stories

1. 作为运维用户，我希望直接在 OpsKat 里进入容器执行命令，这样排查时不用切到终端敲 `kubectl exec`。
2. 作为运维用户，我希望能看到集群里所有类型的资源（包括 CRD），并以和 `kubectl get` 一致的列浏览，这样不用记两套信息。
3. 作为运维用户，我希望一眼看到哪些工作负载、Pod、节点不正常以及最近的告警事件，这样能快速定位问题。
4. 作为运维用户，我希望重启、扩缩容、删除 Pod、改 YAML 这类日常操作能在界面上完成，并在执行前看到影响。
5. 作为权限受限的用户，我希望能用的部分照常可用，不能用的部分明确告诉我原因。

## Design decisions

|---|---|---|
| 1 | 侧栏改为「命名空间选择器 + 按类别分组的资源类型」，右侧以表格显示所选类型，详情、终端、日志以页内标签打开。取代现有的「命名空间 → 类型 → 资源」树。 | 用户认可对比稿 00/01。类型增至二十多种加 CRD 后树不可用。Rejected：在现有树上加节点 —— 改动小但不可扩展，也没有表格总览。 |

| 3 | 可用资源类型来自集群的 API 发现：内置类型按固定类别归组，只显示集群实际提供的；其余可列出的类型归入「自定义资源」，按 API 组分组。 | 不同版本集群可用类型不同；CRD 只能发现得到。Rejected：硬编码类型清单 —— 旧集群会出现不可用类型，CRD 缺失。 |

| 5 | Pod 终端作为集群页的页内标签打开（与日志同层），不进入顶层终端标签体系。 | 用户认可。Rejected：顶层终端标签 —— 可获得分屏与 AI 终端绑定，但需为终端 store 新增一种连接方式，本期不需要。 |
| 6 | 写操作只在 GUI 提供，执行前弹确认（删除命名空间须输入名称）；与其他数据面板一致，不进入审计日志，也不走 AI 的权限策略与审批。 | 用户认可；与 Redis / 数据库面板的 GUI 写操作一致。Rejected：GUI 操作走 AI 策略审批 —— 那套机制服务于 AI / opsctl。 |
| 7 | 「编辑 YAML」以读取时的版本号提交更新（他人改过则拒绝并提示）；「应用 YAML」用服务端 apply，字段管理者为 `opskat`。 | 编辑场景要防止覆盖他人修改；创建 / 更新混合场景用服务端 apply 无需本地合并逻辑。Rejected：客户端 apply（last-applied 注解）—— 需复刻 kubectl 合并逻辑。 |
| 8 | 只显示操作，不预先检查权限；执行被拒时把集群返回的原因原样告诉用户。 | 预检每个操作需对每行做权限查询，代价高。Rejected：按 RBAC 隐藏按钮 —— 实现成本高且容易与真实权限不一致。 |
| 9 | 分两期：本期为本文所述；端口转发与 metrics-server 用量（CPU / 内存列、节点用量条、概览用量卡）为第二期。 | 用户认可。 |
| 10 | （2026-11-17 修订）同一资产复用到集群的连接，SSH 跳板只握手少量次数。 | 运行时验证（报告 V30 / F2）：经代理链时每个请求各自做一次 SSH 握手，打开页面约 45 个并发请求被跳板机 sshd 丢弃部分握手。Rejected：仅限制前端并发 —— 治标，每次请求仍握手、仍慢。 |
| 11 | （2026-11-17 修订）会话结束时结束容器内的 shell；退出应用时有终端才最多等约 2 秒。 | 运行时验证（F1）：关闭标签后容器内 `/bin/bash`、`/bin/sh` 仍在运行，每次打开 / 关闭遗留一个进程。Rejected：保持现状 —— 与 kubectl 被强杀时一样泄漏进程。退出等待由用户选定（2026-11-17），沿用退出前 AI 刷盘的限时等待做法；Rejected：退出时不清理 —— 退出后 shell 留在容器内。 |
| 12 | （2026-11-17 修订）Secret 取值按 UTF-8 解码，二进制显示 base64。 | 运行时验证（F6）：中文取值显示为乱码（逐字节当 Latin-1 解码）。用户要求本轮修正，取代原「展示方式与现在一致」。 |
| 13 | （2026-11-18 修订）主机密钥的保存对同一主机 / 端口 / 密钥类型幂等。 | 第二轮运行时验证（r2 报告 W7 / G1）：跳板机主机密钥尚未保存时，并发的首次握手同时插入同一条记录，除一条外都因唯一约束失败，页面类型发现报错。根因在主机密钥存储的「先查后插」不是原子 upsert。Rejected：K8s 侧串行化首次握手 —— 其他资产类型并发首次连接同样会撞上，应修存储本身。 |

## 导航与命名空间

打开 K8s 资产时，侧栏从上到下为：集群名与刷新按钮、命名空间选择器、集群版本、「集群概览」入口，以及按类别分组的资源类型：

- **集群**：节点、命名空间、事件
- **工作负载**：Pod、Deployment、StatefulSet、DaemonSet、ReplicaSet、Job、CronJob
- **网络**：Service、Ingress、EndpointSlice、NetworkPolicy
- **配置**：ConfigMap、Secret、HPA、ResourceQuota、LimitRange
- **存储**：PVC、PV、StorageClass
- **访问控制**：ServiceAccount、Role、RoleBinding、ClusterRole、ClusterRoleBinding
- **自定义资源**：其余可列出的类型，按 API 组分组列出

集群不提供的内置类型不显示；某个 API 组发现失败（例如聚合 API 不可用）时，只缺这一组，其余照常显示。类别可折叠，折叠状态在本次会话内保持。

命名空间选择器列出集群的命名空间，并在最上方提供「全部命名空间」。打开页面时默认选中资产配置的命名空间；资产未配置时默认「全部命名空间」。账号无权列出命名空间时，选择器只含资产配置的命名空间，并允许手动输入命名空间名。选择器影响所有命名空间级的列表、计数与概览；集群级类型（节点、命名空间、PV、StorageClass、ClusterRole 等）不受影响。

每个类型右侧显示所选范围内的数量。Pod、Deployment、StatefulSet、DaemonSet、Job、节点、事件另显示异常数量（定义见「集群概览」）。数量取不到（例如无权限）时显示「—」，悬停显示原因，不弹错误。

点击类型打开该类型的列表页内标签（已打开则切过去）；「集群概览」标签固定在最左且不可关闭。页内标签支持关闭、关闭其他、关闭左侧 / 右侧（沿用现有菜单）。

## 资源列表

列表页顶部显示类型名、CRD 的 API 组与版本、条目数、当前命名空间范围，以及过滤框、自动刷新开关、刷新按钮与「应用 YAML」按钮。

- **列**：第一列为名称；选择「全部命名空间」时第二列为命名空间；其余列与 `kubectl get` 默认输出一致（不含 `-o wide` 的附加列）。状态类文字按含义着色：正常（如 Running、Ready、Bound、Complete、Active）为成功色，进行中（如 Pending、ContainerCreating、Terminating）为警告色，失败（如 Failed、Error、CrashLoopBackOff、ImagePullBackOff、NotReady）为错误色，其余为中性。
- **排序**：点击列头按该列排序，再点切换方向；默认按名称升序；「运行时间」类列按创建时间排序。
- **过滤**：输入中含 `=` 时作为标签选择器（如 `app=api,tier!=db`）交给集群过滤；否则按名称子串过滤（不区分大小写）。标签选择器语法错误时在过滤框下显示集群返回的原因，列表保持上次结果。
- **自动刷新**：开启后每 5 秒刷新当前列表；关闭标签或切到其他标签时暂停。
- **大列表**：集群分批返回、界面虚拟滚动；5000 行的列表滚动与过滤不出现卡顿。
- **行操作**：悬停时在行尾露出该类型的主要操作图标与「⋯」菜单，右键行弹出同样的菜单并多出「打开详情」「复制名称」。各类型的操作见「操作」一节。点击行打开详情。
- **单元格完整显示**：状态文字（如 CrashLoopBackOff）与带补充说明的值（如重启次数 `7 (111s ago)`）完整显示，不被截断，也不覆盖相邻列；列宽随内容调整，表格放不下时整体横向滚动。
- **状态**：加载中、加载失败（原样显示集群返回的原因并给重试）、空（「命名空间 X 下没有 Y」或「没有匹配的资源」）三态分明；失败不显示为空。

## 资源详情

点击资源打开详情页内标签（标签名为资源名）。头部显示类型图标、名称、状态、类型与命名空间、所属对象（如 Pod 属于 ReplicaSet/xxx，可点击跳转）与创建时间；右侧为该类型的操作按钮，删除放在最右并用错误色。

子标签：

- **概览**：Pod、Deployment、StatefulSet、DaemonSet、ReplicaSet、Job、CronJob、Service、Ingress、ConfigMap、Secret、节点、PVC 有专门的摘要（副本 / 策略 / 选择器 / 镜像 / 端口 / 资源限制 / 关联 HPA / 调度 / 容量等，对应类型适用的项）。其余类型（含 CRD）显示通用摘要：元数据、`status.conditions`（若有）。所有类型都显示标签与注解（默认折叠）。现有 Service、ConfigMap、Secret、Pod 详情里展示的信息全部保留。Secret 的每个取值按 UTF-8 解码后以明文展示（与现在一样不打码），中文等非 ASCII 内容显示正确；解码结果不是有效 UTF-8 文本（二进制数据）时，原样显示 base64 并注明「二进制内容，显示为 base64」；字节数始终按原始数据计算。条件（conditions）按含义着色：多数条件取值 True 表示正常；名称表示问题的条件（MemoryPressure、DiskPressure、PIDPressure、NetworkUnavailable）取值 False 表示正常，正常为成功色、异常为错误色、Unknown 为中性。
- **Pod**：仅 Deployment、StatefulSet、DaemonSet、ReplicaSet、Job 有；列出由其选择器匹配到的 Pod，每行可打开终端或日志，点名称打开 Pod 详情。
- **日志**：Pod 与上述工作负载有；使用现有日志面板，工作负载可切换 Pod，均可切换容器。
- **事件**：该资源的事件，按最近发生时间倒序，告警数显示在子标签上。
- **YAML**：只读，隐藏 `managedFields`，可复制，「编辑」打开编辑对话框。

资源在打开期间被删除时，刷新后详情显示「该资源已不存在」，不显示空白或旧数据。

## 操作

所有操作经资产的连接执行。成功后给成功提示（`notify`，顶部居中）并刷新受影响的列表与详情；失败时以错误提示（右下角）显示集群返回的原因，界面状态不变。

| 资源 | 操作 |
|---|---|
| Pod | 终端、日志、编辑 YAML、删除 |
| Deployment、StatefulSet | 日志、扩缩容、滚动重启、编辑 YAML、删除 |
| DaemonSet | 日志、滚动重启、编辑 YAML、删除 |
| ReplicaSet | 日志、扩缩容、编辑 YAML、删除 |
| Job | 日志、编辑 YAML、删除 |
| CronJob | 立即运行、暂停 / 恢复调度、编辑 YAML、删除 |
| 节点 | 停止调度 / 恢复调度、编辑 YAML |
| 其他（含 CRD） | 编辑 YAML、删除（集群不支持的操作不显示） |

- **扩缩容**：对话框显示当前副本数，可输入或用 −/+ 调整目标（≥ 0）。目标被某个 HPA 管理时提示「由 HPA X（最小–最大）管理，手动设置会被覆盖」，仍允许提交。
- **滚动重启**：确认后按工作负载自身的更新策略逐个替换 Pod（与 `kubectl rollout restart` 效果相同）。
- **删除**：确认框写明对象与后果；被控制器管理的 Pod 注明「删除后会被自动重建」；删除命名空间须输入命名空间名才能确认。删除后关闭该资源的详情、终端、日志标签。
- **立即运行 CronJob**：按其模板创建一个 Job（名称为 `<cronjob>-manual-<随机后缀>`，截断到合法长度），不影响原调度；成功提示含新 Job 名，可点击打开。
- **暂停 / 恢复调度**：切换 CronJob 的 suspend；列表的「暂停」列随之变化。
- **停止 / 恢复调度节点**：只切换节点的可调度标记，不驱逐 Pod；确认框写明这一点。
- **编辑 YAML**：对话框内为 YAML 编辑器，隐藏 `status` 与 `managedFields`；「与集群对比」显示与集群当前版本的差异。保存时若资源已被他人修改，保存失败并显示冲突原因，提供「重新加载并对比」；YAML 语法错误时在编辑器内标出且不提交。编辑器加载完成前，对话框内显示加载中，不出现空白。
- **应用 YAML**：粘贴一个或多个文档（`---` 分隔）。未写命名空间的命名空间级资源落到当前选择的命名空间；选择「全部命名空间」时落到资产配置的命名空间，资产也未配置时该文档报错「未指定命名空间」。执行后逐个文档显示结果（已创建 / 已更新 / 失败及原因），某个文档失败不影响其他文档。

## Pod 终端

- **入口**：Pod 列表行、Pod 详情头部、Pod 详情容器表的每个容器、工作负载「Pod」子标签的每行。Pod 不在 Running 状态时入口置灰，悬停说明原因。
- **打开**：每次打开新建一个页内标签（标签名 `<pod> · <容器>`），默认容器为注解 `kubectl.kubernetes.io/default-container` 指定的容器，否则为第一个容器。
- **工具栏**：容器选择、Shell 选择（「自动」/ `/bin/bash` / `/bin/sh` / 自定义命令）、连接状态（连接中 / 已连接及实际使用的 shell / 已断开）、搜索、重新连接、断开。切换容器或 Shell 会结束当前会话并以新设置重新连接。「自动」先尝试 bash，容器内没有 bash 时改用 sh，并在终端首行注明实际使用的 shell。工具栏在窄窗口下（如同时打开 AI 面板）所有按钮完整可见、可点击，不被裁切。
- **终端行为**：使用应用的终端主题、字体与复制 / 粘贴 / 搜索设置；窗口尺寸变化同步到容器内；切换页内标签或顶层标签不会断开会话、不丢回滚内容。
- **结束**：容器退出、Pod 被删除或网络中断时，终端保留已有输出，底部显示结束原因（如退出码、OOMKilled、连接断开）与「重新连接」。关闭终端标签即结束会话；关闭集群标签或退出应用时结束该集群的全部会话。会话结束（关闭标签、「断开」、切换容器或 Shell 重连、关闭集群标签、退出应用）时，该会话在容器内启动的 shell 及其前台程序随之退出，不在容器内遗留进程；做不到时（如容器内缺少结束进程所需的命令），在日志里记录原因，不打扰用户。退出应用时若有打开的 Pod 终端，最多等待约 2 秒完成这一清理再退出；没有打开的 Pod 终端时退出不受影响。
- **失败**：无权限、容器不存在、自定义命令不存在等，在终端区显示集群返回的原因与「重新连接」。
- 会话的开始、结束与失败按项目日志规范记录（含资产 ID、命名空间、Pod、容器），不记录终端内容。

## 集群概览与事件

**集群概览**（范围随命名空间选择器）：

- 统计卡：Kubernetes 版本与平台；节点总数、可调度数、停止调度数与未就绪数；Pod 总数及运行 / 等待 / 异常数。
- 「需要关注」：列出就绪副本少于期望副本（期望 > 0）的 Deployment / StatefulSet / DaemonSet、失败的 Job、异常 Pod，每行显示原因，点击打开详情；没有时显示「一切正常」。
- 「最近告警事件」：最近的告警事件（最多 5 条），链接到事件列表；在默认窗口宽度且打开 AI 面板时，最近发生时间列完整可读，对象列（如 `Pod/pending-pod`）不被挤压到逐字换行。
- 节点卡片：名称、状态、角色、版本，点击打开节点详情。
- 各区块独立加载：某块取不到（如无权列出节点）时只有该块显示失败原因与重试，其余照常。

**异常的定义**：Pod 处于 Failed / Unknown / Pending，或任一容器处于等待且原因不是 ContainerCreating / PodInitializing，或任一容器上次以非 0 退出且仍在重启；节点未 Ready 或停止调度；Job 失败；工作负载就绪副本少于期望。

**事件列表**：列为类型、原因、对象（可点击打开）、消息、次数、最近发生时间；默认只看告警，可切到全部；可按对象 / 原因 / 消息过滤；按最近发生时间倒序。

## 刷新与状态保持

- 侧栏刷新按钮重新读取集群版本、可用类型、命名空间、计数，并刷新所有已加载的列表、详情与概览（保持 #212 的行为）；不影响终端会话与日志流。
- 切换到其他顶层标签再回来，侧栏折叠、命名空间、打开的页内标签与各列表的过滤、排序保持（沿用现有按资产缓存的做法）。
- 列表与详情只在首次打开、手动刷新、自动刷新或操作成功后读取；切换页内标签不重复读取。

## 连接、权限与失败

- 页面打开只依赖读取集群版本。版本读取失败时整页显示原因与重试；其余任何读取失败都只影响对应区域。
- 无权限、资源不存在、网络错误一律原样显示集群或网络返回的原因。
- 连接经资产配置的 SSH 跳板 / 代理链，与现有读取、日志流相同。
- 同一资产的请求复用到集群的连接，而不是每个请求各自建立：经 SSH 跳板时，打开页面、切换命名空间、刷新等同时发出的几十个请求只需少量 SSH 握手，不会因跳板机的并发握手限制（如 sshd `MaxStartups`）而失败。资产配置被修改或删除、集群标签关闭后，旧连接不再使用；连接断开后下一次请求自动重新建立。首次经某个跳板机访问（其 SSH 主机密钥尚未保存）时，同时进行的几次首次握手也全部成功，该主机密钥只保存一条记录。

## 兼容性

- K8s 资产的配置、导入导出与备份不变。
- AI / opsctl 通过统一 `exec` 执行 kubectl 的行为不变；本期不新增 AI 工具。
- 现有日志面板的功能（容器切换、尾部行数、开始 / 停止）不变，并复用到工作负载日志。
- 移除的界面：命名空间资源树、命名空间详情页（其计数信息由侧栏计数与概览取代）。

## Out of scope

- 端口转发、metrics-server 用量（第二期，单独出 spec）。
- 节点排空（drain）、回滚到指定版本、`kubectl cp` 文件传输、调试临时容器、Windows 节点的 PowerShell 自动检测（可用「自定义命令」手动指定）。
- 多集群同屏、资源变更的实时推送（watch）—— 本期以手动 / 定时刷新为准。
- 按 RBAC 预先隐藏操作（决策 8）。
- 审计日志记录 GUI 操作（决策 6）。
