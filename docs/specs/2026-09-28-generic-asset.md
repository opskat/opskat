# 自定义类型与通用资产

> Status: Approved
> Owner: OpsKat maintainers
> Last updated: 2026-09-28

**Objective:** 用户可以自己定义一类服务（如 Grafana、钉钉机器人、AWS CLI）：字段结构、凭据怎么注入、这类服务怎么用。之后只要为每个实例填上值，就能通过 opsctl 和内置 AI 访问，受现有策略、审批和审计约束。OpsKat 不为这类资产提供专门的操作界面。

**Hard invariant:** 内置资产类型与扩展资产类型的配置、执行、策略匹配、审批和审计行为不变。凭据由宿主注入（HTTP 认证、命令模板、环境变量），渲染结果不出现在调用方输出、AI 上下文、审批内容、审计记录或日志里。「取值」是唯一能输出明文的途径，每次都按策略判定。模板导出文件和日志里不含任何字段值。

## Problem

标注：**[已核实]** = 对照当前 main 源码确认；**[用户决定]** = 本轮讨论中用户选定。

1. **没有"只存凭据"的资产。** 资产类型都是内置的（`internal/assettype/` 按类型注册 handler）或来自扩展（`pkg/extension` manifest 声明的 `assetTypes`）。想管理一个 Grafana API key，要么写扩展，要么把 key 存在 OpsKat 之外。[已核实]
2. **扩展这条路太重，而且依赖桌面端。** 扩展平台能力（PR #326，未合并）的 spec 明确写了"opsctl 在桌面端未运行时独立执行扩展资产"不在范围内。内置类型的 opsctl 远程操作从 #318 起已经不需要桌面端。[已核实]
3. **帮助文档与门禁按内置类型静态注册。** `permission.RegisterExecutor(type, exec, SKILL.md 正文)` 在 `init()` 里注册；`help` 只返回类型的静态文档（`internal/ai/tool/tool_handlers_unified.go:179`）；DocGate 按类型记录（`internal/ai/tool/exec_gate.go`）。运行时由用户定义的类型没有地方提供文档，也无法过门禁。[已核实]
4. **备份不知道有自定义类型。** `BackupData` 覆盖分组、资产、凭据、Agent 来源、权限组、端口转发、快捷键、主题（`internal/service/backup_svc/backup.go:34`）。新增的类型定义如果不进备份，恢复出来的资产会没有类型可依。[已核实]

## Actors and user stories

1. 作为**运维用户**，我想把 Grafana 的地址和服务账号 token 存起来，然后 `opsctl exec grafana-prod -- GET /api/search?query=cpu` 就能调用，token 不会出现在命令行、输出或审计里。
2. 作为**运维用户**，我有三台 Grafana，只想定义一次"Grafana 怎么认证、有哪些接口"，每台实例只填地址和 token；改一次定义，三台同时生效。
3. 作为**运维用户**，我想把 AWS AK/SK 交给 `aws` 命令使用，但不希望其他命令读到它们。
4. 作为**运维用户**，我想接入钉钉机器人这类要求 HMAC 签名的 HTTP API，而不用写代码。
5. 作为**内置 AI / 外部 Agent**，我想通过 `help` 了解某类服务怎么用、这个实例里有什么，然后用 `exec` 调用，每个操作都受策略和审批约束。
6. 作为**运维用户**，我想把定义好的类型导出成文件分享给同事，同事导入后只需要填自己的值。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | **[用户决定]** 做成内置能力（自定义类型 + 通用资产），不走扩展 | opsctl 能独立于桌面端工作；用户不需要安装任何东西。Rejected: 通用 http 扩展 —— 依赖 #326、需要桌面端、要先装扩展；纯密钥保管 + 环境变量交给任意命令 —— 明文外泄，策略管不到具体操作 |
| 2 | **[用户决定]** 通用资产**必须**基于一个自定义类型；配置只存在类型里，资产只存值 | 配置来源只有一种，策略、help、门禁都以类型为单位。Rejected: 类型可选 + 一次性资产 —— 两种配置来源并存，表单、help、门禁都要分别处理 |
| 3 | **[用户决定]** 执行方式二选一：HTTP 请求 / 本地命令；不提供"仅存储" | exec 语义与策略写法唯一；两种方式都能取值。Rejected: 按首词自动判断 —— 有歧义；显式子命令 —— 多一层前缀 |
| 4 | **[用户决定]** 字段只存数据，注入位置全部用模板表达（HTTP 认证、命令模板、环境变量），三处使用同一套模板语言 | 一套语法覆盖 Bearer、Basic、复合环境变量、签名。Rejected: 字段上直接配置"环境变量名" —— 无法拼接，也无法表达签名 |
| 5 | **[用户决定]** 第一轮做模板函数和请求上下文；认证类型通过注册表扩展，首批只有 header / query / basic | 自定义 HMAC 签名（钉钉、飞书等）可以直接用；SigV4、OAuth2、JWT 这类标准协议以后注册签名器，在那之前用命令方式调官方 CLI。Rejected: 本轮就做常用签名器 —— 范围明显变大；只做静态模板 —— 签名类 HTTP API 用不了 |
| 6 | **[用户决定]** 本地命令方式下，命令写在类型上，可以留空。有命令时 exec 只传参数，按 argv 执行、不经过 shell；留空时 exec 传整条 shell 命令 | 固定程序时，密钥只交给这一个程序，策略也按参数写。Rejected: 必须配置命令 —— 需要管道或多个工具时用不了；只能调用时给整条命令 —— 防泄露全靠策略 |
| 7 | 模板只在类型配置里渲染；exec 传入的内容一律按字面处理 | 防止调用方把 `{{secret}}` 拼进任意参数带出密钥。Rejected: 调用方参数也渲染模板 —— 等于把取值能力开放给了所有 exec |
| 8 | **[用户决定]** 取值同时提供给 opsctl 和内置 AI，每次按策略判定，默认需要确认 | 用户接受明文进入 AI 上下文的代价，换取灵活性；审批弹窗会写明这一点。Rejected: 只给 opsctl |
| 9 | **[用户决定]** 默认策略：HTTP 放行 GET / HEAD / OPTIONS，其余需要确认；命令方式没有默认放行；取值没有默认放行 | 查询类操作不应每次弹窗，写操作和取明文要人确认。Rejected: 全部确认；全部放行 |
| 10 | 默认策略定义在类型上，新建资产时复制一份，之后按资产各自管理 | 与内置类型"新建时写入默认策略"一致。多实例共享规则用现有的权限组。Rejected: 资产实时继承类型策略 —— 会与资产级规则、权限组形成第三层继承 |
| 11 | **[用户决定]** 类型上有「使用说明」（这类服务怎么用），资产上沿用现有「备注」（这个实例里有什么），两者都进 help | 两者回答不同的问题，而且使用说明是多个实例共用的。Rejected: 只用备注 |
| 12 | help 分类型层和资产层；DocGate 按自定义类型记录 | 同一类型下的实例语法相同，看过一次类型文档就够了。Rejected: 按资产记录门禁 —— 每个实例都要重复调一次 help |
| 13 | 自定义类型的标识（slug）创建后不能修改 | 标识出现在 opsctl 脚本、AI 调用和导出文件里，改名会让这些引用静默失效。Rejected: 允许改名 |
| 14 | 类型还有资产在用时不能删除 | 避免出现没有类型的孤儿资产。Rejected: 级联删除资产 —— 一次操作删掉多个资产和它们的策略，风险太高 |
| 15 | 修改类型结构后立即对所有资产生效：删掉的字段，其值随之删除；新增的必填字段在资产上标为「缺值」，而不是阻止保存类型 | 保存类型不应被某一台实例卡住；缺值会被明确展示，调用时直接报错。Rejected: 缺值时禁止保存类型 |
| 16 | **[用户决定]** 本轮就做类型的导入 / 导出；导入时标识冲突只能换一个标识，不覆盖已有类型 | 分享类型是多实例复用的自然延伸。覆盖会静默改变已有资产的行为。Rejected: 覆盖已有类型 |
| 17 | HTTP 连接复用内置类型的 SSH 隧道 / 代理链 / TLS 配置区和拨号实现；这些配在资产上 | 每台实例的网络路径不同；Reuse first。Rejected: 在类型上配置连接 |
| 18 | 认证模板的渲染和函数实现放在 `internal/pkg` 下的共享包，#326 的扩展凭据注入与本功能共用 | 两套模板语法一定会漂移。两者谁后合并，谁就改为调用这个共享包 |

## 自定义类型

自定义类型在「设置 → 自定义类型」里管理，类型选择器的「自定义」分组和资产详情头部也有入口。

- **基本信息**：图标（复用 IconPicker）、名称（必填）、**标识**（必填，匹配 `^[a-z][a-z0-9-]{1,31}$`，创建后不可修改）。标识不能与内置类型、已加载扩展声明的类型或其他自定义类型重名，重名时禁止保存并指出冲突对象。
- **执行方式**：HTTP 请求 / 本地命令，二选一。
- **字段结构**：每行包括字段名（匹配 `^[A-Za-z_][A-Za-z0-9_]*$`，类型内唯一）、显示名、填写提示（可选）、是否密钥、是否必填、默认值（可选；密钥字段没有默认值）。至少要有一个字段。
- **HTTP 请求**：
  - Base URL 模板（必填），例如 `https://{{host}}` 或 `https://oapi.dingtalk.com`，可以包含路径前缀。渲染结果必须是 `http` 或 `https` 的绝对 URL。
  - 认证绑定列表，每项为「认证类型 + 名称 + 值模板」。首批认证类型是 `header`、`query`、`basic`；`basic` 需要用户名和密码两个模板，没有名称。
- **本地命令**：
  - 命令模板（可以为空），例如 `aws --region {{region}} --output json`。
  - 环境变量绑定列表，每项为「变量名 = 值模板」，变量名匹配 `^[A-Za-z_][A-Za-z0-9_]*$`。「从字段生成」会为每个字段追加一行 `大写字段名 = {{字段}}`。
- **使用说明**：Markdown，写这类服务怎么用。
- **默认策略**：允许 / 拒绝规则列表。新建类型时按执行方式预填（见「策略」一节）。

**保存校验**（有错误时禁止保存，并在对应行标出原因）：字段名重复或不合法；模板语法错误；模板引用了不存在的字段或函数；在 HTTP 认证以外的地方使用 `request.*`；认证类型未注册；环境变量名重复或不合法；命令模板里引用了密钥字段时不算错误，但会提示"命令行参数会被本机其他进程（ps）看到，建议改用环境变量"。

**修改已有类型**：保存后立即对所有资产生效，底栏会显示"已有 N 个资产使用"。
- 删除字段：各资产上对应的值一起删除。
- 新增必填字段（或把可选字段改为必填）：缺值的资产在详情顶部显示「类型新增了必填字段，这台实例还没填」，列出缺少的字段，并提供「去填写」。补填之前，对该资产执行 exec 会直接报"缺少字段 X"，不发出任何请求、不启动任何进程；取值同理。
- 字段由普通改为密钥（或反之）：值保留，按新属性存储与展示。
- 修改执行方式、绑定或使用说明：下一次调用生效。

**删除类型**：还有资产在用时拒绝，并列出这些资产的名称；没有资产在用时，确认后删除。

## 通用资产

新建资产时，从类型选择器的「自定义」分组选一个类型（分组里有「+ 新建自定义类型」，建好后回到资产表单并选中它）。表单结构与内置类型一致：类型、图标、名称、分组、配置、连接（仅 HTTP 方式）、备注。

- **配置**：按类型的字段结构生成输入项，显示名作为标签、填写提示作为 placeholder，必填项带星号；默认值预先填好。密钥字段可以选"直接输入"（加密保存）或"托管凭据"（引用凭据库条目），与 `PasswordSourceField` 的行为一致。表单下方写明"字段、认证方式与使用说明来自类型「X」"，并附「编辑类型」入口。
- **连接**（仅 HTTP 方式）：复用内置类型的连接区（直连 / SSH 隧道 / 代理链，TLS：跳过校验、ServerName、CA、客户端证书与私钥）。
- **测试连接**（仅 HTTP 方式）：渲染 Base URL 与认证后，对 Base URL 发一次 `GET`。只要收到 HTTP 响应就算连通，显示状态码与经过的隧道；401 / 403 显示为"认证失败"；连接、TLS、隧道错误原样显示。编辑已有资产时，未改动的密钥字段用已存的值补齐。测试连接不经过策略（它不是对资产的操作）。
- **校验**：必填字段为空时禁止保存和测试，并在字段下显示"必填"。
- **详情页**：没有「连接」按钮和功能 Tab。头部显示「<类型名> · 自定义类型 · 编辑类型」。卡片依次为：
  - 字段值：密钥显示为掩码，可以点眼睛查看；托管凭据显示条目名；另外显示渲染后的实际地址和隧道。
  - 用法：按执行方式给出 opsctl 示例，可复制，并附上使用说明的查看入口。
  - 策略卡。
  - 底部是备注。

## 模板语言

`{{ 表达式 }}` 可以出现在模板文本的任意位置，其余部分按原样输出。

- **值**：字段引用 `name`（取资产上的值，空的可选字段按空串处理）；字符串字面量 `"..."`（支持 `\n`、`\"`、`\\`）；`+` 拼接。
- **函数**：`base64(x)`、`hex(x)`、`urlencode(x)`、`sha256(x)`、`hmac_sha256(key, msg)`、`uuid()`。哈希与 HMAC 返回原始字节，通常再用 `base64` 或 `hex` 编码。
- **上下文**：`now.unix`、`now.unix_ms`。同一次渲染（一次 HTTP 请求或一次命令启动）里只取一次时间，所以多处引用得到同一个值。仅 HTTP 认证中可用：`request.method`、`request.path`（不含 query）、`request.body`。
- **失败**：语法错误、引用了未知字段或函数，在保存类型时就会报出。运行时如果密钥解密失败，整个请求或命令失败并报错，**不会**退回发送未认证的请求。

## HTTP 请求

**调用**：`opsctl exec <资产> -- <METHOD> <PATH> [-H '名称: 值']... [-d <数据> | -d @<文件> | -d @-] [-i]`。

- METHOD 可以是 GET / POST / PUT / PATCH / DELETE / HEAD / OPTIONS（不区分大小写）。PATH 必须以 `/` 开头，可以带 query，会拼接在渲染后的 Base URL 后面。写绝对 URL 会被拒绝。
- `-H` 可以重复。`-d @-` 从 stdin 读取请求体。exec 传入的内容一律按字面处理，不渲染模板。
- **注入**：宿主渲染认证绑定，把结果注入 header、query 或 basic auth。调用方写的同名 header / query 会被认证绑定覆盖。
- **输出**：响应体原样写到 stdout；状态行（如 `HTTP 200 OK`）写到 stderr；加 `-i` 时状态行和响应头也写到 stdout，放在响应体前面。响应为 2xx 时退出码为 0；其他状态码退出码为 1，响应体照常输出。请求没有完成时（校验失败、连接失败、TLS 失败、模板渲染失败），错误写到 stderr，退出码为 1，stdout 为空。
- **重定向**：同源重定向跟随（最多 10 次），继续注入认证；跨源重定向不跟随，返回错误，也不会把认证发往别的源。
- **连接**：按资产的隧道 / 代理链 / TLS 配置拨号；隧道、证书、握手出错时原样报错，不会退回直连或跳过校验。
- **AI**：通过统一 `exec` 调用，command 参数的写法与 opsctl 相同（`GET /api/search?query=cpu`）。返回内容是状态行加响应体，沿用 exec 现有的输出截断规则。响应不是文本（Content-Type 不属于 text/*、json、xml）时，只返回"二进制响应，N 字节，Content-Type"。

## 本地命令

- **有命令模板时**：调用 `opsctl exec <资产> -- <参数>...`。宿主渲染命令模板，按空白拆分出 argv（拆分发生在渲染之前，所以字段值里的空格不会拆出新参数），把 exec 的参数按字面追加在后面，不经过 shell 直接启动。例如命令模板 `aws --region {{region}} --output json`，调用 `exec aws-prod -- s3 ls`，实际执行 `aws --region ap-east-1 --output json s3 ls`。
- **命令模板为空时**：调用 `opsctl exec <资产> -- '<整条命令>'`，用系统默认 Shell 执行（与本地终端资产相同）。表单会提示：任何命令都能读到注入的环境变量，只能依靠策略拦截。
- **环境变量**：在当前进程环境的基础上，追加渲染后的绑定。
- **执行位置**：opsctl 当前的工作目录。stdin、stdout、stderr 直接透传，退出码原样返回。
- **失败**：程序不存在或无法启动时报错，退出码为 1；缺少必填字段时直接报错，不启动进程。

## 取值

- **opsctl**：`opsctl secret get <资产> <字段>` 把字段的原值写到 stdout（末尾带换行）。**内置 AI** 使用同一个工具处理器（在工具注册表中新增一项，opsctl 与 AI 共用）。
- **适用范围**：只对通用资产开放，不能用来读取内置类型的密码等。字段不存在时报错，并列出可用的字段名。
- **密钥字段**按策略判定，判定对象是 `secret:<字段>`；审批弹窗写明"明文将输出给调用方；来自 AI 时会进入对话上下文并发送给模型服务商"。**非密钥字段**本来就在详情和 help 里可见，直接返回，不经过审批。
- **审计**：只记录资产、字段名和判定结果，**不记录值**。

## 策略、审批与审计

- 通用资产使用命令型策略（允许 / 拒绝列表，沿用现有的 glob 语义与权限组），判定顺序为 deny → allow → grant → confirm。不同操作匹配的对象不同：
  - HTTP：`<大写方法> <路径>`，路径不含 query，例如 `GET /api/dashboards/uid/abc`。按普通 glob 匹配，不做 shell 解析。
  - 本地命令（有命令模板）：exec 传入的参数原样用空格连接，例如 `s3 ls s3://bucket`。
  - 本地命令（无命令模板）：整条命令，与本地终端资产的命令解析方式一致。
  - 取值：`secret:<字段>`。
- **默认规则**：新建类型时，HTTP 方式预填允许 `GET *`、`HEAD *`、`OPTIONS *`；命令方式没有预填。取值没有默认放行。新建资产时把类型的默认规则复制到资产上。
- **审批**：沿用现有的应用内审批与 opsctl 审批通道（桌面端未运行时回落到终端审批）。弹窗显示资产、操作类型（HTTP 请求 / 命令 / 取值）、匹配对象，以及渲染后的目标地址（HTTP）或程序名（命令），但不显示任何注入值。"始终允许"会把匹配对象保存为 grant，保存前可以改成通配。
- **审计**：HTTP 记录方法、路径和状态码；命令记录 exec 传入的内容和退出码；取值见上一节。认证渲染结果、环境变量值、命令模板渲染出的密钥都不进入审计和日志。`put_asset` / `opsctl create asset` 的审计会省略密钥字段的值，沿用 2026-08-13 spec 的字段白名单做法。

## 帮助、技能与门禁

- **类型层**：新增 `skills/generic/SKILL.md`，覆盖两种执行方式的语法、策略匹配对象、取值用法、`put_asset` 与 `opsctl create asset` 的写法。`help <类型标识>` / `opsctl help <类型标识>` 返回 SKILL.md 正文，外加这个类型的结构（执行方式、Base URL / 命令模板、认证 / 环境变量绑定、字段列表及属性）和使用说明。
- **资产层**：`help <资产>` 返回类型层内容，外加这个实例的字段值（密钥只标注"已设置"，不显示值；缺值的字段标明缺失）、渲染后的实际地址与隧道，以及备注。
- **门禁**：自定义类型下的资产按类型标识记录；在一个会话里，对类型或其中任一资产调用过 help，这个类型的所有资产就都能 exec。
- **技能清单**：系统提示词里的技能清单包含 generic 一项，并列出已定义的自定义类型标识和名称，方便 AI 发现。
- **外部 Agent**：`plugin/opsctl/skills/opsctl/SKILL.md` 与 `references/commands.md` 补充自定义类型、`opsctl secret get`，以及"先 `opsctl help <资产或类型>`"这一步。

## 通过 opsctl 与 AI 管理资产

- **新建 / 更新**：`opsctl create asset --type <类型标识> --name <名称> --config '<JSON>'`（或 `--config-file`），`update asset` 同理；AI 使用 `put_asset`，写法相同。
  - config 的键是字段名。密钥字段的值可以是明文字符串，也可以是 `{"credential_id": N}`，表示引用托管凭据。
  - 新增 `--secret <字段>`（可以重复）：不带值时在终端无回显地读入；没有终端时，与现有 `--password` 一样返回 NEEDS TTY（退出码 3）。
  - 未知字段、缺少必填字段、类型标识不存在时报错。
- 类型的定义、修改、删除、导入、导出只能在桌面端进行，本轮不提供 opsctl 或 AI 入口。

## 导入、导出与备份

- **导出**：在设置的类型列表里，每个类型都有「导出」，生成 `<标识>.opskat-type.json`。内容是格式标识与版本号、名称、标识、图标、执行方式、字段结构（含非密钥字段的默认值）、Base URL / 命令模板、绑定、使用说明、默认策略。**不含任何资产、字段值或凭据。**
- **导入**：「导入类型」选择文件后，先显示预览（名称、标识、执行方式、字段列表、绑定），确认后创建。
  - 格式版本不认识，或者引用了本机没有注册的认证类型、未知函数，都会拒绝导入并说明原因。其他校验规则与保存类型时相同。
  - 标识已存在时，必须填一个新标识（名称也可以改），不能覆盖已有类型。
- **备份**：全量备份与恢复包含自定义类型。
  - 替换模式：用备份中的类型替换现有类型。
  - 合并模式：标识已存在的类型保留本地版本，备份中的资产绑定到本地版本；因此出现的缺值按"新增必填字段"的规则展示。
  - 选择导入资产时，这些资产用到的类型会一起导入。

## Out of scope

- SigV4、OAuth2 client credentials、JWT 等签名器 —— 以后通过认证类型注册表扩展；在此之前用本地命令方式调用官方 CLI。
- 同一个资产同时使用 HTTP 和命令两种方式。
- 用 opsctl 或 AI 定义、修改、导入、导出类型。
- 在线类型商店和内置的预设类型。
- 命令方式下选择 Shell、设置工作目录。
- 非 HTTP 协议由宿主代做认证。
