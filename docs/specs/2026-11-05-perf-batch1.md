# 性能优化第一批：审计查询、opsctl 启动、前端重渲染、Redis / SFTP 往返、会话保存

> Status: Approved
> Owner: OpsKat 维护者
> Last updated: 2026-11-05

**Objective:** 消除 2026-11-05 性能扫描中证据最足、用户最常碰到的七处开销：审计页查询、每次 `opsctl` 调用的固定启动成本、终端 / 传输 / AI 流式事件引起的整应用重渲染、Redis 浏览器与 SFTP 每个操作多出来的网络往返，以及 AI 会话保存的非事务写入。

**Hard invariant:** 用户可见行为与数据不变——同样的查询返回同样的结果、同样的密文能被解密、同样的界面状态；只有耗时、渲染次数、网络往返数与锁持有发生变化。每一项都要先测出修改前的数字，修改后用同一方法复测。

## Problem

标注：**[实测]** = 扫描时实际测量；**[已核实]** = 对照 main（`f1d844f9`）源码确认。

1. **审计页会话列表扫全表。** [实测] 用户库 `audit_logs` 20.3 万行 / 161 MB，`ListSessions` 一天窗口 0.77–12 s，强制走 `idx_audit_createtime` 0.04 s。[已核实] `internal/repository/audit_repo/audit.go:103-115` 按 `session_id` 分组、`createtime` 过滤；索引只有单列（`migrations/202603220001_initial.go:91-95`）；从未 `ANALYZE`。`List` 带 `source` 过滤时同理（source 只有 3 个取值却被选为索引）。
2. **每次 `opsctl` 调用都付 keychain 子进程 + argon2id(64 MiB) 的固定成本。** [实测] 单独跑该 argon2 在高负载下 1.0–1.8 s。[已核实] `bootstrap.Init`（`internal/bootstrap/bootstrap.go:123,147`）无条件 `ResolveMasterKey` 并 `credential_svc.New` 立即派生；`list` / `help` 等不解密的命令也付。
3. **前端顶层组件订阅整个 store。** [已核实] `App.tsx:263-264`、`MainPanel.tsx:96-97`、`SideAssistantPanel.tsx:21-35`、`DatabaseTree.tsx:155`、`FileManagerPanel.tsx:177` 无 selector 或订阅全量字段；`ssh:sync`（每条命令 2–3 次）、传输进度（10 次/s）、AI 流式（20 次/s）都让整个应用与所有隐藏标签重渲染。`SplitPane.tsx:141-149` 拖动分隔条每次 mousemove 写 store。
4. **Redis 浏览器每个操作新拨一次连接。** [已核实] `redis_svc/service.go:171-190` `withClient` 每次 `connpool.DialRedis` 后关闭；运维面板集群概览每 2 s 刷新一次即每 2 s 重建集群客户端。查询面板已有带闲置淘汰与资产失效广播的连接缓存（`internal/app/query/conn_cache.go`、`query.go:52-75`）。
5. **SFTP 每个操作多一次往返，列目录时符号链接逐个 Stat。** [已核实] `sftp_svc/sftp.go:75-83` 每次取客户端都 `Getwd()` 探活；`:252-257` 对每个符号链接串行 `Stat`。
6. **SFTP 目录传输逐个文件串行。** [已核实] `sftp_svc/sftp.go` `UploadDir` / `DownloadDir` 每个文件 ~6 次串行往返，文件之间不重叠；`transfer.Tracker` 注释要求单调用方。
7. **AI 会话保存删除与插入分两次提交。** [已核实] `conversation_svc/conversation.go:131-150` 先 `DeleteMessages` 再 `CreateMessages`，不在一个事务里：两次写锁，中间崩溃丢整段历史。

## Requirements

| # | Requirement | Observable acceptance |
|---|---|---|
| R1 | 审计 `ListSessions` 与带 `source` 过滤的 `List` 在大表上按时间窗走索引 | 新迁移建 `(session_id, createtime)` 与 `(source, createtime)` 组合索引并更新统计；在 ≥20 万行的种子库上 `EXPLAIN QUERY PLAN` 不再全表扫描、一天窗口耗时较修改前下降一个数量级；查询结果与修改前逐行一致 |
| R2 | 不需要加解密的进程不读 keychain、不跑 argon2 | 主密钥解析与密钥派生推迟到首次 `Encrypt` / `Decrypt`，并发首次调用只派生一次；同一主密钥 + salt 加解密结果与修改前互通；解析失败作为 `Encrypt` / `Decrypt` 的错误返回而非 panic；`opsctl` 不解密的命令耗时较修改前下降（hyperfine 对比，沙箱数据目录） |
| R3 | 终端同步事件、传输进度、AI 流式与分隔条拖动不再重渲染无关组件 | 上述组件只订阅所需字段 / 动作；渲染计数测试：`sftp` 传输进度更新不使 `MainPanel` 重渲染、`ssh` 同步状态变化不使 `App` 重渲染、非侧栏会话的流式刷新不使 `SideAssistantPanel` 重渲染、其它标签的查询状态变化不使 `DatabaseTree` 重渲染；拖动分隔条期间直接改 DOM，松开时只写一次 `setSplitRatio` |
| R4 | Redis 浏览器在同一资产 / 库上复用连接 | 连接缓存从 `internal/app/query` 提到服务层可用的共享位置，`redis_svc` 与查询面板共用同一份缓存、同一套闲置淘汰与 `assetconn` 失效；连续多次 Scan / GetKeyDetail / ClusterOverview 只拨号一次；资产改连接配置后下次操作按新配置重拨 |
| R5 | SFTP 取客户端不额外往返，列目录的符号链接并发解析 | 去掉每次 `Getwd` 探活，改为客户端断开时自动移出缓存；会话断开后下一次操作仍能重新建立客户端或返回明确错误；符号链接 `Stat` 有界并发，结果顺序与内容与修改前一致；带延迟的测试桩上往返数 / 耗时下降 |
| R6 | SFTP 目录上传 / 下载多文件并发 | 有界 worker 池（4–8）并发传文件，远端目录先于文件按遍历顺序建立；`Tracker` 支持并发调用且进度总数、完成文件数准确；取消立即停止所有 worker；任一文件失败的错误照常返回；带延迟测试桩上 N 个小文件的耗时较串行下降 |
| R7 | 会话消息保存原子化 | 删除与插入在同一事务内；插入失败时旧消息保留（回滚可观察） |

## Out of scope

扫描报告第二、三档（SQLite WAL、流式输出攒批、RDP 帧、OSS 并行分片、exec 输出上限、扩展包哈希缓存、SQL 编辑器重复 COUNT、`sshpool` 持锁 keepalive、资产树虚拟化、主包拆分、空闲 ticker 等）；AI 工具 `cp` 的目录循环；前端 `persistNow` 的保存频率；审计日志保留策略。

## Verification

每项在沙箱（`make dev-sandbox` / `opsctl` 指向沙箱数据目录）或测试桩上测出修改前后的数字，记录命令与结果。不在用户真实数据目录上做任何验证。
