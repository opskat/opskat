# 扩展驱动的重定向拨号与证书 TLS（扩展平台能力第二轮）

> Status: Approved
> Owner: OpsKat 维护者
> Last updated: 2026-10-21

**Objective:** 扩展提供的数据库驱动可以跟随数据库监听器的重定向，连到资产地址以外的地址（仍经资产的到达途径），并可以用用户在资产里保存的 CA、客户端证书与私钥建立 TLS 连接；Oracle 的共享服务器、SCAN / RAC 与 TCPS 因此能由第三步的扩展支持。

**Hard invariant:** 四个内置驱动的连接与读写行为、已保存的数据库资产配置、不声明新能力的扩展驱动（仍只能拨资产的 `host:port`）、扩展资产类型的宿主侧 TLS 都不回退。

## 所处位置

本规格是 issue #329（Oracle 数据库支持）三步路线第二步「扩展平台能力」的第二轮。第一轮「扩展提供数据库驱动」（规格 [2026-10-19-ext-database-driver](2026-10-19-ext-database-driver.md)，PR #347 已合并）把这两项明确留给本轮：「监听器重定向到其他地址的场景本轮被拒，留给下一轮」「宿主保管的证书交给扩展的方式留给下一轮」。下一轮是宿主代取 Kerberos 票据；之后一轮「驱动提供 SQL 语句分类」；最后是第三步 Oracle 扩展。

## Problem

标注：**[已核实]** = 对照 opskat main（`085b260d`）源码确认；**[实测]** = 2026-10-10 用 go-ora（编成 wasip1、在真实扩展运行时里）连 docker.internal 上 Oracle 11.2~23ai 容器时观察到；**[用户决定]** = 本轮对话中用户选定。

1. **扩展驱动不能跟随重定向。** [已核实] 驱动调用中的拨号只放行资产配置的 `host:port`：按字符串比较主机与端口，比较前不做解析（`pkg/extension/driver_session.go` 的 `confineReach` / `sameEndpoint`），其他地址被拒并报 `dial denied: … is not the address of the database asset`。[实测] Oracle 共享服务器的监听器把客户端重定向到同一主机的随机分派器端口，SCAN / 远程监听器把客户端重定向到其他主机；不跟随时连接失败。
2. **经 SSH 隧道时连到的永远是资产地址。** [已核实] 数据库资产的 SSH 隧道途径用固定目标的拨号，忽略驱动要拨的地址（`internal/connpool/dialer.go` 的 `tunnelDialFunc`，`internal/connpool/database.go` 的 `databaseTransport`）；代理与代理链途径按请求的地址拨。[实测] 固定目标拨号遇重定向：共享服务器场景无限重拨（73 秒 392 次），远程监听器场景重拨 2 次后报 ORA-12516。
3. **数据库资产没有证书字段。** [已核实] 数据库资产只有 `tls`（开关）与 `ssl_mode` 两个 TLS 相关字段（`internal/model/entity/asset_entity/asset.go`），没有 CA、客户端证书、私钥、服务器名、跳过校验；内置 MySQL 打开 `tls` 时不校验证书（`internal/dbdriver/mysql/connect.go`）。Redis、etcd、Kafka 与扩展资产类型有完整的证书字段（路径或粘贴 PEM，私钥加密存储）。
4. **宿主代做 TLS 对数据库协议不成立。** [已核实] 扩展驱动的连接从不由宿主套 TLS（`pkg/extension/host_module.go` 打开驱动的 TCP 时 TLS 配置为空）；数据库客户端库自己在协议中途开始 TLS（PostgreSQL、MySQL 先明文协商再升级）。[实测] 宿主套好 TLS 再交给 go-ora 时报 `tls: bad record MAC`：Oracle 在握手过程中要求重做 TLS，TLS 必须由驱动自己驱动。

## Actors and user stories

1. 作为**运维用户**，我想用扩展提供的 Oracle 驱动连共享服务器、SCAN / RAC 集群，直连或经 SSH 隧道都能连上，不必事先知道集群里每个节点的地址。
2. 作为**运维用户**，我想在资产里填 CA、客户端证书与私钥，让扩展驱动以 TCPS / 双向 TLS 连数据库，与 Redis、Kafka 资产的填法一样。
3. 作为**运维用户**，我想在安装时看清这个扩展会跟随重定向连到其他地址、会拿到 TLS 私钥。
4. 作为**扩展作者**，我想用数据库客户端库自带的 TLS 与重定向逻辑，不必为宿主改库。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | **[用户决定]** 跟随重定向要由扩展在安全契约里声明；声明了的扩展的驱动可以拨任意地址，但一律经资产的到达途径，资产地址以外的每个地址记日志 | RAC / SCAN 用户通常不知道节点地址，声明后免配置即可用；扩展本来就拿到明文口令且安装时经用户确认。Rejected: 声明 + 每资产的地址白名单——白名单漏一项就表现为连不上，RAC 用户难以填全；每资产一个「跟随重定向」开关——用户得自己找到并打开 |
| 2 | 直连途径下，重定向到本机回环或链路本地地址被拒，除非资产地址本身就是这类地址 | 「任意地址」不应包括用户本机上的服务；经隧道或代理时这些地址在远端解释，不受此限 |
| 3 | **[用户决定]** 证书 TLS 由驱动在扩展里完成：宿主在打开会话时把证书内容（私钥解密后）交给驱动，与口令同样处理 | 驱动库（go-ora、pgx、MySQL 驱动）都自己在协议中途做 TLS，Oracle 还会中途重做；交出证书后这些库不用改。Rejected: 新增「在此连接上开始 TLS」的宿主调用、私钥留在宿主——每个驱动库都要打补丁改走宿主调用，并长期跟上游同步 |
| 4 | 证书字段沿用 Redis / Kafka 的字段与填法（启用、跳过校验、服务器名，CA / 客户端证书 / 客户端私钥各可填路径或粘贴 PEM，私钥加密存储） | Reuse first；用户在各类资产里的填法一致。Rejected: 驱动自己用专属字段声明证书——每个扩展各一套，私钥的加密与脱敏要各自实现 |
| 5 | 跟随重定向与证书字段组都是新的扩展能力，要求本轮新增的宿主 ABI | 更早的宿主不认识这两项，必须在安装时拒绝而不是装上后行为不同 |

## 跟随重定向

- **声明。** 扩展在安全契约（`manifest.json`）的网络能力里声明跟随数据库重定向（`network.databaseRedirects`）。只对声明了 `databaseDrivers` 的扩展有意义；没声明驱动却声明它，扩展加载失败并点名原因。
- **安装 / 升级确认。** 前提：要安装或升级的扩展声明了跟随重定向。动作：打开安装确认（桌面端安装 / 升级，以及 `opsctl ext dev` 的确认）。结果：能力列表里多一项，说明「驱动可以连到数据库重定向到的其他地址，经资产的到达途径」；升级时新增这项声明标为「新增」，与现有能力的新增标记一致。
- **拨号。** 前提：声明了跟随重定向的扩展的驱动在会话中拨号。结果：
  - 任意 `host:port` 都放行，一律经宿主为该资产解析的到达途径（直连、SSH 隧道、代理、代理链）；经 SSH 隧道时连到驱动请求的地址，而不是固定连资产地址；
  - 经隧道、代理或代理链时，主机名在远端解析；直连时在本机解析（`.local` 主机照常绕过 mDNS）；
  - 资产地址以外的地址，每条会话第一次拨时记一条日志：扩展、驱动、资产、地址（不含口令）；
  - 直连途径下，目标是本机回环（`127.0.0.0/8`、`::1`、`localhost`）或链路本地地址时被拒，错误点名该地址；资产地址本身就是这类地址时不受此限。
- **未声明的驱动。** 前提：扩展没声明跟随重定向。结果：与上一轮相同，只放行资产的 `host:port`；拒绝的错误在点名地址之外说明「该扩展未声明跟随数据库重定向」。
- **连不上。** 前提：重定向的地址经资产的到达途径不可达。结果：该操作失败，错误给出驱动的报错并点名地址；会话按上一轮的规则处理失败的实例。
- **范围。** 内置驱动的连接、其他资产类型、扩展资产类型的拨号规则都不变。

## 证书 TLS

- **声明。** 驱动描述可以在 TLS Tab 声明使用证书字段组。声明了的驱动，资产表单的 TLS Tab 显示与 Redis、Kafka 资产相同的证书字段：启用 TLS、跳过证书校验、服务器名，CA 证书 / 客户端证书 / 客户端私钥各可选「文件路径」或「粘贴内容」。不声明的驱动表单不变。
- **存储与展示。** 证书字段存在资产配置里，与 Redis 资产同名同义；私钥内容加密存储；opsctl 与 AI 查看资产时，私钥内容只显示为已设置。opsctl 与 AI 的创建 / 更新用同样的配置键，按驱动是否声明证书字段组校验（未声明时这些键被拒绝并点名）；私钥内容以明文出现在命令行时计入明文告警，与口令一致。驱动不可用时编辑保存资产，证书字段原样保留。
- **打开会话。** 前提：资产用声明了证书字段组的扩展驱动，并启用了 TLS。动作：打开会话（每个新实例登录时同样）。结果：
  - 宿主把 TLS 设置交给驱动：是否跳过校验、服务器名、CA 证书、客户端证书、客户端私钥的内容；填的是路径时，由打开会话的进程（桌面端或 opsctl）读取文件内容后交出；私钥解密后交出；
  - 这些内容与口令一样只在打开连接时给出，不进日志；
  - 驱动用它们自己完成 TLS，包括协议中途开始或重做 TLS；
  - 未启用 TLS 时，什么都不交。
- **失败。** 文件读不到或私钥解密失败：打开会话失败，错误点名出问题的字段（不含内容）。证书内容不合法、握手失败：操作失败，错误给出驱动的 TLS 报错。都不回落到不加密或不校验。
- **安装 / 升级确认的警示。** 声明了驱动的扩展，确认里的明文警示从「口令」改为「口令与 TLS 客户端私钥」（桌面端安装确认与 `opsctl ext dev` 的确认同样）。

## Out of scope

- 内置 MySQL、PostgreSQL、SQL Server 的证书字段：仍只有现有的开关与 SSL 模式。
- Oracle 钱包（wallet 目录 / `cwallet.sso`）：第三步 Oracle 扩展决定怎么填。
- 宿主侧为扩展驱动做 TLS、私钥不进扩展的方案（设计决定 3 的被否方案）。
- 每资产的重定向地址白名单、每资产的重定向开关（设计决定 1 的被否方案）。
- 宿主代取 Kerberos 票据：下一轮。
- 驱动提供 SQL 语句分类：另开一轮。
- 数据库资产经要 MFA 的 SSH 跳板时的 MFA 应答：与上一轮一致，不在本轮。
