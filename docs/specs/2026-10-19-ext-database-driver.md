# 扩展提供数据库驱动（扩展平台能力第一轮）

> Status: Approved
> Owner: OpsKat 维护者
> Last updated: 2026-10-20

**Objective:** 一个 WASM 扩展可以为内置的「SQL 数据库」资产提供驱动：装上扩展后，驱动出现在新建 / 编辑数据库资产的驱动下拉里，用它的资产在查询面板、AI、opsctl（含桌面端未运行时）中拿到与内置驱动相同的读写功能，连接在多次操作之间保持。

**Hard invariant:** 四个内置驱动（MySQL、PostgreSQL、SQL Server、SQLite）的全部读写行为、已保存的资产配置、现有扩展（资产类型、工具、页面、商店安装）的行为都不回退；不声明数据库驱动的扩展不受影响。

## 所处位置

本规格是 issue #329（Oracle 数据库支持）三步路线第二步「扩展平台能力」的第一轮。第一步「宿主驱动接口」已分两轮合并（读路径 [2026-10-10-database-driver-seam](2026-10-10-database-driver-seam.md)，PR #342；写路径 [2026-10-16-database-driver-write-path](2026-10-16-database-driver-write-path.md)，PR #345），共享代码不再按驱动名分支，驱动经 `dbdriver.Driver` 注册即可获得全部功能。

**[用户决定]** 第二步分三轮：

1. 本轮：扩展向「SQL 数据库」注册驱动 + 跨调用的会话。
2. 下一轮：经资产连接路径拨监听器重定向地址；协议中途由扩展发起、证书由宿主持有的 TLS。
3. 再下一轮：宿主代取 Kerberos 票据。

本轮完成后，Oracle 扩展（第三步）可以经直连、SSH 隧道、代理以明文协议跑通；TCPS 与重定向场景要等下一轮。

**[用户决定]** 本轮之前先做一轮「opsctl 独立运行扩展」（规格 [2026-10-19-opsctl-ext-standalone](2026-10-19-opsctl-ext-standalone.md)，PR #346 已合并）：opsctl 自己加载扩展、执行扩展资产的 exec，不依赖桌面端。本轮 opsctl 对扩展驱动的执行建在那一轮的 opsctl 扩展宿主上。

## Problem

标注：**[已核实]** = 对照 opskat main（`035c048c`）源码确认；**[实测]** = 2026-10-10 把 go-ora 编成 wasip1、用真实扩展运行时连 Oracle 23ai 时观察到；**[用户决定]** = 本轮对话中用户选定。

1. **扩展不能给「SQL 数据库」提供驱动。** [已核实] `database` 是内置资产类型（`internal/assettype/database.go:20`），资产类型注册表拒绝同名的第二个所有者（`internal/assettype/registry.go:107-110`）；扩展的 `describe()` 必须声明至少一个自己的资产类型（`pkg/extension/descriptor.go:67`）。没有任何「往已有资产类型里加驱动」的扩展点。
2. **扩展碰不到数据库资产。** [已核实] 扩展读资产配置、取凭据、经资产连接路径拨号都先经 `extension_svc.Service.OwnedAsset`，它拒绝类型不属于该扩展的资产（`internal/service/extension_svc/host_providers.go:115-125`）。
3. **连接活不过一次调用。** [已核实] 每次调用新建一组 IO 句柄，调用结束全部关闭（`pkg/extension/runtime.go:464-467`）；实例池每个扩展 4 个、按到达顺序轮转、没有亲和（`runtime.go:42`、`:497`）。[实测] guest 里缓存的连接在下一次调用报 `handle 1 not found`；每次调用都要重新登录，本地 0.1~0.16 秒、60ms 链路 0.8 秒；「整表导出」这类跨多次调用读同一个游标的操作做不到。
4. **扩展里的超时不起作用。** [实测] guest 阻塞在宿主读里时，guest 的定时器不触发：2 秒超时的查询跑满 6.7 秒；宿主侧取消有效（2.0 秒），做法是关掉连接，该实例随之作废。
5. **驱动注册表只适合启动时注册。** [已核实] `dbdriver.Register` 遇到撞名直接 panic（`internal/dbdriver/registry.go:43-58`）；前端的驱动描述在进程内只取一次（`frontend/src/lib/dbDrivers/descriptors.ts:8-19`），之后加载或卸载的驱动看不到。
6. **驱动契约对外部仓库不可见。** [已核实] 驱动契约（`internal/dbdriver`）与所有内置驱动共用的实现 `internal/dbdriver/sqldb`（非测试代码约 2600 行，基于 `database/sql` 加可选的方言接口）都在 `internal/` 下，外部仓库的扩展按 Go 规则不能导入；契约里的驱动 id 与配置类型来自 `internal/model/entity/asset_entity`（`internal/dbdriver/descriptor.go:12`、`driver.go:31`）。[实测] go-ora 的 `database/sql` 驱动在 wasip1 里可用。
7. **opsctl 执行数据库 SQL 时只认内置驱动。** [已核实] opsctl 对数据库资产的 exec 在自己进程里经 `connpool.OpenDatabase` → `dbdriver.Lookup` 连驱动执行（`internal/connpool/database.go:28`），驱动只来自内置驱动的注册（`internal/assettype/database.go:11`）。上一轮让 opsctl 能按需激活单个扩展（`cmd/opsctl/command/ext.go:39` `activateExtensionFn` → `extension_svc.Service.Activate`），但目前只用于扩展资产的 exec，不涉及驱动。
8. **没声明 `network.assetEndpoint` 的扩展 TCP 不受限制。** [已核实] 这种扩展的 TCP 不做任何地址检查、直连拨号（`pkg/extension/host_capability.go:57-63`），是为早期第一方扩展保留的。驱动拿着用户数据库的口令，不能沿用这条路。

## Actors and user stories

1. 作为**运维用户**，我想装上一个提供 Oracle 驱动的扩展后，在「SQL 数据库」里直接选 Oracle 建资产，像内置数据库一样浏览、查询、编辑、导入导出，不必为它学一套新界面。
2. 作为**运维用户**，我想在 opsctl 里对这类资产执行 SQL，桌面端没开也能用。
3. 作为**扩展作者**，我想只写连接与方言就做出一个完整的驱动，与内置驱动共用同一份通用实现，而不是自己再写一遍浏览、分页、表格编辑、导入导出。
4. 作为**运维用户**，我想在安装时看清这个扩展会拿到哪些数据库资产的口令，并且它只能连到这些资产配置的地址。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | **[用户决定]** 扩展平台能力分三轮：本轮驱动 + 会话，下一轮重定向拨号 + 扩展发起的 TLS，再下一轮 Kerberos | 驱动没有跨调用会话就每次点击都重新登录，整表导出也做不了，两者必须一起交付；网络与 TLS、Kerberos 各自独立可交付。Rejected: 驱动扩展点单独先做——交付后的扩展驱动又慢又缺功能；一轮做完五项——体量过大，任一项卡住整轮都交付不了 |
| 2 | **[用户决定]** 驱动契约类型与 `sqldb` 移到 `pkg/` 公开；扩展驱动与内置驱动一样只写连接与方言，宿主把会话上的每个操作转给扩展执行 | 一份通用实现，不分叉；第三步 Oracle 的工作量最小。Rejected: SDK 只镜像一份协议类型、扩展自己实现全部操作——两份通用实现会漂移；宿主跑 `sqldb`、扩展只给原始连接——方言是代码不是数据，每个方言钩子都要跨边界一次，往返过多 |
| 3 | **[用户决定]** 扩展驱动可以声明自己专属的连接字段，类型是扩展资产类型配置字段的子集（文本、数字、开关、枚举、口令、多行），并指定放在哪个 Tab | Oracle 有「Service Name / SID 二选一」「以 SYSDBA / SYSOPER 登录」这类内置字段集合表达不了的项。Rejected: 只用内置字段 + 额外参数——用户手写 `sid=…`，易用性差，校验全靠连接报错；推迟到第三步——Oracle 那一轮会夹带平台改动 |
| 4 | **[用户决定]** opsctl 自己加载提供驱动的扩展，桌面端没运行也能对这类资产执行 SQL；建在上一轮的 opsctl 扩展宿主上 | 用户要求 opsctl 的扩展能力都不依赖桌面端，扩展 exec 先单独一轮做。Rejected: 执行交给桌面端——桌面端不开就用不了 |
| 5 | **[用户决定]** 一条会话最多同时用 3 个扩展实例，每个实例各持一条数据库连接、按需创建；游标与整批执行固定在一个实例上；超出的操作排队 | WASM 实例单线程，一次只能跑一个调用；内置驱动底下是连接池，长查询时树的浏览、AI 批量执行照常并行。Rejected: 每会话一个实例串行——同一资产上一个长查询会挡住其他所有操作；实例内由扩展自己并发——阻塞在宿主读里时实际仍串行 |
| 6 | 驱动由扩展的安全契约（`manifest.json`）点名声明，具体描述来自 `describe()`；安装 / 升级确认把「提供数据库驱动」当作一项能力列出，并给出与「读取凭据」同级的警示 | 安全契约必须在不运行扩展的情况下可读，沿用现有能力声明的分工；驱动必然拿到用它的资产的明文口令。Rejected: 只在 `describe()` 里声明——安装确认时看不到 |
| 7 | 扩展驱动只能连到资产配置的地址，且一律经宿主为该资产解析的到达途径（直连、SSH 隧道、代理、代理链）；驱动调用中只提供日志与这条拨号，不提供其他宿主能力 | 驱动处理的是用户数据库的口令与数据，范围要最小。监听器重定向是下一轮的事。Rejected: 沿用扩展 TCP 的现有规则——没声明 `network.assetEndpoint` 时不检查地址 |
| 8 | 宿主强制执行超时与取消：取消或超时时宿主关掉该实例的连接，操作立即失败，该实例作废，会话本身继续可用 | 扩展里的定时器不触发（Problem 4），只有宿主侧有效。Rejected: 交给扩展自己超时——实测不生效 |
| 9 | AI / opsctl 执行前的 SQL 分类沿用现有分类器，不在本轮交给驱动 | **[用户决定]** 驱动提供语句分类同时牵涉内置 PostgreSQL / SQL Server，另开一轮在第三步之前做 |

## 声明与安装

- **安全契约。** 扩展在 `manifest.json` 的能力里列出它提供的驱动 id（`databaseDrivers`）。`describe()` 为其中每个 id 给出一份驱动描述，字段与内置驱动的描述相同：
  - 基本信息：展示名、显示顺序、别名、默认端口；
  - 表单与功能：使用的内置表单字段、功能声明、写功能的细项声明（能否关闭外键检查、建库选项、改表可改属性、能否不靠主键定位单行）；
  - 本轮新增：专属连接字段（见「驱动专属字段」）。

  驱动的图标就是扩展的图标。
- **声明不一致即加载失败。** 前提：契约与 `describe()` 的驱动 id 集合不同，或某个描述不合法（未知的字段、功能、Tab，专属字段与内置字段同名）。动作：加载扩展。结果：扩展不加载，错误点名扩展与出问题的驱动 id；其他扩展照常加载。
- **只提供驱动的扩展。** 声明了驱动的扩展可以不声明自己的资产类型与策略类型；不声明驱动的扩展仍须至少声明一个资产类型（现有规则不变）。
- **宿主 ABI。** 声明驱动要求扩展的宿主 ABI 为本轮新增的版本；更早的宿主拒绝安装，报 ABI 不兼容，与现有兼容性检查一致。
- **安装 / 升级确认。** 前提：要安装或升级的扩展声明了驱动。动作：打开安装确认。结果：
  - 能力列表里有一项「提供数据库驱动」，点名每个驱动的 id（**[用户决定]** 安装确认时扩展尚未运行 `describe()`，安全契约里只有驱动 id，不显示展示名）；
  - 同时给出警示：用这些驱动的数据库资产，口令会以明文交给扩展；
  - 升级时新增的驱动标为「新增」，与现有能力的新增标记一致。

## 注册与归属

- **注册。** 前提：扩展已启用且通过校验。动作：桌面端启动或扩展加载。结果：它的驱动进入驱动注册表，驱动下拉、表单字段、功能入口、opsctl / AI 的创建与更新都认得它，与内置驱动无差别。
- **撞名。** 前提：某个驱动 id 或别名与内置驱动或另一个已加载扩展的驱动相同。动作：加载扩展。结果：这个扩展整体不加载（它的资产类型、工具也不注册，全有或全无）；错误点名冲突的名字与已占用它的一方；已占用者不受影响；应用不崩溃。
- **归属。** 用扩展驱动的数据库资产属于提供该驱动的扩展：只有这个扩展能经会话拿到它的配置、口令，并经它的到达途径拨号。其他扩展对它的访问照旧被拒绝；这个扩展对其他数据库资产的访问也被拒绝。

## 会话

- **打开。** 前提：资产用扩展驱动。动作：查询面板、AI 或 opsctl 第一次对它（或它的某个库，按驱动声明的会话粒度）执行操作。结果：
  - 宿主起一个专属于这条会话的扩展实例，把配置、口令与到达途径交给驱动，驱动建立连接并确认可达；
  - 连不上时，操作失败并给出驱动的报错，与内置驱动连不上时的展示一致；
  - 交给驱动的配置不含宿主自用的部分（隧道、代理、凭据 id、加密后的口令），口令是解密后的明文，只在打开会话的那次调用里给出。
- **保持。** 前提：会话已打开。动作：之后在同一资产上展开树、翻页、编辑、导入导出。结果：都在这条会话已有的连接上执行，不再登录；「整表导出」的游标跨多次调用读完；会话按查询面板现有的空闲规则回收，回收时关闭它的全部实例与连接。
- **并发。** 前提：同一条会话上有多个操作同时进行。结果：
  - 最多 3 个操作同时执行，每个占用一个实例，各自一条连接；实例按需新建（新建即一次登录），超出的操作排队，按到达顺序执行；
  - 游标从打开到关闭、整批执行从开始到结束，都固定在同一个实例上；
  - 多出来的实例空闲后关闭，会话至少保留一个实例直到它被回收。
- **超时与取消。** 前提：操作在执行中，用户取消，或达到资产的查询超时。结果：
  - 宿主关掉该实例的连接，操作在约 1 秒内以「已取消」或「超时」失败；
  - 该实例作废，会话的其他实例与排队的操作不受影响，下一个需要实例的操作重新登录；
  - 取消排队中的操作只是把它移出队列；
  - 驱动调用不套用扩展工具的 30 秒默认超时，只受资产查询超时与调用方取消约束。
- **扩展故障。** 前提：扩展在调用中 panic、陷入 trap 或超出内存上限。结果：该操作失败，错误标明是扩展驱动的故障；该实例作废，会话继续可用；故障记进应用日志。
- **扩展里的其他宿主能力。** 驱动调用中，扩展只能写日志、经会话的到达途径拨号；KV、文件对话框、HTTP、读取其他资产配置一律拒绝，错误说明「驱动调用中不可用」。

## 网络

- 前提：驱动在会话中拨号。结果：
  - 只允许拨资产配置的 `host:port`，其他地址被拒，错误点名被拒的地址，拒绝记进日志（不含口令）；
  - 一律经宿主为该资产解析的到达途径：配置了代理链、SSH 隧道或代理就经它们，否则直连，直连 `.local` 主机时同样绕过 mDNS；
  - 与扩展是否声明 `network.assetEndpoint` 无关。
  - 到达途径上的 SSH 跳板要 MFA 时，与内置驱动的数据库资产一致：桌面端、opsctl 都不为它应答 MFA（opsctl 只对 SSH 资产与扩展资产应答，[已核实] `cmd/opsctl/command/batch_mfa_test.go:265`）。
- 监听器重定向到其他地址的场景本轮被拒，留给下一轮。
- 数据库连接的 TLS 由驱动在扩展里自己完成；宿主保管的证书交给扩展的方式留给下一轮。

## 驱动专属字段

- **声明。** 驱动描述可以声明专属字段：键、类型（文本、数字、开关、枚举、口令、多行）、所在 Tab（连接、隧道、TLS、高级之一）、是否必填、默认值、枚举取值，标签与说明走扩展自己的多语言。
- **表单。** 前提：资产表单选了这个驱动。结果：专属字段显示在声明的 Tab 里、该 Tab 内置字段之后；必填未填时不能保存，提示与内置字段一致；切换到别的驱动时，专属字段不再显示，保存时不写入新驱动的配置。
- **存储。** 专属字段的值存在资产配置的驱动专属区（`driver_options`），口令类的值与内置口令一样加密存储；opsctl 与 AI 查看资产时，口令类显示为已设置，不显示内容。
- **详情卡。** 资产详情卡在内置连接信息之后列出非口令类的专属字段。
- **opsctl 与 AI 的创建 / 更新。** 专属字段在入参的 `driver_options` 对象里给出，按驱动声明的类型、必填与默认值校验；口令类与内置口令一样计入明文告警；未声明的键被拒绝，错误点名该键。
- **驱动不可用时。** 前提：提供驱动的扩展停用或卸载。动作：编辑并保存这个资产（改名、移动分组等）。结果：保存成功，`driver_options` 原样保留，不被清空。

## 生命周期

- **停用、升级、卸载。** 前提：扩展提供的驱动有打开着的会话。动作：停用、升级或强制卸载扩展。结果：
  - 驱动从注册表移除，它的会话全部关闭；
  - 执行中与排队中的操作失败，报驱动不可用、点名驱动；
  - 用它的资产保留驱动 id 与配置，查询面板显示现有的「驱动不可用」提示；
  - 升级完成后新版本的驱动重新注册，下一次操作按新版本打开会话。
- **启用。** 前提：资产的驱动来自刚被启用的扩展。结果：不必编辑资产，下一次操作即可正常连接。
- **卸载保护。** 前提：还有数据库资产使用这个扩展的驱动。动作：非强制卸载。结果：卸载被拒绝，错误给出资产数量与驱动 id。扩展停用时同样检查，因为检查按资产配置里的驱动 id 进行，不依赖扩展是否已加载。
- **前端刷新。** 前提：驱动注册或移除。结果：驱动下拉、表单、查询面板不重启应用即反映变化；已打开的查询标签页在驱动移除后显示「驱动不可用」，驱动恢复后可以重新打开。

## opsctl

- **管理。** opsctl 能按扩展驱动的描述创建、更新、查看、列出这类资产（含专属字段），与内置驱动的用法一致；创建与更新时跑驱动自己的配置校验。
- **执行。** 前提：桌面端未运行或运行均可。动作：opsctl 对用扩展驱动的资产执行 SQL。结果：
  - opsctl 经上一轮的 opsctl 扩展宿主加载提供该驱动的扩展，经同样的会话、网络与归属规则执行；审批与审计走 opsctl 现有的数据库执行流程；
  - 扩展在桌面端被停用时，opsctl 同样视其为不可用，报驱动不可用。
- **共存。** 桌面端与 opsctl 同时运行时，各自持有自己的会话，共用扩展目录与编译缓存，互不干扰。

## 公开的驱动契约

- 驱动契约（描述、会话、请求与结果类型）与通用实现 `sqldb` 移到 `pkg/` 下公开，不再依赖任何 `internal/` 包；内置驱动、查询面板与 AI 改为使用公开的契约。四个内置驱动各自的方言代码仍在 `internal/`。
- 扩展 SDK 提供注册数据库驱动的入口：扩展作者给出驱动描述与「打开连接 + 方言」，SDK 用公开的 `sqldb` 组装出会话，宿主侧看到的就是一个普通驱动。
- 契约跨宿主与扩展的边界以 JSON 传递；以后给请求或结果加字段必须向后兼容，旧扩展收到不认识的字段时忽略。
- 共享代码不按驱动名分支的检查（`internal/archtest` 与 eslint）照常适用，不加例外。
- `docs/references/adding-a-database-driver.md` 增加「由扩展提供驱动」一节，扩展作者指南给出驱动的写法与能力声明。

## Out of scope

- 经资产连接路径拨监听器重定向地址、协议中途由扩展发起的 TLS、宿主保管的证书交给扩展：扩展平台能力第二轮。
- 宿主代取 Kerberos 票据：第三轮。
- 驱动提供 SQL 语句分类、让 AI / opsctl 的策略按方言判断：另开一轮，在 Oracle 扩展之前。本轮扩展驱动的资产沿用现有分类器，方言特有的语句可能被拒绝执行（只影响 AI / opsctl，不影响查询面板）。
- 手动事务、固定会话的用户可见能力。
- 数据库资产（内置或扩展驱动）经要 MFA 的 SSH 跳板时的 MFA 应答：与内置驱动现状一致，不在本轮。
- Oracle 扩展本身：第三步。
- 读回值编码（二进制、超过 2^53 的整数）：写路径规格已定为另开一轮。
- 非强制卸载在扩展停用时不检查其资产类型的资产（现有行为，[已核实] `internal/service/extension_svc/service.go:396-407`）：本轮只为驱动做按配置的检查，资产类型的这一处不改。

## 修正轮 1：开发安装确认与 `--driver` 明文告警

运行时验证（`e2e/scratch/2026-10-19-ext-database-driver/report.md`）有两项不成立，**[用户决定]** 开修正轮一并修：

- **开发安装 / 升级确认。** [实测] `opsctl ext dev` 安装或升级声明了驱动的扩展时，桌面端确认弹窗的能力行写 `capabilities: none`，不提驱动、没有明文口令警示。前提：用 `opsctl ext dev` 安装或覆盖一个声明了 `databaseDrivers` 的扩展。动作：桌面端弹出确认。结果：与「声明与安装」里的安装 / 升级确认一致——能力里列出「提供数据库驱动」并按 id 点名每个驱动，给出与 `credentials: read` 同级的醒目警示（用这些驱动的数据库资产，口令会以明文交给扩展）；覆盖安装时新增的驱动标出「新增」。不声明驱动的扩展，弹窗内容不变。
- **`--driver` 旗标下的明文告警。** [实测] `opsctl create asset … --driver <扩展驱动> --config '{"driver_options":{<口令类字段>:"…"}}'` 不出现明文告警；驱动写在 `--config` 里时会告警。前提：opsctl 创建或更新数据库资产，口令类专属字段以明文出现在 `--config` / `--config-file` 里，驱动由 `--driver` 旗标给出（或更新时取自已存资产）。动作：执行命令。结果：与驱动写在 `--config` 里时相同的明文告警；告警不回显口令值。不含口令类专属字段时不告警，现有内置口令的告警不变。

| Seam | What it verifies | Prior art |
|---|---|---|
| 开发安装确认 | 声明驱动的扩展的确认内容含「提供数据库驱动」、各驱动 id、明文警示，覆盖安装时新增驱动标「新增」；不声明驱动时内容不变 | `internal/app/opsctl/ext_dev_test.go` |
| 明文告警 | `--driver` 旗标 + `--config` / `--config-file` 中的口令类专属字段告警；无口令类字段不告警 | `cmd/opsctl/command/create_asset_parser_test.go`、`ext_test.go` 的 `TestExtensionDriverFields_ManagedFromTheCommandLine` |
