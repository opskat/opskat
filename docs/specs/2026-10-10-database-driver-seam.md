# 数据库驱动接口（第一轮：读路径）

> Status: Approved
> Owner: OpsKat 维护者
> Last updated: 2026-10-12

**Objective:** 「SQL 数据库」资产的四个内置驱动（MySQL、PostgreSQL、SQL Server、SQLite）的资产配置、连接、浏览与查询行为，全部由一个驱动注册表提供；新增一个驱动只需注册一份实现，不修改共享代码。

**Hard invariant:** 除「有意的行为变化」一节列出的四项外，四个内置驱动现有的全部行为不回退——资产的创建 / 编辑 / 测试连接、查询面板的浏览与查询、AI 与 opsctl 的 SQL 执行，结果与改动前一致；已保存的资产配置不需要迁移。

## 所处位置

本规格是 issue #329（Oracle 数据库支持）三步路线的第一步的第一轮。**[用户决定]** 路线为：宿主驱动接口 → 扩展平台能力 → Oracle 扩展；Oracle 以及以后的其他 SQL 数据库由扩展提供驱动，仍挂在「SQL 数据库」资产下，用数据库类型区分。本轮只做宿主侧，不涉及扩展平台，也不接入任何新数据库。

## Problem

标注：**[已核实]** = 对照 opskat main（`7114d960`）源码确认；**[用户决定]** = 本轮对话中用户选定；**[未复现]** = 读代码得出、尚未在运行中复现。

1. **驱动差异是写死在共享代码里的分支。** [已核实] 后端 11 个非测试文件按驱动常量分支：连接（`internal/connpool/database.go:243,303,374`）、元数据与打开表（`internal/service/query_svc/object_meta.go:105,299,402,561`、`open_table.go:94,166,245`）、引号（`quote.go:16,35`）、导入（`table_import.go:182`）、分页（`internal/ai/helper/database_helper.go`）、资产参数（`internal/assettype/database.go`、`contracts.go`）、端口与校验（`internal/model/entity/asset_entity/asset.go`）、类型断言别名（`internal/ai/permission/type_assert.go`）、面板连接缓存键（`internal/app/query/query_ops.go`）。前端 16 个非测试文件按驱动字符串分支。每加一个驱动，这些位置都要再加一路。
2. **前端没有驱动抽象，MySQL 是所有分支的默认值。** [已核实] 驱动在前端是裸 `string`（`frontend/src/stores/queryStore.ts:17`、`tabStore.ts:30`），没有联合类型，也没有任何描述驱动属性的集中位置；每个分支的 `else` 都是 MySQL 写法。一个未被识别的驱动会被静默当成 MySQL：反引号、`SHOW …`、`LIMIT`、端口 3306。
3. **大部分功能由前端拼 SQL 文本。** [已核实] 只有打开表首屏、表元数据、对象列表、对象源码、SQL 编辑器分页是结构化调用。列数据库与列表（`queryStore.ts:349-398`）、表浏览的计数与翻页（`TableDataTab.tsx:271-315`）、筛选与排序、查看建表语句（`TableDataTab.tsx:905` 起，各库一套）、导出取数、表格增删改、建表 / 改表 / 删表 / 清空、建库、导入，都是前端生成 SQL 文本后走通用的 `ExecuteSQL`（前端非测试代码共 20 处调用）。由扩展提供的驱动无法把方言知识编进前端。
4. **同一条方言规则在多处重复。** [已核实] 标识符引号规则前端一份（`frontend/src/lib/tableSql.ts`）、后端一份（`query_svc/quote.go`，注释写明与前端等价）；首屏的计数与分页在后端，其后每一页在前端；「是否按 schema 分组」在 `queryStore.ts:400` 与 `DatabaseTree.tsx:74` 各定义一次。
5. **资产详情卡显示错误的驱动名。** [已核实] `frontend/src/components/asset/detail/DatabaseDetailInfoCard.tsx:41` 只区分 PostgreSQL 与其他，SQLite 和 SQL Server 资产都显示为 "MySQL"。
6. **PostgreSQL「查看建表语句」按固定 schema 查询。** [未复现] `TableDataTab.tsx:913-915` 把 schema 写死为 `public`，并用完整的 `schema.table` 字符串去匹配表名；而表名正是以 `schema.table` 形式从列表传入（`queryStore.ts:377`）。按代码推断该功能对 PostgreSQL 的表查不到列。

## Actors and user stories

1. 作为**运维用户**，我想让现有 MySQL / PostgreSQL / SQL Server / SQLite 资产在这次改动后用起来和以前一样，不需要重新配置。
2. 作为**运维用户**，我想在资产详情里看到资产真实的数据库类型。
3. 作为**驱动实现者**（宿主维护者，以及下一步的扩展作者），我想通过注册一份驱动实现来增加一种数据库，并声明它支持哪些功能，而不必去改查询面板、资产表单或 AI 执行的共享代码。
4. 作为 **AI / opsctl 用户**，我想让 `exec` 在数据库资产上的行为、以及用驱动名声明类型时的校验，与现在一致。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | **[用户决定]** 新数据库由扩展提供驱动、挂在「SQL 数据库」资产下；先做宿主驱动接口，再补扩展平台能力，最后做 Oracle 扩展 | 以后接更多 SQL 数据库时方便处理。Rejected: 把 Oracle 驱动直接编进宿主——所有用户的安装包多约 15 MB，每加一种数据库都要改宿主并发版 |
| 2 | **[用户决定]** 方言相关的 SQL 一律由驱动生成，前端只发结构化意图；分两轮交付，本轮做读路径，写路径下一轮 | 扩展只需用 Go 实现一次。Rejected: 一轮做完——表格编辑、改表、导入这些高风险路径与读路径绑在同一次发布，回归面最大；前端继续生成、改读驱动描述数据——各库的改表语法、无主键时的单行更新、导入的 upsert 写法用数据表达不了，最终两套机制并存 |
| 3 | 驱动标识沿用现有存储值 `mysql` / `postgresql` / `mssql` / `sqlite` | [已核实] 资产配置里已存这些值，沿用即无需迁移。Rejected: 重新命名并迁移——没有收益 |
| 4 | 读路径操作以「驱动持有的连接」为对象，由驱动自己执行并返回结构化结果；共享代码不替驱动拼 SQL，也不直接对驱动的连接发方言语句 | [已核实] 扩展驱动的会话在扩展内部，宿主无法替它执行语句（issue #329 调研：go-ora 在扩展运行时里实测）。Rejected: 驱动只返回 SQL 文本、共享代码统一执行——取值规整（如二进制、大数）与分页策略（如读够行数即关游标）仍会留在共享代码里按驱动分支 |
| 5 | 驱动没有声明支持的功能，其入口在界面上隐藏 | [已核实] 现有做法：SQLite 隐藏「新建数据库」（`DatabaseTree.tsx:442`）。Rejected: 置灰并提示——与现有做法不一致，且对内置驱动没有新增信息 |
| 6 | 资产的驱动未注册时，给出「驱动不可用」的明确错误 | 仓库原则：不做无意义的回退。Rejected: 沿用现状，按 MySQL 处理——会对一个不是 MySQL 的库发 MySQL 语句 |
| 7 | 资产表单沿用现有的声明式字段描述与标签页；每个驱动声明自己在各标签页里的字段，SQLite 的文件选择与来源切换保留为该驱动自己注册的表单片段 | [已核实] 表单在 main 上已是声明式（`DatabaseConfigSection.tsx` 的四个标签页），驱动差异只剩按驱动名的可见性条件。Rejected: 为驱动另建一套表单机制——重复现有能力 |
| 8 | 隧道、代理链等各资产类型共用的连接参数不进驱动；驱动只负责自己特有的字段 | [已核实] 这部分已收成共用的一份（`internal/assettype/connection_args.go`）。Rejected: 每个驱动各自处理——重复实现 |
| 9 | 表浏览的翻页、计数与导出取数只携带结构化的筛选条件与排序项，由驱动据此生成查询；界面不新增手写 `WHERE` / `ORDER BY` 的入口 | [已核实] 表浏览没有可编辑的 `WHERE` / `ORDER BY` 输入：这两段文本是内部状态，只由筛选器、单元格筛选和列头排序写入（`TableDataTab.tsx:163-164,659-661,679,692,705`），筛选器本身收发的就是结构化条件（`TableFilterBuilder.tsx:76-85`）。Rejected: 驱动生成文本后由前端原样带回——文本不向用户展示，多一次往返没有收益；新增可见的手写输入——是本轮之外的界面变化 |
| 10 | 写路径在本轮保持前端生成，受功能声明控制显示 | **[用户决定]** 见决定 2。四个内置驱动声明的功能集合与它们今天实际可用的功能一致 |
| 11 | 共享代码中新出现的按驱动名分支由自动检查拦截；写路径尚未迁移的文件列入豁免名单，名单只减不增 | [已核实] 仓库已有同样做法（`internal/archtest` 的遗留豁免名单、`frontend/eslint.config.js` 的受限用法规则）。Rejected: 只靠评审——分支会再长回来 |

## 驱动注册表与驱动描述

每个驱动向注册表登记一份实现和一份描述。描述包含：标识、显示名、图标、可用作类型断言的别名、默认端口、它在资产表单各标签页中使用的字段、它支持的功能。

功能声明覆盖以下各项，逐项可独立声明：按 schema 分组、新建数据库、查看建表语句、对象浏览（视图 / 存储过程 / 函数 / 触发器）、表格编辑、建表、改表、删表、清空表、导入、导出为 SQL 语句、复制为 SQL 语句、连接级只读。

- 前提：应用启动完成。动作：前端需要某个驱动的属性（表单字段、图标、显示名、是否分 schema、某功能是否可用）。结果：从后端取得的驱动描述中读取；前端共享代码不出现按驱动名的判断（写路径豁免名单内的文件除外）。
- 前提：打开数据库资产的新建或编辑表单。动作：选择驱动。结果：驱动下拉列出注册表中的全部驱动，表单显示所选驱动声明的字段与默认值，图标随之切换；四个内置驱动呈现的字段、默认值、校验提示与改动前一致。
- 前提：资产的驱动声明了「按 schema 分组」。动作：展开数据库节点。结果：表按 schema 分组显示；未声明的驱动不分组。
- 失败：取驱动描述失败时，表单与查询面板显示该错误，不使用任何内置的替代列表。

## 资产配置与连接

各驱动特有的配置校验、默认值、通过 opsctl 与 AI 创建 / 更新资产时接受的参数与规范化规则、连接的建立（含经隧道、代理、代理链）、连接级只读的处理，由驱动实现负责。

- 前提：通过表单、opsctl 或 AI 创建或更新数据库资产。动作：提交配置。结果：按所选驱动的规则校验与保存；对四个内置驱动，接受的参数、缺失参数的报错、默认端口、SQLite 的路径与来源规则与改动前一致。
- 前提：一份已保存或未保存的数据库配置。动作：测试连接或打开查询面板。结果：经该驱动建立连接；直连、SSH 隧道、SOCKS5 代理、代理链、`.local` 主机名、远端 SQLite 的行为与改动前一致。
- 需要列出可用驱动的错误信息与帮助文本（如缺少驱动参数时的提示）由注册表生成，不再写死四个名字。
- 失败：连接失败时返回驱动给出的错误，表现与改动前一致。

## 读路径操作

以下操作由驱动提供，前端发出结构化请求、接收结构化结果，不再为它们生成 SQL 文本：

| 操作 | 前提与动作 | 可观察的结果 |
|---|---|---|
| 列数据库 | 打开查询面板 | 数据库列表与改动前一致（含 SQL Server 不列系统库、SQLite 无附加库时显示 `main`） |
| 列表与视图 | 展开一个数据库 | 表与视图列表、排序、schema 限定名的形式与改动前一致 |
| 打开表 | 点击一张表 | 首屏的列、类型、列约束、主键、总行数、第一页数据与改动前一致 |
| 表浏览翻页与计数 | 翻页、改每页行数 | 返回对应页的数据与符合当前筛选条件的总行数，与改动前一致 |
| 筛选与排序 | 在筛选器里增删条件、按单元格的值筛选，或点击列头排序 | 返回的行、顺序与总行数与改动前一致；请求中只有结构化的条件与排序项，没有 SQL 文本 |
| 起始查询语句 | 在表的右键菜单里打开 SQL 编辑器 | 编辑器中预填的查询语句由驱动生成，内容与改动前一致（SQL Server 为 `SELECT TOP`，其余为 `LIMIT`） |
| 查看建表语句 | 在表上选择查看建表语句 | 显示该表的建表语句；MySQL、SQL Server、SQLite 的内容与改动前一致，PostgreSQL 见「有意的行为变化」 |
| 对象浏览 | 展开视图 / 存储过程 / 函数 / 触发器，查看源码 | 与改动前一致 |
| SQL 编辑器执行 | 执行一条语句并翻页 | 结果、分页、总行数与改动前一致 |
| 导出数据取数 | 导出为 CSV / TSV / XLSX（可带当前的筛选与排序） | 导出的行与列与改动前一致 |

- 失败：数据库返回的错误原样到达界面，位置与改动前一致；驱动未声明的操作被调用时返回明确的「该驱动不支持此操作」错误，不执行任何语句。

## 写路径的中间态

表格编辑、建表、改表、删表、清空表、新建数据库、导入、导出为 SQL 语句、复制为 SQL 语句在本轮保持现有的前端生成方式。

- 前提：资产的驱动声明了某项写功能。动作：使用该功能。结果：四个内置驱动的行为与改动前一致。
- 前提：资产的驱动未声明某项写功能。结果：该功能的入口不显示。四个内置驱动声明的功能集合等于它们今天可用的功能，因此现有界面不变（SQLite 仍不显示「新建数据库」）。

## 有意的行为变化

1. **资产详情卡显示真实驱动名。** 前提：查看 SQLite 或 SQL Server 资产的详情。结果：驱动一栏显示该驱动的显示名，不再是 "MySQL"。
2. **PostgreSQL 查看建表语句按表所在的 schema 查询。** 前提：PostgreSQL 资产中任一 schema 的表。动作：查看建表语句。结果：显示该表的列、类型、非空、默认值与主键，语句中的表名带其实际 schema。当前行为按代码推断为查不到列 [未复现]；动手前先复现，以确认这是修复而非行为不变。
3. **未注册的驱动报错。** 前提：资产配置中的驱动不在注册表里。动作：打开查询面板、测试连接、或经 AI / opsctl 执行 SQL。结果：返回「驱动不可用」并指明驱动名；该资产仍可编辑与删除。不再按 MySQL 处理。
4. **没有字段的标签页不显示。** **[用户决定]** 前提：打开数据库资产的新建或编辑表单。结果：所选驱动没有声明任何字段的标签页不出现。对内置驱动，这只影响 SQLite：它没有任何 TLS 字段，原先仍显示一个空白的 TLS 标签页，现在不再显示；其余驱动的标签页与改动前一致。

## AI 与 opsctl

- 前提：AI 或 opsctl 对数据库资产执行 SQL。结果：连接与执行经该资产的驱动；权限检查、审批、审计、返回格式与改动前一致。
- 前提：调用方用驱动名或其别名声明类型（如 `--type mysql`、`postgres`、`sqlserver`、`sqlite3`）。结果：别名来自各驱动的描述；对四个内置驱动，可用的名字与断言结果与改动前一致，声明的驱动与资产不符时照旧报错。

## 兼容性

- 已保存的资产配置不变、不迁移。
- 现有的结构化调用与通用的 SQL 执行调用保留；新增的读路径调用是增量。
- 不改变 SQL 权限策略的解析方式、审批流程与审计记录。

## 文档

新增一份贡献者文档，说明如何添加一个数据库驱动（注册实现、声明描述与功能、哪些地方仍在写路径豁免名单内）；更新架构文档中数据库与查询面板相关的描述，并按文档维护规则登记新文档。

## Out of scope

- 写路径改由驱动生成（表格编辑、建表 / 改表 / 删表 / 清空、建库、导入、导出与复制为 SQL）——第二轮规格。
- 手动提交 / 回滚与固定会话——随扩展平台的会话能力一起设计。
- 扩展向「SQL 数据库」注册驱动、扩展平台的会话级连接 / 重定向网络 / TLS 握手 / Kerberos 取票能力——第二步规格。
- Oracle 驱动本身——第三步规格。
- 数据库类型的 TLS 接入证书字段（CA / 客户端证书）——不在 issue #329 路线内，另行提出。
- AI 的 SQL 权限策略按方言解析——另行提出。
- SQL 编辑器按方言的关键字与函数补全——另行提出。
- 导入对话框调用了不存在的绑定（`ImportTableDataDialog.tsx:202-205`，[未复现]）——与本轮无关，单独修复。

## Testing decisions
