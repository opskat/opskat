# 扩展 ABI 重置为 1.0：运行时与业务解耦

> Status: Approved
> Owner: OpsKat 维护者
> Last updated: 2026-10-27

**Objective:** 扩展运行时只认识 WASM 沙箱、宿主函数、权限与调用作用域；资产类型、工具、策略、片段、数据库驱动、前端页面都作为**贡献**由所属子系统定义、校验与接入。安全契约只表达基础能力，扩展作者面对一套 SDK、一种可调用单元（工具），前端页面只拿到有稳定约定的宿主组件。已发布的 Oracle、Elasticsearch 扩展与仓库内的 notebook 迁到新 ABI 后功能不变。

**Hard invariant:** 内置资产类型与四个内置数据库驱动的行为不回退；AI / opsctl 经 `exec` 调用扩展工具时的策略、审批、授权与审计不回退；现有每一项网络与凭据门禁的收紧程度不放松（唯一的放宽是决定 4 的 `network.assetRoute`，必须声明并在安装确认里列出）；口令、keytab、Kerberos 会话密钥与认证注入的明文不交给扩展的范围不扩大。

## 所处位置

**[用户决定]** 不考虑兼容，并把 ABI 版本重置为 `1.0`：宿主只认新形状的 hostABI `1.0`。[已核实] hostABI 2.0~2.5 只在 main 与 nightly 上出现过；最新正式版 v1.14.0 的 `HostABIVersion` 是旧形状的 `1.0`（工具、资产类型等写在 manifest 里），与新 ABI 同名，由此带来的失败表现见「版本与旧扩展」。原先分析里的三块（贡献点、能力、前端）合成一轮，在一个长期分支上做完再一次合并进 main；扩展仓（opskat/extensions）里的 Oracle、Elasticsearch 迁移也在本轮，商店发布等宿主发版后再做。

## Problem

标注：**[已核实]** = 对照 main `c60d0bf8` 或扩展仓 `origin/main` `0cb89de` 的源码确认；**[用户决定]** = 本轮对话中用户选定；**[未知]** = 只能在实现或真机上确认。

1. **运行时里写着业务规则，并且已经和宿主对不上。** [已核实] `pkg/extension` 自己校验资产类型的 configSchema、端点 / 认证 / 连接项、工具参数、策略组前缀、片段分类、驱动描述（`descriptor.go:42-492`、`manifest.go:249-366`）。其中片段的内置分类清单硬编码为 shell / sql / redis / mongo / prompt（`manifest.go:88-94`），而宿主的片段分类注册表还有 `k8s`（`internal/service/snippet_svc/category.go:58-64`）：扩展声明 `k8s` 分类能通过校验，随后被注册表静默跳过；扩展往内置的 `k8s` 分类预置片段则在加载时被拒。多处校验在子系统里又做了一遍（`internal/assettype/extension.go:54-59`、`snippet_svc/service.go:343`、`policy_group.go:561`）。
2. **能力按业务需求在长。** [已核实] hostABI 2.3 / 2.4 / 2.5 各加了一项只给数据库驱动用的东西：`capabilities.databaseDrivers`、`network.databaseRedirects`、`capabilities.databaseKerberos` 与宿主调用 `dbdriver.kerberos_ticket`（`manifest.go:59-67,203-220`、`host_module.go:70-71`）。「经资产连接路径拨任意地址」「用资产凭据取 Kerberos 票据」本身是通用能力，但名字与校验都限定在驱动上（不声明驱动就拒绝，`manifest.go:564-571`）；驱动会话是一条独立的特判路径（`hostfn.go:63-85`、`driver_session.go:146-405`）。
3. **调用单元有三套。** [已核实] 工具（`opskat.Tool`，有 schema、策略、超时）、Action（`RegisterAction`，只给页面调，无 schema、无策略、无超时、不出现在 describe 里，`pkg/extsdk/registry.go:547-549`）、驱动会话；宿主对应 `CallTool` / `CallAction` / `OpenDriverSession` 三个入口，页面对应 `CallExtensionTool` / `CallExtensionAction` 两套调用。
4. **必须声明资产类型。** [已核实] describe 不声明资产类型就拒绝加载（`descriptor.go:89`），只给纯驱动扩展开了豁免（`:79-87`）；纯片段包这类不需要资产的扩展做不了。
5. **线格式维护了两份。** [已核实] SDK 有自己的一套 describe 结构，注释要求「JSON tag 与 `pkg/extension/descriptor.go` 手工保持一致」（`pkg/extsdk/describe.go:17-18`）。
6. **轻量的商店索引拖进整个运行时。** [已核实] `pkg/extstore`（扩展仓的发布工具也用）只为兼容判断与能力类型 import 了 `pkg/extension`，依赖里因此有完整的 wazero 与宿主网络代码。
7. **宿主组件直接成了 ABI。** [已核实] 页面经 `hostUI` 拿到的 `QueryResultTable` 就是查询面板的组件本身（`frontend/src/extension/inject.ts:8,26`），它的 props 改动会直接破坏扩展；页面的 `slot` 从未被校验，唯一的取值是 `asset.connect`（`frontend/src/extension/assetTypes.ts:43`），没有 slot 的页面没有入口。
8. **opsctl 与桌面端校验不一致。** [已核实] 桌面端加载扩展时校验「认证 / 连接项需要端点字段」（`manager.go:305,319`），opsctl 用缓存的 describe 时不校验（`manager.go:250-263`）。

## Actors and user stories

1. 作为**扩展作者**，我想用一套 SDK 注册工具、资产类型、策略组、片段、驱动和页面，写错时在加载那一刻就得到点名具体贡献的错误，不必关心宿主内部怎么接。
2. 作为**扩展作者**，我想只写一种可调用单元：页面要的长任务、事件流、取消，和 AI / opsctl 要的策略、审批，都在同一个工具上声明。
3. 作为**扩展作者**，我想做一个只提供片段或只提供驱动的扩展，不必为此虚构资产类型。
4. 作为**运维用户**，我想在安装确认里看清扩展要的每一项基础权限，尤其是能经资产连接路径到达其他内网地址的权限。
5. 作为**运维用户**，我想升级应用后，已装的 Oracle、Elasticsearch 扩展换成新版本即可照常使用；没换的旧版本明确显示为不兼容，而不是半工作。
6. 作为**宿主维护者**，我想改查询面板、片段分类、策略模型时不必同步修改扩展运行时。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | **[用户决定]** 不保留兼容，宿主只支持新形状的 hostABI `1.0`；三块一轮做完，长期分支一次合并 | 只破坏一次，扩展仓只迁移一次；2.x 从未进入正式版，版本号从头开始。Rejected: 分 PR 合进 main——合并期间 nightly 上商店扩展不可用；每块各升一次 ABI——扩展要重建发布三次；用 `2.0` 或 `3.0`——不与 v1.14.0 的旧 `1.0` 同名，旧扩展能被判为不兼容，但用户选择从 1.0 重新开始，同名代价见「版本与旧扩展」 |
| 2 | 运行时与贡献分离：运行时只做沙箱、宿主函数、权限执行、调用作用域和贡献点注册表；每种贡献由所属子系统注册贡献点并负责校验、接入、撤销 | 业务规则回到规则的主人那里，片段分类这类漂移从结构上不再发生。Rejected: 只把业务清单改成注入——两份线格式与运行时里的 help 渲染都还在 |
| 3 | 门禁按**调用作用域**执行：每次调用带上由拥有该资产类型的子系统解析好的作用域（资产、可达端点、连接路径拨号器、认证注入、票据来源、允许的宿主调用），运行时只按作用域与权限放行 | 驱动会话现在已是这个形状（宿主注入 reach 与票据来源），扩展资产的工具调用也改成这样后，运行时不再需要读 configSchema 与认证声明。Rejected: 运行时继续按贡献内容自己算端点——运行时得一直认识资产类型 |
| 4 | **[用户决定]** `network.assetRoute`（原 `databaseRedirects`）对任何带资产的调用生效：声明并经安装确认后，工具与驱动都可经该资产的连接路径拨任意地址；安装确认把它标为高风险 | 与驱动现在承担的风险同一级别，且由用户逐个扩展确认。Rejected: 改名后仍只给驱动——机制统一了但权限仍按业务区分 |
| 5 | Kerberos 票据机制通用化为权限 `kerberos` 与宿主调用 `auth.kerberos_ticket`，但只有带票据来源的作用域能取到票；本轮只有用 Kerberos 认证的数据库资产会带票据来源 | 沿用 [2026-10-22 规格](2026-10-22-ext-driver-kerberos-sql-classify.md)决定 3、5：只用本资产凭据、只给本资产的调用、必须声明。实际可取票的范围与现在相同。Rejected: 扩展资产类型也可配置 Kerberos 凭据——没有需求，扩大攻击面 |
| 6 | **[用户决定]** Action 并入工具：每个工具要么声明策略动作（AI / opsctl 的 `exec` 与页面都能调），要么声明只给页面用；任何工具都可发事件、可被取消；只给页面用的工具可以不设超时 | 一种可调用单元；页面工具也得到参数 schema 校验。Rejected: 保持分开——两套注册、两套调用入口 |
| 7 | 数据库驱动 id 仍在 manifest 里预先声明（`contributes.databaseDrivers`），并须与 describe 一致 | 安装确认在运行扩展代码前就要告诉用户「这个扩展会接管 oracle 驱动」（2026-10-22 规格决定 5 的同一理由）。Rejected: 只从 describe 得知——安装确认读不到 |
| 8 | 只有声明了策略动作的工具才要求扩展提供资产类型；其他贡献不要求 | 经 `exec` 调用必须指向本扩展类型的资产，这是工具贡献点自己的规则。Rejected: 保留全局「必须声明资产类型」并扩充豁免——豁免清单只会越来越长 |
| 9 | SDK 与宿主共用一份纯数据线格式；manifest、权限与兼容判断放在一个不依赖运行时的纯数据包里，商店索引只依赖它 | 消除手工同步的副本与发布工具对 wazero 的依赖。Rejected: 保留 SDK 副本加对照测试——仍是两份 |
| 10 | `hostUI` 只导出宿主为扩展定义 props 的包装组件：`CodeEditor`、`JsonTreeView`、`DataTable`；页面必须声明宿主定义的插槽 | 宿主内部组件可以自由演进。Rejected: 继续透出查询面板组件——它的每次改动都是一次 ABI 破坏 |
| 11 | **[用户决定]** 本轮包含扩展仓 Oracle、Elasticsearch 的迁移，并用它们做真机验收；商店发布在宿主发版后进行 | 只有真实扩展才能证明新 SDK 可用。Rejected: 另开一轮——问题要到合并后才暴露 |

## 安全契约（manifest.json）

manifest 只含用户在扩展代码运行前就要审核的内容：`name`、`version`、`minAppVersion`、`hostABI`、`backend`、`permissions` 与 `contributes.databaseDrivers`。

`permissions` 的每一项都是基础能力，不提任何业务：

- `fs.read` / `fs.write`：可读写的路径前缀，语义同现在的 `capabilities.fs`。
- `credentials: "read"`：可拿到资产凭据明文，语义不变。
- `kerberos`：可在带票据来源的作用域里取 Kerberos 票据（决定 5）。
- `network.http`：可访问的 URL 前缀白名单，语义同现在的 `http.allowlist`。
- `network.allowPrivate`：白名单里的地址允许解析到内网地址，语义同现在的 `tunnel`。
- `network.assetEndpoint`：可访问作用域里资产的端点，语义不变。
- `network.assetRoute`：可经作用域里资产的连接路径拨任意地址（决定 4）。直连时目标在本机解析，解析结果是回环、链路本地、未指定地址或本机任一网卡地址时拒绝，错误点名扩展、资产与目标；例外只有资产自己的地址：资产端点是回环 / 链路本地地址时可拨这类地址，资产端点解析到本机某个网卡地址时可拨该地址本身（任意端口），本机其他地址仍拒绝。经 SSH 隧道或代理链的拨号在远端解析，不受此限。

manifest 里出现未知字段、`hostABI` 不是 `1.0`、或某项权限的取值不合法时，manifest 解析失败，错误点名扩展与字段。`contributes.databaseDrivers` 之外的贡献出现在 manifest 里同样是解析错误。

安装、升级与 `opsctl ext dev` 的确认逐项列出声明的权限与驱动 id；`network.assetRoute`、`kerberos`、`credentials: "read"` 标为高风险，升级时新增的项标为新增，与现在对新增能力的标注方式一致。

## describe() 与贡献点

describe 的回答由 `icon`、`i18n` 与 `contributes` 组成；`contributes` 的每个键对应一个贡献点：`assetTypes`、`tools`、`policy`、`snippets`、`pages`、`databaseDrivers`。

- 运行宿主扩展的每个进程（桌面端、opsctl）在加载任何扩展前注册同一组贡献点。
- 加载时，每个键交给对应贡献点校验。贡献点能看到整个扩展的只读视图（权限与全部贡献），用于跨贡献的规则。
- 全部通过后才依次接入；任何一个接入失败，已接入的全部撤销，扩展不加载。
- 卸载、停用时撤销该扩展的全部贡献。
- describe 里出现未注册的键，或进程缺少某个贡献点，扩展不加载。
- 错误点名扩展、贡献类型和具体条目，例如：`elasticsearch: tools[bulk]: parameter "body" ...`。
- 读缓存的 describe（opsctl、列表、已停用扩展）走同一套贡献点校验，与桌面端首次加载的结论相同（问题 8）。

## 各贡献的规则

规则沿用现在的语义，只是归属改变；下面只写本轮有变化或需要明确的部分。

**资产类型**：configSchema 规则、端点字段、认证绑定、连接项、测试连接的语义不变。声明认证或连接项要求有端点字段，且权限里有 `network.assetEndpoint`。资产类型名不得与内置类型或其他扩展的类型重名。

**工具**：
- 名字、参数类型、禁止 `asset_id` 参数、超时上限等规则不变。
- 每个工具必须二选一：声明策略动作（固定动作、按参数分类、或按参数给出多个资源），或声明只给页面用。两者都没有、或两者都有，都是注册错误。
- 声明了策略动作的工具要求本扩展至少提供一个资产类型（决定 8）。
- 默认超时 30 秒，可声明最长 10 分钟；只给页面用的工具可声明不设超时，由调用方取消。
- 参数可标记为「大内容」（原 `FileParam`）：opsctl 接受 `--<名>-file <路径>` 或 `-` 读标准输入，AI 与页面照常传值，策略、审批、审计都看到完整内容，与现在相同。

**策略**：策略面类型、策略组 id 前缀、默认组的规则不变；策略动作集合仍由工具的声明推导。只有声明了策略动作的工具时才要求声明策略面类型。

**片段**：分类 id 与预置片段的格式规则不变。哪些分类是内置的，只由宿主的片段分类注册表决定，因此 `k8s` 与以后新增的内置分类都受保护：扩展声明与内置同名的分类，加载失败并点名该分类；扩展可以往任何内置分类预置片段。

**数据库驱动**：驱动描述的校验规则不变；manifest 与 describe 的驱动 id 集合必须一致；驱动 id 不得与内置驱动或其他扩展的驱动重名。驱动声明使用 Kerberos 字段组时，权限里必须有 `kerberos`。

**页面**：每个页面必须声明插槽，且插槽属于宿主定义的集合，本轮只有 `asset.connect`（双击本扩展类型的资产打开的页面）。入口脚本与样式路径必须位于扩展目录内，规则与现在前端的检查相同，改为在加载时校验。

## 调用作用域与权限执行

每次调用都在一个作用域里执行。作用域由拥有资产类型的子系统解析：扩展资产类型由资产类型子系统解析，数据库资产由数据库连接子系统解析。作用域给出：

- 资产（id、名称、类型），没有资产时为空；
- 可达端点；
- 连接路径拨号器（SSH 隧道、代理链、TLS 配置）；
- 认证注入；
- 票据来源；
- 本次调用允许使用的宿主调用。

运行时对每个宿主调用按作用域和 manifest 权限放行：

- **网络**：
  - `network.http` 白名单内的地址按现在的规则直连。
  - 作用域端点在声明 `network.assetEndpoint` 时可达，并按现在的规则走连接路径和认证注入。
  - 其他地址只有声明了 `network.assetRoute` 且作用域有连接路径时才可经连接路径拨号。
  - 都不满足时拒绝，并记录一条点名扩展、资产与目标的拒绝日志，与现在一致。
- **票据**：只有作用域带票据来源、且声明了 `kerberos` 时，`auth.kerberos_ticket` 才返回票据；否则返回点名原因的错误。SPN 规则沿用 2026-10-22 规格决定 3。
- **调用种类的限制**：数据库驱动会话的作用域只允许日志、TCP 与截止时间、停止检查、取票据，与现在相同。这条限制由作用域表达，运行时不再判断「是不是驱动会话」。
- **凭据**：`asset.get_config` 只服务作用域里的资产，且该资产的类型必须由本扩展提供，明文与否按 `credentials`，语义不变。

## 工具调用

- AI 与 opsctl 经 `exec <资产> -- <工具>` 只能调用声明了策略动作的工具。只给页面用的工具在 `help` 里不出现，经 `exec` 调用时返回「该工具只供扩展页面使用」。
- 页面可以调用本扩展的任何工具，可带资产 id（页面所在资产）或不带。参数按工具的 schema 校验。页面调用不经策略、审批、授权与审计，与现在页面调用工具相同。
- 工具执行中发出的事件只送给页面调用方，AI 与 opsctl 的调用方忽略事件。
- 页面可按调用 id 取消任何一次工具调用；取消后工具的停止检查返回真，调用以取消结束。
- 原先用 Action 实现的功能（Elasticsearch 控制台内容的读取与保存、测试夹具里的事件与取消用例）改为只给页面用的工具后，事件、取消与长时间运行的行为保持不变。

## 前端

- **页面**：在资产上双击打开的页面由 `asset.connect` 插槽决定，与现在相同。插槽清单由宿主定义，前端与 Go 两侧各自持有并由一致性检查对照。
- **`hostUI`**：导出 `version`（与 hostABI 相同，`1.0`）、`CodeEditor`、`JsonTreeView`、`DataTable`。每个组件的 props 由 `hostUI` 自己定义，至少覆盖 notebook 与 Elasticsearch 现在的全部用法，宿主内部组件的 props 变化不改变这些契约：
  - **`CodeEditor`**：值、语言、高度、字号、只读、占位提示、编辑器选项、变更回调，以及挂载回调。挂载回调交出编辑器实例与 Monaco 实例，扩展可以据此注册语言、高亮与补全（Elasticsearch 控制台现在就这样用）。Monaco 本身的 API 属于契约的一部分，宿主升级 Monaco 主版本即是一次 hostUI 契约变更。
  - **`DataTable`**：列、行、加载中、行号与行号偏移、行高密度、排序、复制、单元格选中回调与行选中回调。
  - **`JsonTreeView`**：只读展示一个 JSON 值。
- **页面 API**：只有调用工具与取消工具调用两个调用入口；调用工具可传入事件回调。原先调用 Action 的入口删除。

## SDK

- 扩展作者只 import 一个 SDK 包。它用共享线格式生成 describe，不再有手工同步的副本。
- 注册调用一一对应贡献：资产类型、工具（策略动作或只给页面用、事件、大内容参数、超时）、策略组、片段分类与预置片段、页面、数据库驱动。
- `ToolContext` 提供资产、参数、资产配置、事件写入与停止检查；`ActionContext` 与 `RegisterAction` 删除。
- 注册错误仍在扩展加载时失败，不推迟到首次调用。

## 版本与旧扩展

宿主的 `SupportedHostABIs` 只有 `1.0`，指新形状；hostABI 的版本演进说明从文档中删除，从这一版重新记起。

- **声明 2.0~2.5 的扩展**（nightly 时期的扩展，含商店里已发布的 oracle 0.1.0、elasticsearch 0.1.0）：设置的扩展列表里显示为不兼容，不加载、不注册任何贡献，原因写明声明的 hostABI 与宿主支持的版本。商店里只有这些版本的扩展显示为不可安装，原因相同。opsctl 对这类扩展资产执行 `exec` 时报错并点名扩展与原因，不加载它。
- **旧形状的 1.0 扩展**（v1.14.0 及更早正式版时期的扩展）：[已核实] 它们的 manifest 含 `capabilities`、`assetTypes`、`tools` 等字段。版本检查会通过，随后 manifest 严格解析因未知字段失败；扩展列表把它显示为加载失败并给出该解析错误，不加载、不注册任何贡献。**[用户决定]** 接受这一表现，宿主不为识别旧形状增加任何判断。
- **新扩展装到 v1.14.0 及更早的宿主上**：[已核实] 旧宿主只校验 `minAppVersion` 的格式、不与应用版本比较，也没有商店，因此只有手动安装会遇到。旧宿主会接受它，表现为一个不提供任何内容、调用即失败的扩展。旧宿主无法修改，本轮不处理。新扩展的 `minAppVersion` 设为包含本次改动的第一个正式版。
- **数据沿用**：用户已保存的扩展资产数据、扩展 KV 数据、权限组选择在换装新版本扩展后照常可用，前提是新版本沿用同样的资产类型名、配置字段与策略组 id。

## 扩展仓迁移

- Oracle、Elasticsearch 与仓库内的 notebook、测试夹具迁到新 manifest、新 SDK：Action 改为只给页面用的工具、`FileParam` 改为大内容参数、驱动权限改为基础能力命名、页面改用新的 `hostUI` 契约。
- 资产类型名、配置字段与策略组 id 不变，以满足上一节的数据沿用。
- 迁移后的 Oracle、Elasticsearch 版本号升为 `0.2.0`，不覆盖商店里已发布的 `0.1.0`。
- 迁移后的扩展在真机上通过下文的运行时验收；扩展仓的改动以独立 PR 提交，依赖宿主分支的伪版本，宿主发版后再切到正式版本并发布到商店。

## Out of scope

- 扩展资产类型配置 Kerberos 凭据（决定 5）。
- 新增插槽，例如设置页、侧栏。
- 事件流送达 AI 或 opsctl。
- 商店发布与宿主发版本身。
- 真多节点 RAC、TAF。
