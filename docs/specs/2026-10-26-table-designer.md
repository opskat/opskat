# 表设计器：设计表 / 新建表 / 查看结构合一，并支持索引管理

> Status: Approved
> Owner: OpsKat 维护者
> Last updated: 2026-10-26

**Objective:** SQL 数据库资产的「新建表」「设计表」「查看结构」合并为同一个以内层标签打开的表设计器，在其中编辑字段、管理索引、预览并执行驱动生成的语句；每种数据库（四个内置驱动与扩展驱动）能做什么完全由驱动声明，设计器按声明渲染与校验。

**Hard invariant:**
- 共享代码（前端与后端）不按驱动 id 分支（`internal/archtest` 的 `TestNoDriverBranchInSharedCode` 与 `frontend/eslint.config.js` 的 `no-restricted-syntax` 照旧生效，不加豁免）。
- 驱动没有声明的能力，设计器不显示、宿主不发送；宿主绝不把驱动不认识的改动交给它，从而让它被静默丢弃。
- 设计器无法完整表示的已有索引不会被重建或改写。
- 保存前一律经过确认，确认里显示的就是将要执行的语句。
- 现有改表能力不回退：四个内置驱动在旧改表对话框里能做的改动（改表名、列改名、新增 / 删除列、驱动声明的已有列属性、表注释），在设计器里照样能做，生成的语句与改动前一致（「有意的行为变化」一节列出的除外）。
- 已发布的 Oracle 扩展（未声明本轮新能力）照常可用，只是不获得新能力。

## 所处位置

标注：**[已核实]** = 对照 opskat main（`c60d0bf8`）与 extensions 仓库 Oracle 扩展（`a10489e`）源码确认；**[用户决定]** = 本轮对话中用户选定；**[未复现]** = 读代码得出、尚未在运行中复现。

本轮建立在规格 [2026-10-16-database-driver-write-path](2026-10-16-database-driver-write-path.md)（写路径由驱动生成）与 [2026-10-19-ext-database-driver](2026-10-19-ext-database-driver.md)（扩展驱动）之上：建表、改表语句已由驱动生成，本轮扩展这份接口，并重做前端交互。评审用 mockup 在 `.dev-kit/artifacts/2026-10-26-table-designer/mockups/`（本地评审材料，不入库）；本规格的文字是唯一约束。

## Problem

1. **建表与改表是两个不一样的对话框，信息密度低、改动不可见。** [已核实] `CreateTableDialog.tsx` 与 `AlterTableDialog.tsx` 各自一套布局；建表不能写注释；每一列是一张带边框的卡片（`AlterTableDialog.tsx:421`），一屏只看得到几列；改了什么要到 SQL 预览才知道。
2. **驱动锁定的输入不说原因。** [已核实] 改不了的输入只是变灰（`AlterTableDialog.tsx:439`、`:449`、`:459`、`:467`），只有两种写死的能力组合有说明文案（`ALTER_LIMITS`，`:52-63`）。
3. **新建表的入口太深。** [已核实] 只有「库节点右键 → 新建表」一条路（`DatabaseTree.tsx:643-654`）；「表 (n)」分组行没有菜单，空库只显示「暂无表」，侧栏工具栏的 `+` 是新建数据库（`DatabaseTree.tsx:542-552`）。
4. **没有索引管理。** [已核实] 索引只在只读的「查看结构」对话框里列名字、唯一与否、列（`TableStructureDialog.tsx:66-79`）；改表请求（`AlterTableRequest`，`pkg/dbdriver/session.go:393`）与建表请求（`CreateTableRequest`，`:355`）都不含索引。
5. **默认值按文本猜写法，函数默认值被写成字符串。** [已核实] `sqldb.Literals.Default`（`pkg/dbdriver/sqldb/literal.go:79`）只把数字、`TRUE` / `FALSE` / `NULL`、`CURRENT_TIMESTAMP` / `NOW()` 原样写入，其余一律加引号；Oracle 扩展用同一规则（`extensions/oracle/alter.go`）。于是 Oracle 的 `SYSDATE`、PostgreSQL 的 `gen_random_uuid()` 等表达式默认值无法设置。
6. **类型只能手打，新列类型写死。** [已核实] 驱动描述没有类型信息（`pkg/dbdriver/descriptor.go:11-50`）；新列一律预填 `VARCHAR(255)`（`AlterTableDialog.tsx:75`、`CreateTableDialog.tsx:43`），对 Oracle、SQLite 都不合适。
7. **名称原样加引号，大小写悄悄变成区分的。** [已核实] PostgreSQL（`internal/dbdriver/postgresql/table.go:16`）与 Oracle 扩展（`extensions/oracle/connect.go` 的 `quoteIdent`）都按原样加引号建名：PostgreSQL 里含大写、Oracle 里含小写的名字之后都必须加引号才能访问，界面不提示。
8. **读出的索引信息不完整，不能作为重建依据。** [已核实] 索引只有名字、列、唯一（`IndexMeta`，`pkg/dbdriver/browse.go:55`）：
   - PostgreSQL 按 `indnatts` 取列（`internal/dbdriver/postgresql/catalog.go:62-70`），把 `INCLUDE` 列当成键列，不读部分索引的 `WHERE`；
   - SQL Server 按 `key_ordinal` 排序（`internal/dbdriver/mssql/catalog.go:53-62`），`INCLUDE` 列的 `key_ordinal` 为 0，显示在键列前面；
   - MySQL 把 `COLUMN_NAME` 扫进 `string`（`internal/dbdriver/mysql/catalog.go:59-75`），表达式索引的这一列是 NULL。[未复现] 推断含表达式索引的表读结构整体报错。
9. **只读连接的资产仍显示「设计表」。** [已核实] 树的菜单只看驱动能力（`DatabaseTree.tsx:459`），资产的只读连接开关（`genericFields.ts:73`）在执行时才由连接拦下。
10. **扩展驱动会静默丢弃不认识的字段。** [已核实] driverwire 约定「字段只加不改，收到不认识的字段就忽略」（`pkg/extension/driverwire/driverwire.go:1-12`）。若宿主把索引改动、默认值写法等新字段发给按旧版本构建的扩展，改动会被悄悄丢掉而不报错。

## Actors and user stories

1. 作为**运维用户**，我想在一个标签里看清并修改一张表的字段和索引，改了什么一眼可见，保存前看到确切的语句。
2. 作为**运维用户**，我想在任何数据库上都只看到它真正能做的操作，做不了的说清原因，而不是点了保存才报错。
3. 作为**运维用户**，我想少点几下就能新建一张表。
4. 作为**驱动实现者**（宿主维护者与扩展作者），我想只在驱动里声明能力、实现语句生成，就让一种数据库获得表设计器的全部或部分能力，而不改共享代码。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 设计器以内层标签打开，取代改表与建表对话框 | 字段与索引同屏需要空间，标签能与表数据、SQL 标签并排切换。Rejected: 加大对话框 —— 仍是模态，不能边看数据边改结构 |
| 2 | 「查看结构」并入设计器，不能改时以只读打开 | [用户决定] 一处看结构。Rejected: 保留只读对话框 —— 两套展示会漂移 |
| 3 | 设计器与索引管理同一轮发布 | [用户决定] 两者改的是同一份驱动接口，分两轮要返工 |
| 4 | 每项能力由驱动在描述里声明，缺省即不支持 | 沿用 `AlterTableAttributes` 的做法，满足 OCP 与 archtest。Rejected: 前端按驱动写能力表 —— 违反不按驱动分支的约束，扩展无法参与 |
| 5 | 默认值分「无 / NULL / 值 / 表达式」四种写法 | 消除按文本猜（Problem 5）。Rejected: 扩充猜测白名单 —— 各数据库函数无穷尽，永远猜不全 |
| 6 | 名称大小写只提醒、不阻止保存、不自动改写 | [用户决定] 所见即所得。Rejected: 自动转大写 / 小写 —— 用户刻意要的名字会被改掉 |
| 7 | 设计器表示不完整的已有索引只读、只能删除 | 按不完整的模型重建会悄悄改变索引（Problem 8）。Rejected: 允许编辑并尽量保留 —— 无法保证不丢定义 |
| 8 | 外键本轮只读展示 | [用户决定] 控制范围。Rejected: 本轮一起编辑 —— 跨表依赖与各库语义差异大 |
| 9 | 表结构语句可回滚的驱动整次保存在一个事务里执行 | [用户决定] 消除半途状态；复用已有的 `ExecuteBatch` 整批原子执行（`pkg/dbdriver/session.go:489`）。不能回滚的驱动（MySQL、Oracle）照旧逐条执行并如实报告 |
| 10 | 新能力只通过驱动描述上的新可选字段与请求上的新可选字段传递，不升 hostABI | driverwire 只加字段即兼容；缺省字段让旧扩展自然落到「不支持」。Rejected: 升 hostABI —— 迫使所有已装扩展重新发版 |
| 11 | 删除警告由草稿得出，不依赖驱动给语句打标 | 草稿里已知删了哪些列和索引，旧扩展同样适用。Rejected: 驱动返回危险语句标记 —— 旧扩展给不出 |
| 12 | 自增只在新表、新列上可设；新表预置自增主键 `id` | [用户决定] 改已有列的自增在各库语义差异大。新表的 `id` 类型取驱动声明的主键默认类型 |
| 13 | 侧栏 `+` 改为下拉，「当前库」= 选中树节点所在的库，没有选中时取第一个展开的库 | [用户决定] 新建表比新建库常用；代价是新建库多一次点击 |

## 入口与标签

- **设计表**：表右键菜单「设计表」打开设计器标签。同一张表只开一个设计器标签，再次触发切到已有标签。驱动未声明改表能力、或资产开启了只读连接时，这一项显示为「查看结构」，打开只读设计器；原「查看结构」对话框删除。
- **新建表**，以下任一处都打开空白设计器，目标库为触发处所在的库（有 schema 的驱动为所在 schema）：
  - 「表 (n)」分组行悬停出现 `+`；
  - 库里没有表时「暂无表」旁的「新建表」；
  - 库节点、「表」分组、表的右键菜单「新建表」；
  - 侧栏工具栏 `+` 下拉的「新建表」（目标库按决策 13），下拉另有「新建查询」「新建数据库…」（后者仅驱动声明建库能力时出现）；
  - 没有打开任何内层标签时，内容区的「新建查询 / 新建表」按钮。
  驱动未声明建表能力或资产为只读连接时，以上入口都不出现。
- 标签标题为「设计 库.表」「新建表 · 库」或只读时「结构 库.表」；有未保存改动时显示圆点。设计器标签与其他内层标签一样在重启后恢复，恢复时重新读取表结构，草稿不保留。
- 关闭有未保存改动的设计器标签（含批量关闭、关闭整个查询标签）时，沿用表数据标签的关闭拦截：取消 / 放弃并关闭 / 保存…。

## 设计器布局

- **工具栏**：表名输入、表注释输入（驱动不支持表注释时不显示）、改动计数（字段与索引各自的新增 / 修改 / 删除数）、问题数、撤销全部改动、重新读取表结构、保存（`⌘S`，经快捷键设置可改）。新建表时表名前是目标库（schema）选择，保存按钮为「创建」。
- **子页**：字段、索引、外键（只读；新建表时不显示）、SQL 预览。有改动的子页标签上显示圆点。
- **状态栏**：驱动名与表的全名。
- 撤销全部改动与重新读取表结构在有未保存改动时先确认。重新读取后草稿丢弃，界面与刚打开时一致。

## 字段

- 每列一行的紧凑表格：序号、主键、名称、类型、可空、默认值、注释（驱动不支持列注释时整列不显示）、操作。单元格直接编辑。
- **改动标记**：新增行左侧绿条；改过的行黄条，改过的格子底色变黄，悬停显示原值；标记删除的已有列红条加删除线，保存前可恢复。删除新增的行直接移除。
- **锁定**：已有列上驱动没声明可改的属性显示锁图标，悬停说明原因（由驱动声明的可改属性生成）；驱动能力有限时，表格上方有一条说明，列出它能改与不能改的，文案由声明生成而不是按驱动写死。新增的列不受这些锁定限制。
- **类型**：输入框带下拉，列出驱动声明的常用类型（分组）；输入任何文本都可原样采用。驱动未声明类型时只有输入框。新列的预填类型取驱动声明的默认类型；未声明时留空并要求填写。
- **列属性**（选中一列时在表格下方）：
  - 默认值写法「无 / NULL / 值 / 表达式」：「值」按字面量写入（字符串加引号，按列类型写法由驱动决定），「表达式」原样写入。读出已有列时由驱动判定写法。驱动未声明支持这四种写法时，退回现在的单一文本输入与现有猜测规则。
  - 主键、自增：自增只在新表与新列上可勾（驱动声明支持自增时出现），已有列显示其现状。改主键见「索引」。
  - 已修改的属性列出原值，可逐项还原。
- **名称提醒**：驱动声明了名称折叠规则（转大写 / 转小写）时，表名、列名、索引名与规则不符时给黄色提醒，说明之后要加引号访问；不阻止保存。

## 索引

- **列表**：名称、类型、列（按次序；降序标箭头；表达式显示为虚线框）、驱动声明的选项（如方法、聚集）、注释（驱动支持索引注释时）、操作。改动标记同字段。
- **编辑区**（选中或新建时在右侧）：名称、类型（驱动声明的类型列表，如普通 / 唯一 / 全文 / 位图）、列（按次序；可加、移除、上下移；驱动支持时每列可设降序与前缀长度；可选列包括本次草稿里尚未保存的新列）、驱动声明的选项（枚举或开关，通用渲染）、注释（驱动支持时）。
- **新建索引名**按 `idx_表_列` 自动生成，手动改过后不再跟随列变化。
- **名称唯一范围**由驱动声明（表 / schema / 库）；与范围内已有索引（含其他表的）重名时就地报错并阻止保存。
- **主键**作为一项索引（类型「主键」）显示；驱动声明主键可改时可以在编辑区改主键的列，否则「主键」类型不可选、已有主键只读。
- **修改已有索引**由驱动写成删除后重建（或驱动支持的等价语句），编辑区提示大表重建可能锁表。
- **只读索引**：驱动读出时标明无法完整表示的已有索引（如表达式、部分、带 `INCLUDE` 列、非默认操作符类、筛选、列存储、函数索引）显示锁图标与原因，只能删除，不能编辑；驱动标明不可删除的（如 SQLite 为 `UNIQUE` 约束自动建的索引）没有删除按钮。
- **随列删除**：标记删除一列时，引用它的索引自动标记删除并注明「随列 … 一起删除」；恢复该列则一起恢复。
- 驱动未声明索引编辑能力时，索引页只读，顶部说明「当前驱动版本不支持在设计器里修改索引」；对扩展驱动附「去更新」入口。

## 外键

只读列出名称、列、引用表与列、ON UPDATE、ON DELETE；顶部注明只读。

## SQL 预览

- 驱动按当前草稿生成的语句，按执行次序编号，与保存时执行的完全一致；草稿变化后重新生成，生成失败时在此显示驱动错误且禁止保存。
- 草稿里删除了已有列或索引时，顶部红色警告列出将删除的列（及其中数据）与索引。
- 可复制全部语句，可「在 SQL 标签打开」（放进新的 SQL 标签，供手工改写后执行）。
- 只读设计器里这一子页换成「建表语句」，显示驱动给出的 DDL（驱动声明查看 DDL 能力时出现）。

## 保存

1. 草稿有校验问题时保存禁用（见「校验与提醒」）。
2. 保存先弹确认：列出全部语句；有删除列或索引时显示红色警告、确认按钮为危险样式。
3. 驱动声明表结构语句可回滚时，整批语句在一个事务里执行：失败则整批回滚，提示失败的语句与数据库错误，草稿原样保留，表结构不变。
4. 否则逐条执行，任何一条失败即停止：确认框转为结果视图，逐条显示已执行 / 失败（附数据库错误）/ 未执行；设计器随后重新读取表结构，已生效的改动不再标记，未执行的改动留在草稿里。
5. 全部成功后：顶部成功提示（`notifySuccess`），设计器重新读取表结构，树刷新；改了表名时标签与树跟随新名字；新建表成功后设计器转为该表的设计标签。
6. 执行走现有的查询面板执行路径，审计与只读连接的拦截不变。

## 新建表

与设计表同一设计器：表名必填，预置一列自增主键 `id`（类型取驱动声明的主键默认类型；驱动未声明自增时只预置主键列）与一条主键索引；可同时添加列、索引、表注释与列注释（驱动支持时）；保存生成的建表语句（含索引）由驱动给出。目标库可在工具栏改。

## 只读查看

只读设计器（入口见「入口与标签」）：表名与注释为文本，标注「只读」及原因（只读连接 / 驱动不支持改表）；字段、索引、外键子页全部不可编辑；没有保存、撤销、添加、删除；最后一个子页为「建表语句」。

## 校验与提醒

- **错误**（阻止保存）：表名为空；列名为空或重名（不分大小写）；类型为空；索引没有列；索引名为空或在唯一范围内重名；同一张表出现两个主键；驱动声明的选项冲突（如 SQL Server 一张表只能有一个聚集索引）；没有任何列。
- **提醒**（不阻止保存）：名称大小写与驱动折叠规则不符；驱动的值写法提示（如 Oracle 空字符串即 NULL）。
- 出错的格子标红；底部列出问题与提醒，点击跳到对应格子。

## 加载与失败

- 读取表结构时保留工具栏与子页形状，表格区骨架占位。
- 读取失败显示驱动原始错误，可重试或关闭标签。

## 驱动声明

驱动描述（`Descriptor`）新增以下可选声明，缺省一律视为不支持；会话据同一份声明拒绝越界的请求（返回 `ErrUnsupported`），与现有 `AlterTableAttributes` 一致：

| 声明 | 含义 |
|---|---|
| 常用类型 | 分组的类型列表、新列默认类型、主键默认类型 |
| 默认值写法 | 支持「无 / NULL / 值 / 表达式」四种写法 |
| 自增 | 新表 / 新列可设自增 |
| 名称折叠 | 转大写 / 转小写 / 无，用于名称提醒 |

- 索引类型与选项的显示名：内置类型用宿主的 i18n；扩展独有的类型与选项用扩展自己的 locales，同 `DriverField.Label`。
- 读结构（改表模型）新增：每列的默认值写法与自增现状；每个索引的类型、列（含降序、前缀、是否表达式）、选项、注释、是否只读及原因、是否可删除。
- 改表请求与建表请求新增：列的默认值写法与自增、索引的新增 / 修改 / 删除（建表时为索引列表）、主键变更。

## 读结构的修正

为让索引能作为编辑依据，本轮修正 Problem 8：PostgreSQL 区分键列与 `INCLUDE` 列并读出部分索引条件；SQL Server 只把键列按次序列为键列，`INCLUDE` 列单列；MySQL 正确读出表达式索引。其他读取索引的地方（如表头悬浮卡片 `ColumnHeaderCard.tsx`）随之显示正确的键列。

## 扩展驱动

- 新声明与新请求字段都只加不改，按 driverwire 约定旧扩展忽略它们；hostABI 不变。
- 宿主只向声明了对应能力的驱动发送新字段；草稿含驱动未声明的改动时，设计器不让产生该改动（入口不出现或输入锁定），宿主在会话边界再次拒绝。
- 按旧版本构建的扩展（未声明任何新能力）：字段编辑与现在的改表能力一致；类型下拉、默认值四种写法、自增、名称提醒不出现；索引页只读并提示更新扩展。
- 共用 SQL 库（`pkg/dbdriver/sqldb`）提供新能力的默认实现与可选的方言接口，方言实现即开启，声明与实现由同一份列表给出；扩展经 SDK 获得同样的能力。
- Oracle 扩展在 extensions 仓库另行跟进发版（声明 Oracle 的类型、名称折叠转大写、普通 / 唯一 / 位图索引、名称唯一范围 schema、自增 `IDENTITY`）；宿主先发布，扩展跟进前按上一条行为工作。

## 有意的行为变化

1. 改表、建表对话框与「查看结构」对话框删除，由设计器标签取代。
2. 侧栏工具栏 `+` 由「新建数据库」改为下拉，新建数据库多一次点击。
3. 新列不再一律预填 `VARCHAR(255)`，改为驱动声明的默认类型。
4. 声明了默认值写法的驱动，默认值按所选写法写入，不再按文本猜测；旧输入规则只保留给未声明的驱动。
5. PostgreSQL、SQL Server、SQLite 的保存整批在事务中执行，部分失败不再留下半途改动。
6. 只读连接的资产不再出现「设计表」与「新建表」入口。

## Out of scope

- 外键的新增、修改、删除。
- 已有列的自增变更；列顺序调整（只有 MySQL 支持）。
- 表选项（引擎、字符集、排序规则、分区、表空间）、检查约束、触发器、生成列的编辑；设计器不显示的列属性（如 MySQL 的排序规则、`ON UPDATE`）照旧原样保留。
- 在线 / 并发建索引选项（`CONCURRENTLY`、`ONLINE` 等）。
- AI 工具与 `opsctl` 的表结构编辑。
- Oracle 扩展的改动本身（extensions 仓库另行处理）。
