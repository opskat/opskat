# 自动备份（与备份位置解耦：WebDAV / GitHub Gist / 本地文件夹）

> Status: Approved
> Owner: OpsKat 维护者
> Last updated: 2026-11-17

**Objective:** 用户开启一次自动备份后，OpsKat 会按设定的间隔检查数据，数据有变化时把加密的完整备份写到用户选中的一个或多个位置（WebDAV、GitHub Gist、本地文件夹），每个位置保留多个历史版本，任何一个位置失败都不影响其他位置，失败后自动重试。

**Hard invariant:** 现有手动备份与恢复（文件、Gist、WebDAV 的导出 / 导入 / 恢复列表 / 记住的导出默认项）行为不变；手动备份文件 `opskat-backup.encrypted.json` 永远不会被自动备份覆盖或清理；没有开启自动备份的用户不会因此产生任何外网请求或文件写入。

## Problem

标注：**[已核实]** = 对照 opskat main（`86f40e5f`）与 PR #192 head（`9790115e`）源码确认；**[用户决定]** = 本轮对话中用户选定；**[评审]** = PR #192 下已有的评审意见。

1. **PR #192 把自动备份做成了 WebDAV 专属。** [已核实] 开关、加密密码、状态都存成 `WebDAVAutoBackup*` 字段，上传直接调 WebDAV；Gist 与本地无法复用。[用户决定] 自动备份不应只和 WebDAV 关联。
2. **在 IPC 方法后逐个触发备份，会漏掉一部分数据写入。** [已核实] PR 在 `internal/app/system/*.go`、`internal/app/ssh/*.go` 的二十多个方法成功后调用 `auto_backup_svc.Schedule()`；而内置 AI 的资产增删改（`internal/ai/tool/tool_handlers_crud.go`）、`asset_put_svc`、以及另一个进程 opsctl 写同一个数据库，都不经过这些方法，改动后不会触发自动备份。
3. **单文件覆盖会把误删固化进唯一的备份。** [评审] 自动备份固定写 `opskat-backup-auto.encrypted.json`，误删资产后约 2 秒就会用删除后的状态覆盖它；上传是直接 PUT，中途失败可能留下截断文件；失败后不重试，直到下一次写操作才会再试。
4. **PR 与 main 冲突。** [已核实] main 之后为 WebDAV 增加了「记住导出默认项」（`WebDAVExport*` 配置项、`saveWebDAVExportDefaults`），PR 改写的 `SaveWebDAVConfig`、`ClearWebDAVConfig` 与 `AppConfig` 同一区域，无法直接合并。
5. **后台任务写配置有数据竞争。** [已核实] main 上 `bootstrap.GetConfig()` 返回共享指针、`SaveConfig` 整体替换且无锁；自动备份在后台 goroutine 里记录状态，会与设置页的保存并发改同一结构体。PR 中的 `UpdateConfig`（加锁的读-改-存）与 `GetConfig` 返回副本解决了这个问题。

## Actors and user stories

1. 作为**用户**，我想开一次开关就让资产、凭据等数据自动备份到我已有的 WebDAV / GitHub / 同步文件夹，不用再记得手动导出。
2. 作为**误删了资产的用户**，我想从自动备份里找到误删之前的版本恢复，而不是只剩一份误删之后的备份。
3. 作为**同时用 AI 和 opsctl 改资产的用户**，我希望这些改动也会被自动备份。
4. 作为**用户**，我想一眼看到每个备份位置最近一次成功是什么时候、失败的话原因是什么。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | **[用户决定]** 自动备份是独立于备份位置的一项功能，本轮支持 WebDAV、GitHub Gist、本地文件夹三个位置，可任意组合 | 覆盖全部已有远程备份方式；本地文件夹可以指向 iCloud / OneDrive 等同步目录。Rejected: 只做 WebDAV（PR 现状）；只做核心 + WebDAV、其他以后再说——会留下一半的功能 |
| 2 | **[用户决定]** 备份内容固定为全部：资产、分组、凭据、策略组、端口转发、快捷键、终端主题 | 自动备份的目的是能完整恢复；设置项越少越不容易配错。Rejected: 复用手动导出的勾选项——多一组需要理解的选项 |
| 3 | **[用户决定]** 检查间隔（每 5 分钟 / 每 30 分钟 / 每小时 / 每天，默认每 30 分钟）与保留份数（5 / 10 / 30，默认 10）由用户选择 | 不同用户对备份频率与空间的要求不同。Rejected: 写死 5 分钟、10 份 |
| 4 | 按间隔定时检查 + 内容指纹判断是否有变化，不在各个写入点触发 | 能覆盖 IPC、内置 AI、opsctl、扩展等全部写入来源（问题 2），且不用改动各个写入点。Rejected: PR 的逐方法 `Schedule()`——漏写入、改动分散在二十多处 |
| 5 | 每次写一个带时间戳的新文件、保留最近 N 份；写入先写临时文件再改名 | 误删后仍有之前的版本可恢复；上传中断不会损坏已有版本（问题 3）。Rejected: 单文件覆盖；在数据量骤降时跳过备份——保留多份已能兜底，阈值规则没有需求 |
| 6 | Gist 位置使用一个专用私密 Gist、每次覆盖，不受保留份数限制 | Gist 自带修订历史，旧版本可在 GitHub 上找回；在一个 Gist 里堆多个文件会让现有的 Gist 恢复流程读不到。Rejected: 在 Gist 中按时间戳保存多个文件 |
| 7 | 失败按 1、2、4…分钟退避重试，上限为检查间隔；各位置独立 | 一次网络抖动不应导致长期没有备份（问题 3）；一个位置坏了不能拖累其他位置。Rejected: 失败后等到下一个间隔或下一次写入 |
| 8 | 快捷键与终端主题由前端把当前内容同步给后端；同步到达之前不做第一次检查 | 两者只存在前端本地存储，后端读不到。若不等待，启动后第一次备份会缺这两项，且指纹变化会多出一个版本。Rejected: 本轮把快捷键、主题迁到后端存储——超出范围 |
| 9 | 自动备份设置卡片放在「导入与备份」页「导入」卡片之后、「文件备份」之前；各位置的连接配置仍在原有卡片，自动备份卡片只负责勾选 | 不重复配置 WebDAV 地址与 GitHub 登录。Rejected: 在自动备份卡片里再放一套 WebDAV / GitHub 配置 |
| 10 | 修改后点「保存」才生效，与 WebDAV 卡片一致；有未保存修改时「立即备份」不可点 | 开关、密码、间隔、位置需要一起生效，避免半套配置。Rejected: 改完即存 |
| 11 | **[用户决定]** 改动直接推到 PR #192 的分支（贡献者允许维护者修改），保留贡献者的配置加锁改动并在提交中注明合著者 | 用户选择沿用原 PR。Rejected: 新开 PR 并关闭 #192；只解冲突、以后再重新设计 |

## 设置界面

参考 mockup（本地证据，不提交）：`.dev-kit/artifacts/2026-11-17-auto-backup-targets/mockups/shots/`。以下为约束性要求。

- **位置：** 设置 →「导入与备份」页，新增「自动备份」卡片，位于「导入」卡片之后、「文件备份」卡片之前。
- **关闭状态：** 卡片只显示标题「自动备份」、一句说明（按设定间隔检查数据，有变化时自动加密备份到选中的位置；数据未变化时不会重复上传）与标题右侧的开关。
- **打开开关后显示：**
  - 一行固定的备份内容说明：资产、分组、凭据、策略组、端口转发、快捷键、终端主题，始终用下方密码加密。
  - **备份密码**：密码输入框（可切换显示）。已保存过密码时占位为「已保存，留空则不修改」，下方说明「恢复自动备份时需要此密码；修改后只影响之后的备份，已有的旧版本仍需旧密码」。
  - **检查间隔**、**保留份数**两个下拉框，选项与默认值见决策 3。
  - **备份位置**：三行，每行一个复选框、图标、名称、一行说明，行右侧是该位置的状态。
    - WebDAV：说明为已配置的 WebDAV 地址。未配置时该行不可勾选，说明为「尚未配置 WebDAV」加一个跳到下方 WebDAV 卡片的链接。
    - GitHub Gist：说明为已登录的 GitHub 用户名，以及「单个私密 Gist，每次覆盖；旧版本在 GitHub 修订历史中，不受保留份数限制」。未登录时该行不可勾选，说明为「尚未登录 GitHub」加一个跳到下方 Gist 卡片的链接。
    - 本地文件夹：说明位置是一个只读路径框和「选择文件夹」按钮（系统目录选择对话框）；未选择时占位提示可以选 iCloud / OneDrive 等同步目录。
  - 底部：「保存」「立即备份」两个按钮，右侧一行最近一次检查的结果（如「上次检查 3 分钟前 · 数据无变化，已跳过」「正在检查数据变化…」）。
- **行状态**（仅对已勾选且可用的位置显示）：成功 =「N 分钟前」等相对时间（绿色）；正在写入 = 转圈 +「备份中…」；本轮排队等待 =「等待中」；失败 = 红色「失败 · N 分钟后重试」，行内再显示一块原始错误文本（等宽、可选中复制）。从未成功过且无错误时不显示状态。
- **位置不可用时的勾选：** 已保存的勾选会保留；该位置因未配置 / 未登录而不可用时，复选框显示为不可操作，检查时跳过它，不记为错误；重新配置后自动恢复。
- **校验（点「保存」时，行内显示，不弹 toast）：** 开启且从未保存过密码、本次也没填 →「请设置备份密码」；开启但没有勾选任何可用位置 →「至少选择一个备份位置」；勾选了本地文件夹但没选路径 → 在该行提示选择文件夹。校验失败时不保存。
- **保存成功：** 顶部居中成功提示「自动备份设置已保存」，底部行变为「设置已保存 · 下次检查约 X 后」。保存失败：右下角错误提示并附原因，设置不变。
- **立即备份：** 有未保存修改或正在备份时不可点；点击后忽略「数据无变化」判断，对每个勾选且可用的位置各写一个新版本；按钮变为转圈 +「备份中…」，完成后各行状态刷新。
- **加载：** 读取自动备份设置期间卡片内容区显示加载状态；读取失败显示失败原因与重试按钮（沿用现有的加载 / 错误组件）。
- **窄窗口：** 设置内容区宽度不足时，各行说明与路径换行显示，不截断 Gist 的说明文字。
- **恢复：**
  - WebDAV 卡片的「选择备份」下拉框同时列出手动备份与自动备份；自动备份显示为「自动备份 · YYYY-MM-DD HH:mm（大小）」，时间为本地时区，按时间倒序排在手动备份之后。
  - Gist 卡片的 Gist 下拉框中出现自动备份专用 Gist（描述以「OpsKat Auto Backup」开头），选中后可以像其他 Gist 一样恢复。
  - 本地文件夹中的自动备份通过「文件备份 → 导入」选择文件恢复；「文件备份」卡片的说明补充这一点。
  - 恢复时输入的是自动备份密码，恢复流程与现有加密备份恢复相同。

## 检查与写入流程

- **何时检查：** 自动备份开启并保存后、以及应用启动后，在前端第一次同步快捷键与主题之后进行第一次检查；此后每隔一个「检查间隔」检查一次。保存设置会让计时从保存时刻重新开始。界面上有数据改动时（资产、分组、凭据、策略组、端口转发、快捷键、主题），前端在 2 秒防抖后请求一次额外检查；其他来源（内置 AI、opsctl、扩展）的改动由下一次定时检查发现。
- **判断是否有变化：** 每次检查生成一份完整备份数据，对其明文内容（不含导出时间）计算指纹。每个位置各自记住最近一次成功写入时的指纹；指纹与之相同的位置本次跳过，不同的位置写入新版本。指纹持久保存，应用重启后不会因为重启而重复上传；关闭应用前来不及备份的改动，会在下次启动后的第一次检查中写入。
- **修改备份密码：** 保存新密码后，所有位置记住的指纹失效，下一次检查会用新密码写一个新版本，保证最新版本始终能用当前密码恢复。
- **同一时刻只有一轮检查在跑。** 一轮进行中又到了下一次检查或收到额外检查请求时，合并为本轮结束后再跑一轮。
- **加密：** 与现有远程备份相同的加密格式（用户密码派生密钥）；没有密码不会写出任何文件。

## 各位置的写入规则

| 位置 | 文件 | 写入方式 | 版本保留 |
|---|---|---|---|
| WebDAV | 已配置目录下的 `opskat-backup-auto-<UTC 时间戳>.encrypted.json` | 先上传到同目录下的临时文件名，成功后改名为正式文件名；改名失败时删除临时文件，已有版本不受影响 | 写入成功后，只在 `opskat-backup-auto-*.encrypted.json` 范围内按时间保留最新 N 份，删除更早的；清理失败只记日志，不算本次失败 |
| 本地文件夹 | 所选文件夹下同样的文件名 | 先写同目录临时文件，再改名 | 同 WebDAV |
| GitHub Gist | 自动备份专用私密 Gist，描述「OpsKat Auto Backup - <本地时间>」，文件名与手动 Gist 备份相同 | 第一次写入时创建并记住其 ID，之后每次更新同一个 Gist；记住的 Gist 已被删除（404）时重新创建一个 | 依赖 GitHub 修订历史，不按 N 清理 |

- 文件名里的时间戳用 UTC，保证跨时区排序正确；界面显示时换成本地时间。
- 手动备份文件 `opskat-backup.encrypted.json` 与其他不符合自动备份命名的文件，永远不会被写入或清理。
- 本地文件夹不存在时**不自动创建**（可能是未挂载的外接盘或同步目录），记为失败「文件夹不存在」。

## 失败与恢复

- **单个位置失败：** 不影响其他位置本轮的写入。失败的位置记录错误原文与时间，按 1、2、4、8…分钟退避重试，最长不超过检查间隔；任意一次成功后清除错误、重置退避。错误与最近成功时间持久保存，重启后仍显示。
- **典型失败**都要显示可读的原因：WebDAV 连不上 / 认证失败 / 空间不足 / 改名不被支持；GitHub 登录失效（沿用现有的登录失效识别）/ 限流 / 网络错误；本地文件夹不存在 / 无写权限 / 磁盘已满。
- **位置变为不可用：** 清除 WebDAV 配置或退出 GitHub 登录后，对应位置按「位置不可用时的勾选」处理，不报错、不重试。
- **关闭自动备份：** 停止定时检查与重试；已有的备份文件、Gist 都保留不动；各位置的状态与指纹保留，再次开启后按指纹继续判断。
- **生成备份数据失败**（如凭据解密失败）：本轮所有位置都不写，底部检查结果显示失败原因，按退避重试。
- **网络代理：** WebDAV 与 GitHub 请求沿用现有云备份的出站方式（遵循「设置 → 网络」的代理设置）。

## 安全与隐私

- 自动备份密码用现有凭据加密方式存入配置文件，界面读取时不返回已保存密码的明文（只返回「已设置」）。
- 自动备份文件总是加密；错误文本里不出现 WebDAV 密码、Bearer token、GitHub token 与备份密码。
- 日志对每一轮检查记录：是否有变化、每个位置的结果（成功 / 跳过 / 失败及原因）与耗时，不记录任何凭据。

## 兼容

- PR #192 从未合并，不存在需要迁移的旧配置字段；不保留 PR 中的 `WebDAVAutoBackup*` 字段。
- WebDAV 现有的「记住导出默认项」、手动上传文件名、恢复列表的过滤规则不变（自动备份文件名本来就符合现有的 OpsKat 备份命名，会自然出现在恢复列表中）。

## Out of scope

- 把快捷键、终端主题的存储迁到后端。
- 自动备份到 Gist 时按 N 清理修订历史，或在界面中浏览 Gist 修订历史。
- 自动恢复 / 多设备双向同步。
- 自定义备份内容、自定义文件名或子目录。
- 数据量骤降时跳过备份等启发式保护。
- opsctl 侧的自动备份配置或触发命令。

| 设置 IPC（保存 / 读取自动备份设置） | 校验（缺密码、无可用位置、本地未选路径）失败时不保存；密码加密存储且读取不返回明文；位置不可用时勾选保留 | `internal/app/system/settings_test.go` |
| 前端「自动备份」卡片（vitest） | 开关显隐；行内校验文案；位置不可用时不可勾选且显示跳转链接；行状态（成功 / 失败含错误原文 / 备份中）；有未保存修改时「立即备份」不可点；保存提交的内容 | `frontend/src/components/settings/__tests__/` 下现有设置组件测试 |

无法自动化的部分：真实 WebDAV 服务（如坚果云 / Nextcloud 对 MOVE 的支持）、真实 GitHub、系统目录选择对话框、跨重启的指纹持久效果。收尾时在隔离沙箱（`make dev-sandbox`）里运行时验证：开启自动备份并选本地文件夹（间隔选最短），确认第一次检查写出一个文件；不改数据时下一次检查不写新文件且底部显示「数据无变化，已跳过」；在界面改一个资产后写出新版本；用 opsctl 改一个资产后下一次定时检查写出新版本；连续制造超过 N 次改动后文件夹中只剩 N 个自动备份文件且手动备份文件仍在；把文件夹改成不存在的路径后该行显示失败与重试倒计时；用「文件备份 → 导入」恢复其中一个自动备份成功。
