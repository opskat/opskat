# Design and implementation archive

The files under `specs/` and `plans/` are dated snapshots of design decisions and
implementation plans. Their status, paths, examples, and descriptions reflect the
repository when each document was written; they are preserved as project history,
not maintained as current documentation.

For current facts, use the committed code and the maintained contributor docs:

- [Architecture](../ARCHITECTURE.md) — current structure and subsystem boundaries
- [Development guide](../DEVELOP.md) — commands and engineering conventions
- [Verification guide](../VERIFICATION.md) — current verification workflow
- [Documentation maintenance](../DOC-MAINTENANCE.md) — ownership and fact-check rules

Use `specs/` to understand the design rationale for a dated change and `plans/` to
understand its intended implementation sequence. A statement such as “planned” or
“not implemented” is therefore historical, not a claim about the current branch.
Do not copy facts from this archive into maintained docs without checking them
against committed code first.
