# SSH Agent 认证设计

> 状态：草案——待人工终审
> 负责人：OpsKat
> 最后更新：2026-08-04
> 议题：[#267](https://github.com/opskat/opskat/issues/267)
> 交互原型：`.dev-kit/artifacts/2026-08-04-ssh-agent-auth/mockups/`

**目标：** 让用户可以在 macOS、Linux 与 Windows 上保存多个 SSH Agent 来源，为 SSH 资产显式选择一个来源和一把精确密钥，并在 OpsKat 现有 SSH 连接路径中完成无隐式回退的 Agent 认证。

**硬不变式：** `auth_type="agent"` 的连接只能由用户保存的来源与规范、精确的指纹所对应的唯一签名器完成认证；任何来源、身份、签名、主机密钥或 MFA 失败，都不得切换到其他 Agent 密钥、密码、托管密钥、本地密钥或继承的 `ClientConfig.Auth`。

## 问题

1. **OpsKat 没有一等 SSH Agent 认证类型。** 当前 SSH 资产只支持 `password` 和 `key`；`internal/assettype/ssh.go`、`internal/service/credential_resolver/` 与 `internal/service/ssh_svc/` 没有 Agent 端点或签名器选择模型。
2. **现有连接调用方无法表达“只使用 Agent 中指定的一把密钥”。** 终端、SFTP、代理链、`sshpool`、AI 与 opsctl 最终需要的是 SSH 认证方法；直接暴露 Agent 的全部签名器会让服务器看到并尝试多把密钥，违反 Issue #267 的精确选择要求。
3. **Agent 端点是运行时签名能力，不是 OpsKat 拥有的私钥。** 端点可以离线或跨平台保存，但动态身份、备注、公钥与签名不应进入数据库、备份或普通资产详情。
4. **Agent 公钥认证可能要求 keyboard-interactive MFA。** 设计必须区分“公钥已部分成功后的第二因子”和“公钥失败后的错误回退”。
5. **不同调用方的交互能力不同。** 桌面终端和交互式 opsctl 可以回答 MFA；AI、后台测试和非交互批处理不能显示隐藏提示，但可以复用已经认证且仍有效的 SSH 客户端。
6. **产品必须跨平台验证真实 Agent 传输。** Unix socket 与 Windows OpenSSH named pipe 的连接、取消、畸形响应和签名行为不能只依靠模拟签名器覆盖。

## 参与者与用户故事

1. 作为桌面用户，我希望保存并检查多个 SSH Agent 来源，以便明确选择每个 SSH 资产使用的签名提供方。
2. 作为资产编辑者，我希望按指纹选择一条精确的 Agent 身份，以保证 OpsKat 不猜测也不尝试无关密钥。
3. 作为 MFA 用户，我希望只有在所选密钥已被服务器接受为第一因子后，桌面或交互式命令行流程才显示服务器挑战。
4. 作为管理员，我希望不可用或平台不兼容的来源仍然可见，同时不泄露 Agent 内容，以便理解备份和跨平台恢复后的状态。
5. 作为自动化调用方，我希望 Agent 认证失败明确且非交互，从而避免自动化卡在不可见提示上或静默改用其他凭据。

## 设计决策

| 编号 | 决策 | 依据与否决方案 |
|---|---|---|
| 1 | 新增一等认证类型 `auth_type="agent"`。 | 它提供明确的校验和失败语义。否决：包装系统 `ssh`/`ssh-add`，因为这会绕过 OpsKat 的连接所有权，且跨平台行为不一致。 |
| 2 | 独立持久化 `ssh_agent_sources`。 | 端点是外部签名能力，不是 OpsKat 拥有的私钥。否决：存成 SSH 密钥凭据，因为这会错误暗示密钥材料由 OpsKat 管理。 |
| 3 | 支持 `environment`、`unix_socket` 与 `windows_named_pipe`。 | 三者覆盖首版三个目标平台上的 OpenSSH 兼容 Agent。否决：原生 Pageant，因为它是另一种协议，Issue #267 不要求支持。 |
| 4 | 每个 Agent 认证资产必须显式保存来源 ID 和规范、精确的 `SHA256:` 指纹。 | 选择结果稳定且可审计。否决：选择第一把、唯一一把、按备注匹配或尝试全部密钥，因为这些方式都具有隐式性并可能在不同操作间变化。 |
| 5 | 只用一个选定签名器构造一个认证方法。 | 服务器不得看到无关 Agent 身份。否决：`ssh.PublicKeysCallback(agentClient.Signers)`。 |
| 6 | 必须证明所选签名器成功完成过签名。 | SSH `none` 成功或继承认证不能伪装成 Agent 认证。否决：把任意成功握手都视为 Agent 成功。 |
| 7 | 仅在精确公钥部分成功后允许一次 keyboard-interactive。 | 这可以支持常见 OTP/MFA 服务器，同时不把 MFA 变成回退。否决：公钥被拒绝后进入 keyboard-interactive，或重复协商更多因子。 |
| 8 | SSH 认证完成后关闭 Agent 传输。 | 已建立客户端不再需要 Agent。否决：在连接池或会话生命周期中保留 socket，因为这会扩大暴露面并使取消更复杂。 |
| 9 | 身份仅存在于运行时；公钥只能通过显式复制操作获取。 | 动态 Agent 数据可能敏感且很快过期。否决：持久化身份快照，或把公钥载入前端共享状态。 |
| 10 | Agent 来源与现有凭据混排显示。 | 用户已经在同一页面管理密码和 SSH 密钥。否决：新增页面级凭据类型标签或独立 Agent 设置页。 |
| 11 | 允许离线保存结构有效的来源，并把不兼容导入项保留为 `unsupported`。 | 笔记本会话、硬件密钥和跨平台备份在编辑时经常不可用。否决：保存前强制探测成功。 |
| 12 | 复用产品 SSH 解析与握手路径。 | 直连、代理、连接池和自动化调用方需要一致的认证语义。否决：每个调用方各自实现 Agent。 |
| 13 | 非交互调用方可以复用当前已认证客户端，但不能发起隐藏 MFA。 | 复用不会产生提示；新建 MFA 连接会让自动化挂起或产生意外。否决：后台 OTP 提示或回退凭据。 |
| 14 | 备份来源定义并重映射 Agent 来源 ID，但绝不导出 Agent 身份或密钥材料。 | 恢复资产引用需要来源定义；Agent 内容属于运行时数据。 |
| 15 | 通用主机密钥、缓存代次、连接池关闭、托管凭据、备份和扩展沙箱重构不属于本规格。 | 它们是审查中发现的产品级问题。本功能在必要时消费其稳定契约，但不拥有其内部架构。 |

## 来源模型与生命周期

### 持久化来源定义

一个来源包含：

- 数字 ID；
- 非空显示名称；
- 端点类型；
- 端点定义；
- 可选描述；
- 创建和更新时间。

数据表为 `ssh_agent_sources`。表中不保存身份、公钥、签名、私钥或运行时状态。

端点含义：

| 类型 | 保存内容 | 支持平台 |
|---|---|---|
| `environment` | 环境变量名，例如 `SSH_AUTH_SOCK`；每次操作重新解析变量值 | macOS、Linux、Windows |
| `unix_socket` | Unix socket 绝对路径；校验前可展开 `~` | macOS、Linux |
| `windows_named_pipe` | 本机 OpenSSH 兼容 pipe，例如 `\\.\pipe\openssh-ssh-agent` | Windows |

保存时只验证结构，不验证可达性：

- 环境变量名必须符合语法；
- 运行时环境变量值必须再次按当前平台端点校验，不能相对于 OpsKat 工作目录解释；
- Unix 路径展开并做词法清理后必须是绝对路径，但保存时不要求 socket 存在，也不固定符号链接解析结果；
- Windows 只接受本机 `\\.\pipe\...` 命名空间，拒绝远程 UNC pipe；
- 当前平台不支持的端点类型可以被导入，并保持 `unsupported` 可见状态。

操作系统提供对端凭据时，Unix 传输校验对端有效 UID 与 OpsKat 相同。Windows 依赖本机 named-pipe ACL，不修改提供方 ACL。

### 显式持久化

发现、探测、检查、连接测试和候选项“添加”都不能写入 `ssh_agent_sources`。

- 顶层 **添加 SSH Agent** 打开空白对话框。
- 发现候选项的 **添加** 打开同一个预填对话框。
- 只有用户显式提交对话框才持久化来源。
- 端点离线时仍允许保存来源。
- 活动 Agent 认证 SSH 资产正在引用来源时拒绝删除。

修改端点类型或端点值属于连接配置变更。系统通过产品现有连接失效边界，使直接引用该来源的 SSH 资产及其当前活动 SSH 隧道依赖项不再获得旧连接。只修改名称或描述不触发连接失效。

## 发现、检查与身份隐私

### 发现

首版只发现数量有限且位置已知的候选项：

- 当前进程环境中非空的 `SSH_AUTH_SOCK`；
- Windows 默认 OpenSSH pipe `\\.\pipe\openssh-ssh-agent`。

发现流程不扫描用户文件系统。候选项按规范端点身份去重，并排除已保存来源。

桌面进程与 opsctl 直连进程可能看到不同的环境变量值，这是预期行为。需要固定端点时，用户应保存具体 socket 或 pipe 来源。

### 检查

检查来源时，后端打开传输、列出身份、校验响应，并在返回前关闭传输。

返回的身份摘要只包含：

- 规范指纹；
- 密钥类型；
- 清理后的备注；
- 当前资产使用数量。

边界限制如下：

- 最多 256 条身份；
- 单个密钥 blob 最多 64 KiB；
- 单条备注最多 1 KiB；
- 每个密钥 blob 都必须能解析为 SSH 公钥；
- 畸形、超限、延迟或非预期 Agent 协议响应返回类型化错误。

后端身份缓存不能跨操作存活。前端只能在相关来源行或表单处于活动状态时保存有界身份摘要，并在折叠、关闭、卸载或来源变更时清除。

### 显式复制公钥

身份摘要不携带公钥。复制操作按来源 ID 和指纹重新读取来源，验证密钥 blob，并返回不含 Agent 备注的 `ssh.MarshalAuthorizedKey(publicKey)`。响应不能进入模块级长期前端状态。

## SSH 资产契约

Agent 模式 SSH 资产保存：

- `auth_type: "agent"`；
- `agent_source_id`，必须是正数且对应现存来源；
- `agent_key_fingerprint`，必须是规范、精确的指纹。

指纹格式要求：

- 前缀必须精确为大写 `SHA256:`；
- 无首尾空白；
- base64 无填充；
- 解码后的摘要必须恰好为 32 字节；
- 重新编码结果必须与输入完全相同。

Agent 字段与密码、私钥字段互斥。存在以下任一内容时，后端拒绝 Agent 模式：

- 托管凭据 ID；
- 密码；
- 私钥或私钥路径；
- 私钥口令；
- 连接测试或重试接口传入的临时密码、密钥覆盖；
- 克隆 SSH 客户端配置时继承的认证方法。

切换离开 Agent 模式时，序列化器删除 Agent 字段；切换到 Agent 模式时，删除密码和密钥材料。即使调用方绕过前端，后端校验仍是权威边界。

对于 SSH Agent 字段，写入边界拒绝可能导致 Go 与 SQLite 对 `auth_type` 或 `agent_source_id` 解释不一致的重复 JSON key 和非规范拼写，然后保存规范表示。这只是 SSH Agent 的局部完整性要求，不代表重构仓库中所有资产解码器。

SQLite 约束提供最终的竞态安全检查：

- 活动 Agent 认证 SSH 资产不能引用不存在的来源；
- 被引用来源不能删除；
- 对 Agent 判别字段或来源字段制造顶层歧义的原始写入，以稳定错误 token 拒绝。

## 认证状态机

### 精确选择签名器

每次新建 Agent 认证 SSH 连接时：

1. 在操作发生时解析已保存来源。
2. 使用调用方 context 和 deadline 打开 socket 或 named pipe。
3. 列出并校验 Agent 身份。
4. 对每条身份计算 `ssh.FingerprintSHA256`。
5. 要求指纹恰好匹配一条身份。
6. 仅包装该签名器，并保持其真实签名能力接口。
7. 只用该签名器构造一个 SSH 公钥认证方法。
8. 握手前清除全部继承和临时认证方法。

零条匹配返回“所选身份缺失”；多条匹配返回“身份重复，无法唯一选择”。两种情况都不能选择其他密钥。

记录型签名器使用所选公钥在本地验证每个返回签名。提供方拒绝、畸形签名或本地验签失败统一返回 `ssh_agent_sign_failed`。

### Agent 认证成功条件

Agent 模式连接成功必须同时满足：

- 主机密钥验证成功完成；
- 只向服务器提供了所选公钥 blob；
- 所选签名器在用户认证期间至少产生一次本地验证有效的签名；
- 服务器按允许的认证序列完成认证。

如果服务器在签名器使用前接受 SSH `none` 认证，OpsKat 必须关闭连接并返回 `ssh_agent_auth_not_used`。

### MFA 延续

只有精确公钥认证返回部分成功后，才允许进入 keyboard-interactive。

- 最多执行一次；
- 公钥被拒绝时不得执行；
- 重复部分成功、第三因子或非预期方法序列全部关闭失败；
- 挑战按服务器给出的顺序显示；
- 零提示和多提示挑战都不能由客户端虚构输入；
- 答案只存在于当前请求中，提交或取消后立即清除。

交互式调用方接收结构化挑战元数据并提交答案。非交互调用方新建连接需要 MFA 时返回 `ssh_agent_mfa_required`，不能显示隐藏提示。

### Agent 传输所有权与取消

执行 SSH 握手的组件拥有 Agent 传输。

- 握手前失败时关闭传输；
- 调用方取消时关闭传输，并停止等待 Agent 列举或签名响应；
- `ssh.NewClientConn` 成功后，在返回已建立 SSH 客户端前关闭传输；
- 已建立 SSH 客户端、连接池条目、终端、SFTP 客户端和已路由协议会话都不能持有 Agent socket 或 pipe。

Agent 协议无法撤回硬件提供方已经接受的操作。因此 UI 和日志只能表示“OpsKat 已停止等待”，不能声称提供方操作已被取消。

### 主机密钥边界

Issue #267 不重构主机密钥数据库，但要求产品主机密钥验证器提供以下契约：

- 缺少验证器时关闭失败；
- 查询或保存失败时，在 Agent 签名前终止；
- 初次接受的密钥固定在当前连接的内存状态中；
- 后续 rekey 提供相同密钥时，无需再次访问仓库或 UI 即可通过；
- rekey 密钥变化时关闭连接；
- 产品代码不能把 `ssh.InsecureIgnoreHostKey` 用作回退。

如果现有主机密钥子系统无法提供该契约，应将修正作为独立发布前置任务。

## 产品连接路径

所有已保存资产连接路径都使用同一个支持 Agent 的认证工厂，不能由各调用方分别构造 Agent 认证方法。

### 交互式桌面路径

以下路径可以显示结构化 MFA 挑战并支持取消：

- SSH 连接测试；
- 终端连接；
- 终端重连；
- 从桌面发起的交互式 SFTP 或传输操作。

关闭进度 UI、资产标签页或对应应用操作时，必须取消该操作拥有的 Agent 等待和 SSH 握手任务。

### 代理与跳板路径

有效保存代理链中的任意 SSH 层都可以使用 Agent 认证。来源在该层真正拨号时解析，不能在解析资产配置时提前打开。

认证期间正在建立的路由由当前操作持有，直到连接所有权成功转移。取消时必须关闭该操作拥有的路由并等待认证任务退出。Issue #267 不重构认证完成后的通用端口转发生命周期或共享客户端关闭机制。

产品仍接受的旧 jump-host 字段也必须使用同一个 Agent 认证工厂，不能拥有单独的回退实现。

### SSH 连接池与 opsctl

桌面持有的 `sshpool` 在桌面进程中完成 Agent 访问与 MFA。交互式 opsctl 在正常二进制或会话流量开始前接收结构化挑战帧并返回答案。

- 非交互 opsctl 不显示提示；
- 客户端断开或命令 context 取消时，取消 Agent 列举、签名、MFA 等待和 SSH 握手；
- 非交互操作可以复用代次仍有效且已通过交互认证的客户端；
- 新建非交互连接需要 MFA 时返回 `ssh_agent_mfa_required`。

帧格式细节和通用连接池关闭状态机不属于本规格；本规格只负责可观察的 Agent 挑战、取消和进入原始数据模式前的交接行为。

### 协议隧道、AI 与扩展

数据库、Redis、MongoDB、Kafka、Kubernetes、etcd、RDP、OSS、VNC 或已安装扩展等现有产品路径，在获取 SSH 隧道时，必须通过同一个认证工厂解析 Agent 认证 SSH 资产。

该要求不新增扩展网络能力，也不修改扩展沙箱授权。它只适用于现有宿主已经授权并选择 SSH 隧道资产之后。

AI 的 SSH 执行、复制和 SFTP：

- 不接收 Agent 端点、备注或公钥；
- 不新增 Agent 管理工具；
- 可以复用当前已认证的 SSH 租约；
- 新建连接需要交互时返回 `ssh_agent_mfa_required`；
- 绝不能把 Agent 失败转换为密码更新或重试流程。

通用 AI 连接缓存租约和 mutation 失效属于独立基础设施工作。

## 后端与 IPC 边界

后端职责划分如下：

- Agent 传输和认证包负责端点校验、Agent 协议、签名器选择及传输生命周期；
- Agent 来源服务负责持久化、来源校验、发现、使用情况查询和运行时检查；
- SSH 资产服务负责 Agent 字段校验与来源引用完整性；
- SSH 连接服务负责主机密钥验证、SSH 握手和交互适配器；
- 调用方依赖共享认证与连接接口，不能导入来源仓库。

Wails 边界提供按使用方划分的操作，而不是一个包含全部信息的巨大来源对象：

- 列出来源摘要；
- 为凭据编辑对话框读取单个来源定义；
- 创建、更新、删除来源；
- 发现候选项；
- 探测候选项或已保存来源；
- 检查身份；
- 测试指定来源与指纹组合；
- 显式复制指定公钥；
- 读取来源使用情况；
- 为资产详情读取所选 Agent 信息。

隐私规则：

- 完整端点只出现在来源编辑和探测界面；
- 模块级共享状态只包含来源摘要、运行时状态和有界身份摘要；
- 资产详情、AI 安全视图和普通日志不暴露端点路径；
- 请求结束后，任何 IPC 数据都不得继续保留签名、私钥或挑战答案。

## 用户体验

`.dev-kit/artifacts/2026-08-04-ssh-agent-auth/mockups/` 下的交互原型是辅助证据，以下文字要求具有约束力。

### 凭据列表

Agent 来源与密码、SSH 密钥显示在现有混排列表中，不增加页面级凭据类型标签。

- 英文页面标题保持 **Credentials**；
- 中文页面标题为 **密钥管理**；
- 来源行显示名称、来源类型和运行时状态；
- 展开来源时延迟加载身份；
- 指纹文本可选择；
- `Identity comment` 的中文标签为 **身份备注**；
- `Fingerprint` 的中文标签为 **指纹**。

运行时状态必须明确区分：

- 加载中；
- 可用且包含身份；
- 可用但为空；
- 不可用；
- 当前平台不支持。

不可用或不支持的来源仍可编辑，并可在不违反引用约束时删除。

### 来源对话框

对话框包含名称、端点类型、端点和可选描述。

- 顶层添加打开空白字段；
- 候选项添加打开预填字段；
- 名称和端点结构未完成前禁用保存；
- 保存不要求探测成功；
- 探测结果不能持久化来源；
- 当前平台不兼容的端点类型在手动创建时禁用，但编辑导入数据时保留。

### SSH 资产表单

认证类型选择器新增 **SSH Agent**。

新建表单初始不选择来源和密钥。即使只有一个来源或一个身份，UI 也不能自动选择。

用户选择来源后再加载该来源的身份。密钥字段显示指纹、密钥类型和清理后的备注。修改来源时清除尚未保存的密钥选择。

编辑资产时，如果已保存指纹当前不存在：

- 以单独的只读“当前不可用”值显示已保存指纹；
- 不能把它插入当前可选身份列表；
- UI 不能推断替代项；
- 用户显式选择可用身份或切换认证类型前，保持禁止保存。

切换认证类型时，提交配置应清除互斥字段；后端错误仍是权威结果。

### 资产详情

Agent 认证 SSH 资产详情显示：

- 认证类型；
- 来源显示名称；
- 已保存指纹；
- 当前可用性；
- 仅当所选身份当前可用时显示密钥类型和备注。

详情不显示来源端点或公钥。身份缺失时不能显示过期的密钥类型或备注元数据。

### MFA 挑战

桌面进度界面只为当前活动且可见的连接操作显示结构化服务器提示。

- 标签与输入框正确关联；
- 隐藏标签页不能抢夺焦点；
- Enter 提交当前挑战；
- Esc 取消操作；
- 多个提示保持服务器顺序；
- 服务器文本按普通文本渲染，不能作为 HTML；
- 取消和错误都不能保留已输入答案。

Agent 错误绝不能打开密码更新对话框或调用密码重试接口。

### 无障碍与窄窗口

所有仅图标的刷新、检查、复制、编辑、删除、展开和对话框关闭控件，除 Tooltip 外还必须具有本地化 `aria-label`。

在 1000×640 下，除非用户显式折叠，否则资产树和 AI 面板保持可见。来源行、对话框和资产表单在长指纹及中英文标签下都不能产生表单横向滚动。

## AI、opsctl 与导入行为

### AI 资产增删改查

现有资产增删改查对 Agent 认证 SSH 资产对称接收并返回 `agent_source_id` 和 `agent_key_fingerprint`，校验规则与桌面保存一致。

AI 安全视图不包含：

- 来源端点；
- 身份公钥；
- 身份备注列表；
- 签名或挑战答案。

不新增用于创建、发现、检查或删除 Agent 来源的 AI 工具。

### opsctl

基于已保存资产的 SSH、执行、复制和 SFTP 命令使用与桌面相同的 Agent 认证行为。

Agent 相关资产 mutation 必须经过产品规范的应用服务变更路径，不能绕过来源引用校验。通用桌面所有权、跨进程代次和版本错配规则属于外部基础设施契约，不由 Issue #267 设计。

### 第三方配置导入

OpenSSH、Tabby、WindTerm 等导入器无法仅根据 `IdentityAgent` 或端点推断精确 Agent 密钥，因此不能自动创建可直接使用的 Agent 认证资产。

导入资产可以保留足够的非敏感信息供用户继续配置，但在用户显式选择来源和指纹前，不能保存为 Agent 模式。

## 备份与恢复

Agent 来源定义不含私钥，因此其导出不受托管凭据秘密包含选项控制。运行时身份和 Agent payload 永不导出。

- 部分资产导出包含被导出 Agent 认证 SSH 资产引用的来源；
- 全量资产导出包含全部 Agent 来源定义，包括当前未使用来源；
- 导入预检在写入前拒绝重复来源 ID、缺失来源引用和畸形 Agent 字段；
- 先创建来源，再创建 Agent 认证资产；
- 每个导入 Agent 认证 SSH 配置中的旧来源 ID 都映射为新来源 ID；
- 不能按来源名称猜测合并；
- 平台不兼容来源照常保留并显示为 `unsupported`；
- 任一失败都回滚来源和资产写入。

本规格不重构托管凭据导出和重映射、仅凭据恢复或产品级备份事务协调器。

## 失败语义与隐私

Agent 错误使用稳定错误码和清理后的消息：

| 错误码 | 含义 |
|---|---|
| `ssh_agent_source_not_found` | 已保存来源不存在 |
| `ssh_agent_source_in_use` | 活动资产正在使用来源，拒绝删除 |
| `ssh_agent_platform_unsupported` | 当前平台不支持该端点类型 |
| `ssh_agent_env_unset` | 已保存环境变量没有可用值 |
| `ssh_agent_endpoint_unavailable` | 无法打开 socket 或 pipe |
| `ssh_agent_protocol_error` | Agent 协议或身份列举失败 |
| `ssh_agent_payload_invalid` | 身份数量、密钥 blob 或备注畸形或超限 |
| `ssh_agent_empty` | Agent 可达但没有身份 |
| `ssh_agent_identity_missing` | 已保存指纹当前不存在 |
| `ssh_agent_identity_duplicate` | 指纹无法唯一确定签名器 |
| `ssh_agent_sign_failed` | 提供方签名或本地验签失败 |
| `ssh_agent_publickey_failed` | 精确公钥交换未完成 |
| `ssh_agent_auth_not_used` | SSH 成功但未使用所选签名器 |
| `ssh_agent_auth_sequence_unsupported` | MFA 或认证方法序列不受支持 |
| `ssh_agent_mfa_required` | 新建连接需要调用方无法提供的交互 |
| `ssh_agent_mfa_failed` | 挑战输入或服务器验证失败 |
| `ssh_agent_cancelled` | 调用方停止等待或操作 context 结束 |
| `ssh_host_key_verifier_missing` | 产品连接缺少显式主机密钥验证器 |
| `ssh_host_key_store_failed` | Agent 签名前的主机密钥持久化失败 |
| `ssh_host_key_changed` | rekey 与初次接受的密钥不同 |
| `asset_config_duplicate_key` | Agent 相关资产 JSON 因重复 key 产生歧义 |
| `asset_config_noncanonical_key` | Agent 相关已知 key 拼写不规范 |

日志可以记录来源 ID、资产 ID、端点类型、指纹和阶段，但不能记录端点值、身份备注、公钥 blob、签名、私钥、OTP 答案或原始 Agent payload。包装内部错误时，不能让端点路径重新出现在用户可见消息或普通结构化日志中。

## 兼容性与发布依赖

- 现有密码和密钥资产保持当前行为；
- 导入的不支持来源保留数据，但不能在当前平台连接；
- 不理解 Agent 字段的旧客户端不能安全创建或更新 Agent 资产；
- 以下产品契约存在且集成测试通过前，不得在生产中开放 Agent 功能。

Issue #267 消费但不重构以下外部契约：

1. 主机密钥验证关闭失败，并支持连接内相同密钥 rekey 固定；
2. 连接相关资产或来源变更后，受支持的同版本产品进程不能在未来获取到旧缓存；
3. 操作拥有的 SSH 握手路由响应取消，且不保留 Agent 传输；
4. 现有扩展隧道授权在调用 Agent 认证工厂前已经确定 SSH 资产。

如果某项契约不可用，对应 Agent 连接路径必须保持禁用，不能发布回退或不完整安全保证。

## 不在范围内

- SSH Agent Forwarding 和 `auth-agent-req@openssh.com`；
- 调用系统 `ssh` 或 `ssh-add`；
- 原生 Pageant 协议集成；
- 自动选择来源或密钥；
- 尝试全部 Agent 身份；
- 持久化 Agent 身份列表、备注、公钥、签名或私钥；
- 自动把 OpenSSH `IdentityAgent` 转换为可用 Agent 认证资产；
- 扩展独立公共 `pkg/client` SSH API；
- 通用主机密钥表迁移、CAS 信任存储重构或冲突管理 UI；
- 产品级资产图诊断、历史悬空引用修复和通用创建、删除图校验；
- 产品级持久代次、桌面所有权或版本错配协议及通用跨进程 mutation 重构；
- 通用 SSH 连接池条目状态机、长时间执行、PTY、SFTP 关闭及认证后的任意 closer 行为；
- 通用 AI `ConnCache` 租约或引用计数重构；
- 托管密码或密钥凭据失效、Kafka 嵌套凭据引用和仅凭据备份语义；
- 通用备份协调器或非 Agent 凭据引用重映射；
- 扩展页面调用 token、扩展 SDK 或开发服务器迁移、原始 TCP 权限、HTTP 重定向或代理策略及 DNS rebinding 加固；
- 仓库内所有资产类型的规范 JSON 解码重构；
- 与 Agent 来源 payload 无关的现有托管凭据列表 DTO 隐私改造。

这些属于独立平台问题，可以作为前置或后续议题，但其内部架构不由 Issue #267 负责。

## 测试决策

| 测试边界 | 验证内容 | 既有基础 |
|---|---|---|
| 端点校验与传输 | 离线保存、环境变量重新解析、Unix 同 UID、本机 Windows pipe、context 取消 | 现有 context-aware 网络测试；需新增真实 Agent fixture |
| 恶意 Agent fixture | 空、超限、畸形、延迟和重复身份；拒绝签名；无效签名；payload 不泄露 | `x/crypto/ssh/agent` 协议行为 |
| 精确认证状态机 | 只提供所选密钥；签名器实际使用；拒绝 SSH `none`；清除继承认证；无回退 | 现有可控 SSH 服务器测试 |
| MFA 延续 | 一次公钥部分成功后的一次 keyboard-interactive；拒绝、重复和非交互行为 | 现有 SSH 进度和交互测试 |
| 主机密钥集成 | 查询或保存失败发生在 Agent 签名前；相同 rekey 使用本地固定；变化 rekey 失败 | 现有主机密钥验证测试和记录型签名器 |
| Agent 生命周期 | 成功、失败和取消时关闭 socket 或 pipe；已建立客户端不持有 Agent 引用 | 连接所有权测试 |
| 产品 SSH 路径 | 直连、代理或跳板、终端、SFTP、连接池、交互式 opsctl、AI 或非交互以及现有授权隧道使用同一认证契约 | 现有 SSH 服务、连接池和调用方测试 |
| 来源持久化 | 仅显式保存、来源存在或删除约束、端点变更失效回调 | SQLite 仓库和服务集成测试 |
| 备份与重映射 | 先来源后资产、来源 ID 重映射、回滚、不支持来源保留、不含 Agent payload | 现有备份导入导出测试 |
| 前端体验 | 混排列表、空白或预填对话框、不自动选择、缺失指纹、重试行为、MFA 焦点或取消和无障碍 | Vitest、RTL 与已提交交互原型证据 |
| 跨平台真实 fixture | macOS 或 Linux 真实 Unix socket、Windows OpenSSH 兼容 named pipe、保留日志和机器可读结果 | CI 和发布工作流调用的新平台 fixture 脚本 |

跨平台验证必须包含一次原生成功流程、身份缺失、提供方拒绝签名、等待 Agent 时取消以及 Agent+MFA。CI 工具链支持时，Windows named-pipe 取消路径在竞态检测器下运行。fixture 产物不能包含私钥、签名或挑战答案。

人工审查覆盖六个已提交交互原型场景的视觉一致性，并确认对原生提供方提示的描述准确；提供方自身 UI 不属于 OpsKat 自动化范围。
